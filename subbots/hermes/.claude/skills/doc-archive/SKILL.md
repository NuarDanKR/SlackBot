# doc-archive

**슬랙에 올라온** 첨부 문서를 md 로 바꿔 자료 저장소의 `documents/` 에 쌓는다.
슬랙 대화(`slack-export/`)와 **별도 트리**다 — 사람이 한 말과 문서에 적힌 것을 섞지 않는다.

## 어디서 돌리나 — 저장소가 둘이다

2026-08-31 부터 코드와 자료가 갈렸다. **명령은 코드 저장소 뿌리에서 친다** — 이 파일도
스크립트도 `npm`·`node scripts/` 도 거기 있다. 문서·대화·`config.json` 은 **자료 저장소**에
있고, 그 뿌리는 `.env` 의 `HERMES_DATA_ROOT` 다.

```bash
cd ~/hermes/code                     # 코드 저장소 (VM 은 /opt/hermes/code)
DATA=$(node -e "import('./src/config.js').then(m=>console.log(m.DATA_ROOT))")
```

**자료를 다루는 git 은 `git -C "$DATA"` 로 친다.** 이 스킬에서 가장 위험한 자리다 —
11단계의 「원본 바이너리가 새어 들어갔나」 검사는 `git ls-files` 와 `git status` 로 보는데,
**없는 경로를 대도 git 은 화내지 않는다.** 코드 저장소에서 문서 경로를 대면 빈 출력과
종료코드 0 이 나오고, 검사는 **아무 파일도 안 본 채 「깨끗하다」고 보고한다.**
둘이 같은 곳을 보는지는 `node scripts/check-roots.js`.

> **출처는 슬랙뿐이다** (WHK 결정, 2026-08-03). 메일로만 받은 자료·로컬 파일은 넣지 않는다.
> 채널이 곧 사업장이고 채널의 비공개 여부가 곧 문서의 공개 여부라, 출처를 슬랙으로 묶어야
> 분류와 공개 판정이 **추측이 아니라 사실**이 된다. 자세한 것은 3단계.

`slack-sync` 와 형제 스킬이다. 대화 텍스트는 slack-sync(MCP 커넥터, WHK 개인 인증),
첨부 실물은 이 스킬(Hermes 봇 토큰). MCP 는 바이너리를 base64 로만 돌려줘 큰 PDF 를 못 받는다 —
인증 경로가 달라서 합치지 않았다.

> **"slack-sync 먼저" 를 기다리지 않는다.** 이 스킬은 `slack-export/` 를 한 줄도 읽지 않는다 —
> 첨부는 슬랙 API 에서 직접 받고, 사업장은 채널에서, 공개 여부는 슬랙 스레드의 `[공개]` 댓글에서
> 온다. 데이터 의존이 없다. 게다가 대화 원문을 넣는 일은 평상시 slack-sync 가 아니라
> **VM 의 07:00 자동 반영**이 한다(slack-sync 는 예외 넷에만 쓴다). **첨부만 밀렸으면 이 스킬만
> 돌리면 된다.** 둘을 붙여 돌리는 것은 대화와 첨부를 같은 시점으로 맞추려는 편의일 뿐이고,
> 어긋나도 위생 점검이 「동기화 N일 밀림」·「미변환 N건」으로 각각 알린다.
>
> **대신 반대 방향으로 강한 결합이 있다 — 바로 아래.**

`$ARGUMENTS` 로 사업장·채널명이 주어지면 **그것만** 처리한다(`--channel` 로 넘긴다).
없으면 봇이 속한 전 채널을 훑는다.

## 내 산출물이 남의 일을 멈춘다

VM 의 **대화** 자동 반영은 커밋 직전 관문에서 **이 스킬의 검증 스크립트를 그대로 돌린다**
(코드 저장소의 `src/ingest/verify.js` 의 `runGate` → `scripts/verify_format.py --all`).
같은 관문이 문서 트리를 둘 더 본다 — `documents/` 에 md·`.doc-state.json` 아닌 파일이 추적되는지
(`checkBinaryLeak`), `.doc-state.json` 의 `local_files` 가 비었는지(`checkNonSlackSources`).

**하나라도 걸리면 그날 자동 반영이 통째로 롤백된다.** 문서만 못 들어가는 것이 아니라
**대화가 안 들어간다.** 그래서 7단계 검증과 11단계 원본·`local_files` 확인은 이 스킬의 품질
문제가 아니라 **남의 일을 멈추지 않기 위한 것**이다. 깨진 md 를 push 하면 다음 날 아침
대화 반영이 멈추고, 그 사실은 봇의 DM 보고에만 나온다.

## 전제

- **kordoc** — 변환은 `npx -y kordoc` CLI 로 한다(4단계). MCP 도구는 한 건 확인용 보조
- **엑셀 출력물 주의** — 회차마다 통째로 반복되는 명단·부록 절이 있으면 그 절은 빼고
  메타에 무엇을 왜 뺐는지 적는다. 안 그러면 같은 명단이 수십 번 쌓여 검색이 중복으로 찬다
  (`사업장나/잔금수금-업무보고.md` 의 「6. 잔금납부 계약자 목록」이 그 예)
- **봇 스코프 `files:read`** — 없으면 파일 대신 로그인 HTML 이 온다. `npm run check` 로 확인
- 자료 저장소의 `documents/index.md` — 없으면 부트스트랩(아래 0단계)
- **엑셀 변환에 `openpyxl` 이 필요하다** — `xlsx_to_blocks.py` 가 못 찾으면 그 자리에서
  종료한다. 처음 한 번:
  ```
  pip install -r .claude/skills/doc-archive/scripts/requirements.txt
  ```
  그 밖의 번들 스크립트는 파이썬 표준 라이브러리만 쓴다
  (`.doc`·`.pptx` 를 다룰 때만 LibreOffice 가 추가로 필요하다 — 없으면 그 파일만 건너뛴다.
  부르는 형태가 까다롭다 — 7단계 「못 읽는 포맷」 참조)
- **한 번에 한 세션에서만 돌린다.** 다른 창(다른 터미널)에서 이 스킬이나 `slack-sync` 가
  돌고 있으면 끝나기를 기다린다. 겹치면 두 가지가 깨진다:
  - `.doc-state.json` 은 실행 끝에 한 번 쓰고(9단계) `index.md` 는 통째로 다시 쓴다(8단계).
    두 세션이 겹치면 **나중에 쓰는 쪽이 앞 세션의 추가분을 모르는 채로 덮는다** — 덮인 문서는
    md 는 남아 있는데 기록이 없어 다음 실행에서 다시 변환 대상으로 올라온다
  - 커밋이 남의 것을 쓸어 담는다. 2026-08-04 에 다른 터미널의 세션이 자기 작업을 커밋하면서
    **스테이징돼 있던 다른 작업 204개까지 함께 담아 push 했다.** 승인을 기다리던 변경이었는데
    승인 없이 나갔고, VM 이 15분 안에 pull 해 팀 앞 근거가 됐다.
    커밋 전에 `git status` 로 **내가 만든 것만 들어 있는지** 확인한다

### 엑셀 서식을 손볼 때 — `check_against_libreoffice.py`

`xlsx_to_blocks.py` 의 서식 해석(구역 선택·반올림·회계 서식)을 고쳤으면 시험만으로는
부족하다. 시험은 **우리가 정한 기대값**과 맞는지 보는 것이라, 기대값 자체가 틀렸으면
같이 틀린 채로 초록이 된다. 그래서 바깥 렌더러와 한 번 맞춰 본다.

```bash
python .claude/skills/doc-archive/scripts/check_against_libreoffice.py
```

- 종료코드 **0** 어긋남 없음 / **1** 어긋난 셀 있음 / **2** LibreOffice 가 없어 **재지 못함**
  (2 를 0 과 가르는 이유: 안 돌아간 검사를 통과로 읽으면 안 된다)
- **「안 그리고 셈」이 늘어난 것은 고장이 아니다.** LibreOffice 는 엑셀의 대리자일 뿐이라
  둘이 갈리는 값이 있고, 그런 값은 known=False 로 세는 것이 맞다. 지키는 것은 하나 —
  **그린 것 중에 어긋난 것이 0** 이어야 한다
- 늘 돌릴 필요는 없다. `test_xlsx_to_blocks.py` 는 의존성이 없으니 그쪽을 늘 돌린다

이 검사는 2026-08-23 에 「구역 축을 일회용 오라클로만 검증해 감사할 수 없다」를 없애려고
만들었고, **첫 실행에서 바로 결함을 하나 잡았다** — 반올림해서 0 이 된 음수에 마이너스가
붙어 `-0` 이 나오던 것(아카이브에 이미 1셀 들어가 있었다).

## 시험 — 코드를 고쳤으면 돌린다

이 폴더의 스크립트를 고쳤으면 아래를 돌린다. 여덟 다 임시 폴더에서만 돌아
진짜 `.doc-state.json` 과 `~/.doc-cache` 는 안 건드리지만, 의존성은 갈린다 —
`test_xlsx_to_blocks.py` 는 `openpyxl` 을 가드 없이 불러온다(엑셀 변환
자체가 그 라이브러리를 쓰기 때문이다). 없는 기계에서는 그 시험이 첫 줄에서
`ModuleNotFoundError` 로 죽는다 — 먼저 `pip install -r
.claude/skills/doc-archive/scripts/requirements.txt` 로 설치한다(「엑셀 변환」
절과 같다). **`test_review_batch.py`·`test_screen_personal.py` 도 마찬가지다** —
둘 다 `review_batch`→`xlsx_to_blocks` 를 거쳐 `openpyxl` 을 끌어온다. 「나머지는 표준
라이브러리만」이라고 적혀 있던 것은 **틀린 말이었다**(2026-09-21 정정 — 임포트를 따라가
확인했다). 나머지 다섯은 표준 라이브러리만 쓴다.

**아래 목록이 폴더의 시험 전부는 아니다.** 지금 이 폴더에 `test_*.py` 가 12개이고
여기 여덟만 적혀 있다 — 빠진 것은 `test_apply_approvals`·`test_count_track_changes`·
`test_extract_comments`·`test_fetch_limit` 이다. **전건을 도는 것은 `npm run check`** 이고
(`scripts/check-catalog.js` 가 발견한 시험을 전부 분류하도록 강제한다), 이 목록은 손으로
돌릴 때의 차림표다.

```bash

python .claude/skills/doc-archive/scripts/test_fetch_filters.py
python .claude/skills/doc-archive/scripts/test_prune_cache.py
python .claude/skills/doc-archive/scripts/test_decide.py
```

**수집은 슬랙에서 비공개인데 `config.json` 의 `privateChannels` 에 선언이 없는
채널을 이제 내려받지 않는다** (2026-09-16 fail closed — `select_channels`·
`report_rejected_private`). 전에는 경고만 찍고 계속 내려받았다.

**개수를 세기 전에 그 파일이 무엇으로 실패를 찍는지 먼저 본다.** 정상 실행에서도
`✗` 가 나오는 파일이 둘이다 — `test_screen_personal.py` 는 2줄, `test_review_batch.py`
는 3줄(둘 다 시험 이름·기대 메시지 문구 안에 `✗` 라는 글자가 들어 있어서다).
**`test_review_batch.py` 는 실패를 `PASS`/`FAIL` 로 따로 찍으니 그 표시를 세면
구별된다. `test_screen_personal.py` 는 실패도 `✗` 로 찍으므로 세는 것으로는 통과와
실패를 가릴 방법이 아예 없다.** 그래서 먼저 볼 것은 **종료코드**(0 통과 / 1 실패
있음)다. 2026-08-26 에 `test_screen_personal.py` 의 `✗` 를 세다가 「되돌리기 전에도
✗ 2건」이 나와 판정이 불가능해진 적이 있다.

**시험이 진짜로 무언가를 잡는지 재려면 — 코드를 되돌려 보는 그 방법 — 같은 측정을
두 번 이상 하고 `.pyc` 캐시를 끈다.**

```bash
PYTHONDONTWRITEBYTECODE=1 python .claude/skills/doc-archive/scripts/test_screen_personal.py
# 또는 잰 뒤 지운다: find .claude/skills -name __pycache__ -type d -exec rm -rf {} +
```

**2026-08-26 에 이 측정이 한 번 틀린 값을 냈다.** `_trunc` 다섯 자리를 되돌려 재는데
첫 회차만 「2곳이 잡힌다」가 나왔고, 그 뒤 캐시를 켜고 3회·끄고 5회를 더 재도 전부
「1곳」이었다. **원인은 못 찾았다** — 재현되지 않는다.

캐시를 끄라고 적는 이유는 그것이 원인이어서가 아니라 **조건이 실제로 갖춰져 있기
때문이다**: 파이썬은 `.pyc` 가 최신인지를 **원본의 크기와 mtime 으로만** 보는데,
`_trunc` 다섯 자리를 맨 슬라이싱으로 되돌리면 **다섯 다 정확히 −6바이트**라 크기로
구별이 안 된다(13,832 → 전부 13,825). `fetch_slack_files.py` 도
`excluded`/`deferred`(32,364), `excluded_names`/`deferred_names`(32,440) 두 쌍이 같다.
**만약 이 기전으로 어긋나면 에러가 안 난다** — 시험은 초록·빨강을 멀쩡히 찍고 판정만
한 자리 밀린다. 끄는 비용이 0이니 끄고 잰다.

**더 중요한 것은 한 번만 재고 보고하지 않는 것이다.** 위 사고에서 나를 잡아 준 것은
캐시가 아니라 **두 번째 측정**이었다.

아카이브 md 의 포맷 계약은 시험이 아니라 `verify_format.py` 가 전수로 잰다 —
코드를 고친 뒤 함께 돌린다.

```bash
python .claude/skills/doc-archive/scripts/verify_format.py --all
```

## 포맷 계약 — 어기면 에러 없이 검색이 0건이 된다

문서 md 는 Hermes 코드 저장소의 `src/archive.js` 가 파싱한다.
`slack-sync` 의 채널 md 와 **같은 세 가지 계약**을 쓴다.

| 계약 | 파싱하는 곳 | 문서 md 에서의 뜻 |
|---|---|---|
| `**YYYY-MM-DD · 원본파일명**` | `archive.js` 의 `splitMessages` | 회차 1건 = 검색 히트 단위 |
| `## YYYY-MM` | `archive.js` 의 `readChannel` | 월 섹션. 최신이 위 |
| 첫머리 연속 `>` 줄 | `archive.js` 의 `metaBlock` | 메타 블록 |

**계약이 깨져도 에러는 안 난다.** 검색이 조용히 0건이 되고 봇은 "아카이브에 없습니다"라고
답한다. 그래서 7단계 검증을 건너뛰면 안 된다.

메타 블록 규칙:
- **블록 안의 빈 줄은 블록을 끊지 않는다.** `archive.js` 의 `metaBlock` 은 빈 줄을 건너뛰고
  다음 `>` 줄까지 계속 읽는다. 그래서 빈 줄 뒤에 적은 `열람`·`공개승인` 도 봇은 읽는다 —
  이걸 반대로 읽는 검사를 따로 만들면 **검사는 통과인데 공개 여부 판정이 갈린다.**
  그래서 파서는 `verify_format.py` 의 `meta_lines()` 하나뿐이고 `review_batch.py` 도 그걸 쓴다
- `**열람**: 공개` 가 **없으면 비공개로 취급**된다 (fail-closed). 공개 문서에는 반드시 적는다
- **비공개 채널의 문서는 기본이 비공개다.** `config.json` 의 `privateChannels` 에 있는
  채널에서 온 문서에는 `**열람**: 비공개` 를 적는다. **목록은 여기 옮겨 적지 않는다** —
  채널이 늘 때마다 낡고, 낡은 목록을 보고 "공개겠거니" 한 것이 2026-08-05 사고의 원인이었다.
  볼 때마다 자료 저장소의 `config.json` 을 연다.
- **예외는 하나 — 슬랙 스레드에 `[공개]` 댓글이 달린 경우다** (WHK 결정 2026-08-05).
  그때는 `**열람**: 공개` 와 `**공개승인**` 두 줄을 **모두** 적는다. 한 줄만 적으면
  봇은 계속 막는데 md 는 공개라고 말하는 어긋난 상태가 된다 (`verify_format.py` 가 잡는다).

  ```
  > **열람**: 공개
  > **공개승인**: 슬랙 스레드 [공개] 댓글 · 2026-08-05 · 김OO
  ```

  두 줄을 다 요구하는 이유: 공개 채널 문서에 흔한 `열람: 공개` 를 비공개 채널 문서에
  실수로 복사해 붙이는 것만으로 `#비공개가` 자료가 팀 앞에 나가면 안 되기 때문이다.
  판정은 `documents.js` 의
  `isPrivate = !access || access !== '공개' || (projectIsPrivate(project) && !approved)` 이다.
- `**공개승인**` 은 **비공개 채널 문서에만** 쓴다. 공개 채널 문서에 적으면 검사가 ✗ 를 낸다
- **줄을 아예 빼지 않는다.** 빼도 fail-closed 로 비공개가 되지만, 그러면
  '비공개로 정한 것'과 '적기를 빠뜨린 것'이 구분되지 않는다. 값을 명시한다
  (`verify_format.py` 가 이 누락을 잡는다)
- 한 줄에 항목이 여러 개면 `·` 로 나눈다. 값 안에 `·` 를 쓰려면 그 항목만 한 줄에 단독으로 둔다
- `**원본**` 은 `Slack 파일 (저장소 미포함) — 슬랙 #{채널} 채널` 로 적는다.
  **`~/.doc-cache/` 를 가리키면 안 된다** — 10단계에서 비우므로 곧 없는 경로가 된다.
  (2026-08-04 에 200건이 그 상태였다. 처음 캐시를 비우면서 다 고쳤다.)

```bash
python .claude/skills/doc-archive/scripts/fetch_slack_files.py --dry-run
python .claude/skills/doc-archive/scripts/fetch_slack_files.py --limit 30 \
    --manifest /tmp/doc-manifest.json
```

- **첨부는 여기서 받는다. 미리 받아두는 길은 없다** — 10단계가 변환 후 원본을 지우므로

  건너뛴다(`= 이미 있음`).
- **이 단계는 멈춰 서지 않는다.** 2026-08-06 까지는 슬랙 호출에 **대기 상한이 없어**
  연결이 반쯤 끊기면 영영 서 있었다. 지금은 `TIMEOUT = 30` 이 걸려 있고 상한 초과·
  연결 끊김도 재시도 대상이며, 한도를 넘기면 `ERROR: … 재시도 한도 초과` 로 끝난다.
  **사유는 화면에 나온다 — 로그 파일은 없다.** 옛 수집 래퍼가 `~/.doc-cache/.fetch.log`
  에 적었지만 그것은 2026-09-02 에 걷어냈고, 그전에도 이 스크립트를 직접 부르면
  로그가 안 남았다.
- **`--limit` 은 「새로 내려받을 건수」다 — 캐시에 있는 것은 한도를 안 먹는다** (2026-08-30 부터).
  그전에는 상한을 자른 **뒤에** 캐시를 확인해서 이미 받아둔 것도 한도를 먹었고, 목록이
  최신순이라 앞쪽 30건이 전부 캐시면 **그 회차는 한 건도 안 받고 끝나고 다음 회차도 똑같았다**
  — 뒤에 있는 새 파일이 영영 안 받아진다. **에러는 안 났다**: 종료코드 0 이고 「받음 N」도
  정상으로 보였다. 이제 한도에 걸려 남은 것이 있으면 「남은 N건은 다시 실행하세요」로 알리고,
  회차를 거듭하면 결국 전부 받아진다. `--dry-run` 도 같은 판정을 쓰므로 미리보기가 실제와
  같다(전에는 dry-run 이 캐시까지 `[dry]` 로 찍었다). 판정은 `plan_fetch()`, 시험은
  `test_fetch_limit.py`.
  회차 결과를 파일로 받고 싶으면 `--manifest <경로>` 를 준다(안 주면 화면에만 나온다)
- **이미 다룬 것은 다섯 갈래로 거른다** (`classify()` — `known`·`excluded`·`deferred`·
  `superseded`·`other_format`). `.doc-state.json` 의 `slack_files` 에 있는 것,
  사람이 빼기로 한 것(`excluded`), 만기 전 보류(`deferred`), 최신이 대신한 옛 판(`superseded`),
  그리고 **이미 변환된 자료와 (채널 + 확장자 뺀 이름)이 같은 것**(`other_format`).
  다섯 다 **파일 ID 와 이름 양쪽**으로 본다 — 같은 자료를 다시 올리면 ID 가 새로 생기는데
  판정은 그 자료에 내린 것이라 따라가야 한다.
  마지막 것이 없으면 같은 자료의 다른 포맷 판이 영영 새것으로 잡힌다 — 아래 `--prefer` 중복 제거는
  **이번 실행에서 함께 발견된 것끼리만** 돌기 때문에, 짝이 이미 변환돼 걸러지면 남은 판이 혼자 살아남는다.
  Hermes 위생 점검(`archive-health.js`)과 **같은 판정이어야 한다** — 갈리면 한쪽은 「34건 남음」,
  한쪽은 「0건」 이라고 알린다 (2026-08-04 에 실제로 그랬다. 34건 중 진짜 새것은 1건)
- **규칙을 고쳐 이미 든 문서를 다시 변환해야 할 때는 `--refetch <파일ID>`.**
  안 쓰면 그 문서는 첫 갈래(`known`)에서 걸려 **후보 0건이 나오는데 에러도 안내도 없다** —
  8/26(마스킹 규칙 2판)과 8/27(머리글 규칙) 두 번 다 이 자리에서 막혀 손으로 우회했다.
  파일 ID 는 `.doc-state.json` 의 `slack_files` 키다. 여러 번 주거나 쉼표로 이어 줄 수 있고,
  **지목한 것만** 열린다(`known` 과 `known_names` 양쪽에서 그 ID 만 뺀다).
  실행하면 `다시 받기: N건 (--refetch)` 가 찍히고, 기록에 없는 ID 를 주면 그것도 알린다 —
  조용히 다시 받으면 같은 문서가 두 벌 쌓인 이유를 나중에 못 찾는다.
  `excluded`·`deferred`·`superseded` 는 **안 건드린다.** 그것들을 되돌리는 길은 `decide.py --clear` 다

  ```bash
  python .claude/skills/doc-archive/scripts/fetch_slack_files.py \
      --dry-run --days 3 --channel 사업장가 --refetch F0EXAMPLE01
  ```
- 스레드 답글의 첨부까지 받는다 — 자료 파일만 답글로 올리는 스레드가 흔하다
- **사업장 = 그 채널.** 추측하지 않는다
- **개명된 채널은 「그 채널」이 슬랙의 현재 이름이 아니다.** 채널 이름이 바뀌어도 대화 md
  파일명은 안 바꾸므로(`slack-archive.js` 의 `fileName`), 아카이브가 아는 사업장 이름은
  **개명 전 이름**이다. 수집이 그것을 되짚어 `channel` 에 넣고(`archive_channel_names`,
  원본은 `.sync-state.json` 의 `channels[<id>].file`), 화면 맨 위에 이렇게 알린다:

  ```
  ============================================================
  개명된 채널이 있습니다 — 사업장 이름은 아카이브 쪽을 씁니다
    #새이름 → 사업장 「옛이름」  (documents/projects/옛이름/)
  새 이름으로 폴더를 만들면 같은 사업장이 두 벌로 갈립니다.
  ============================================================
  ```

  **이 줄이 뜨면 새 이름으로 폴더를 만들지 말 것.** 2026-09-16 에 실제로 그럴 뻔했다 —
  9/8 에 개명된 채널의 첫 문서가 들어왔는데 수집이 새 이름을 사업장으로 잡아, 옛 폴더가
  멀쩡히 있는데도 새 폴더가 생겼다. 그대로 뒀으면 같은 사업장 자료가 둘로 나뉘고 봇
  색인에도 두 줄이 섰다. **경고가 없던 것이 원인이라 그날 수집·위생 점검 양쪽을 고쳤다.**
  - 되짚기는 `제외·보류·물림` 판정에도 듣는다. 그 판정들은 파일 ID 와 `name_key`(채널+이름)
    양쪽으로 거는데, 저장된 기록의 채널은 개명 전 이름이라 새 이름으로 만든 키와 안 맞는다.
    같은 자료를 다시 올리면 ID 도 새로 생겨 **두 갈래가 다 빗나가고 에러는 안 난다.**
  - `.sync-state.json` 을 못 읽으면 `! 개명 지도를 읽지 못했습니다` 로 알리고 현재 이름을
    쓴다. **그 줄이 뜨면 폴더 이름을 사람이 확인한다.** 되짚기가 함께 꺼지므로, `config.json`
    에 **옛 철자**로 적어 둔 개명된 비공개 채널이 바로 아래 「선언 안 된 비공개 채널」 거부
    목록에 잘못 섞여 나올 수 있다(자료가 안 쌓이는 쪽이라 유출 사고는 아니다) — 이 줄이 뜨면
    **폴더 이름과 거부 목록 둘 다** 확인한다
- **채널이 공개인지 비공개인지도 추측하지 않는다.** 코드는 슬랙의 실제 비공개 여부가 아니라
  `config.json` 의 `privateChannels` **목록**을 본다. 새 비공개 채널이 생기면 목록에 없어서
  **그 채널의 첨부는 아예 내려받지 않는다** (2026-09-16 fail closed). 수집이 이걸

  ```
  슬랙에서 비공개인데 config.json 의 privateChannels 에 없는 채널 — 내려받지 않았습니다
  ```

  로 알리므로, **이 배너가 뜨면 `config.json` 의 `privateChannels` 에 채널 이름을 넣고
  수집을 다시 돌린다.** 변환할 것은 없다 — 애초에 안 내려받았기 때문이다. 봇 재시작은
  이 판정과 무관하다 — 수집은 이 PC 에서 사람이 돌린다.
  (2026-08-05: `#비공개나` 이 목록에 없어 비공개 채널 문서 5건이 공개로 들어갔다.
  채널 이름만 보고 "공개겠거니" 한 것이 원인이다. 그때 막은 것은 대화 수집뿐이었고,
  문서 수집은 경고만 하고 계속 내려받다가 2026-09-16 에야 닫혔다)
  - **넣을 목록이 둘이다.** `privateChannels` 는 「비공개로 취급하라」이고 `digest.skipChannels`
    는 「아예 다루지 마라」다. 앞엣것만 넣으면 그 채널은 **아카이브 대상이 되어** 다음 07:00
    부터 대화가 쌓이기 시작한다. 수집할 채널인지를 함께 정하고, 아니면 둘 다에 넣는다
    (`#비공개바`·`#비공개-바` 가 그 경우다 — 비공개이면서 TEC 범위 밖. **둘 다 적힌 채널은
    채널 md 가 없는 것이 정상**이니 없다고 만들지 말 것)
  - **경고가 없다고 다 선언된 것은 아니다.** 이 경고는 **봇이 멤버인 채널**만 훑는다
    (`users.conversations`). 초대되지 않은 비공개 채널은 어긋나 있어도 조용하다 —
    `#비공개-바` 는 2026-07-07 개설인데 한 달간 경고가 없다가 봇이 2026-08-07 08:52 에
    초대되자 그날 바로 났다. 그러니 조용한 것은 「선언이 다 됐다」가 아니라
    「봇이 못 보는 자리는 안 세어진다」로 읽는다
- 같은 자료를 `.hwpx` 와 `.pdf` 로 함께 올리는 일이 흔하다(주간보고·회의안건).
  이름이 같으면 원본 포맷 하나만 받는다(`--prefer hwpx,hwp,docx,pdf`).
  둘 다 변환하면 같은 내용이 두 벌 쌓여 검색이 중복 히트로 찬다
- 슬랙은 `.hwp` 의 `filetype` 을 `binary` 로 보고한다. 그래서 스크립트는 **파일명 확장자**를
  먼저 본다. 이걸 반대로 하면 한글 문서가 에러 없이 통째로 걸러진다

### 3. 수집 경로는 슬랙 하나뿐이다 — `~/Downloads` 는 넣지 않는다

**Hermes 의 근거는 슬랙으로만 한정한다** (WHK 결정, 2026-08-03). 메일로만 받아
`~/Downloads` 에 있는 자료는 아무리 관련이 있어도 아카이브에 넣지 않는다.

전에는 `~/Downloads/02-프로젝트`·`03-계약·법무` 등을 2차 경로로 훑는 절차가 있었다. 왜 뺐나:

- **사업장이 사실이 아니라 추측이 된다.** 슬랙 파일은 채널이 곧 사업장인데, Downloads 파일은
  출처 채널이 없어 파일명·내용으로 판단해야 한다
- **공개·비공개 판정의 근거가 없다.** 슬랙 문서는 채널의 비공개 여부에서 자동으로 나오지만,
  Downloads 문서는 그때 사람이 메타에 적은 `열람:` 한 줄이 전부다
- **개인 자료와 같은 트리에 있다.** `05-개인-금융세무`·`08-참고·기타` 를 손으로 적은
  제외 목록으로 막고 있었는데, 목록에서 빠지면 조용히 샌다
- 실제로 중복도 만들었다 — 같은 `260617_지하1층 상업시설 대물변제…hwp` 가 슬랙과 Downloads
  양쪽에서 들어와 `사업장타` 에 두 벌 쌓여 있었다 (2026-08-03 에 Downloads 판을 제거)

**필요한 자료가 슬랙에 없으면 슬랙에 올린다.** 그러면 채널이 곧 출처가 되고 판정이 사실이 된다.
`.doc-state.json` 의 `local_files` 는 비워 둔다.

### 4. 변환 — kordoc **CLI** 로

```bash
npx -y kordoc --silent -d <출력디렉터리> <파일들...>
```

**MCP 도구(`mcp__kordoc__*`)가 아니라 CLI 를 쓴다.** 여러 건을 한 번에 돌릴 수 있고,
세션에 붙은 MCP 서버가 낡은 인스턴스일 때 생기는 문제(PDF 를 못 읽는다며 거절)를 피한다.
MCP 도구는 한 건만 눈으로 확인할 때만 쓴다.

주의할 점 다섯:

- **`parse` 같은 하위 명령이 없다.** `kordoc [옵션] <파일들>` 이 전부다.
  `kordoc parse file.pdf` 라고 쓰면 `parse` 를 파일명으로 읽어 엉뚱한 에러가 난다
- **파일명에 `[` `]` `'` 백틱 이 있으면 Git Bash 에서 `/c/...` 경로로 부르지 말 것.**
  **kordoc 잘못이 아니고 버전과도 무관하다** — 원인은 **MSYS2(Git Bash)가 그런 글자가
  든 인자를 경로 변환에서 빼는 것**이다. 그러면 네이티브 프로그램에 `/c/Users/...` 가
  **그대로** 넘어가고, 윈도우에는 그런 경로가 없으니 kordoc 은 **없는 파일과 똑같은
  에러**를 낸다(`fileType: "unknown"` · `PARSE_ERROR`). 파일 내용은 열어 보지도 못한다.

  `node` 로 argv 를 찍어 본 것이 증거다 (2026-09-03 실측, kordoc 4.12.0):
  ```
  bash$ node -e "…process.argv…" "/c/…/평범.docx"        → ["C:/…/평범.docx"]   ← 변환됨
  bash$ node -e "…process.argv…" "/c/…/대괄호[1].docx"   → ["/c/…/대괄호[1].docx"] ← 안 됨
  ```

  **고치는 법 — 이름을 바꾸지 말고 경로를 윈도우식으로 넘긴다.** 셋 다 실측으로 통한다.

  ```bash
  # Git Bash 에서 돌릴 때: cygpath -m 으로 감싼다
  args=(); for f in ~/.doc-cache/<채널>/*; do args+=("$(cygpath -m "$f")"); done
  npx -y kordoc --silent -d "$(cygpath -m <출력디렉터리>)" "${args[@]}"
  ```

  | 어떻게 부르나 | `대괄호[1].docx` · `[TC]앞자리.docx` · `작은따옴표'.docx` · 백틱 |
  |---|---|
  | Bash + `/c/...` 경로 | **전부 죽는다** (`PARSE_ERROR`) |
  | Bash + `cygpath -m` 로 만든 `C:/...` 경로 | 전부 산다 |
  | Bash + 그 폴더로 `cd` 한 뒤 **상대** 경로 | 전부 산다 |
  | PowerShell (경로 변환이 없다) | 전부 산다 |

  2026-09-03 에 위 네 줄을 같은 docx 한 벌(이름만 다름)로 각각 돌려 확인했다.
  `{` `!` `(` `)` `&` `#` `+` `=` 는 **영향 없다** — 죽이는 것은 `[` `]` `'` 백틱 넷뿐이다.

  **2026-09-02 에 21건 중 3건이 이 함정으로 죽었다** — 셋 다 파일명 **앞자리에 두 글자
  이상 대괄호**가 붙은 모양이었다(`[XX]…` 꼴 둘 · `3. 260618_ [XX] …` 꼴 하나). 그때는
  대괄호를 뺀 임시 이름으로 복사해 변환하고 결과를 되돌려 우회했다. **이제 그 복사는
  필요 없다.** 경로만 윈도우식으로 넘기면 된다.

  **이 줄은 2026-09-03 이전에 「고쳐졌다 (4.10.0 에서 확인)」고 적혀 있었다.** 그 확인은
  4.10.0 에서 `평범.pdf`·`대괄호[1].pdf`·`작은따옴표'.pdf` 를 잰 것인데, **셸을 안 적었다.**
  kordoc 을 무죄로 본 것은 맞았지만 「그러니 안심하고 아무 셸에서나 부르면 된다」로 읽혔고,
  9/2 에 그대로 3건이 죽었다. `4.5.0 은 글로브로 해석한다` 던 옛 진단도 **셸을 kordoc 으로
  오해한 것일 수 있다** — 4.5.0 을 지금 다시 재지 않아 그건 **확인 못 함**으로 남긴다.
  `fetch_slack_files.py` 의 `GLOB_UNSAFE` 우회는 2026-08-29 에 걷어냈고 **되살릴 이유가
  없다**(원인이 이름이 아니라 경로다). 슬랙 원래 이름은 캐시에 그대로 남는다
- **파일명에 `&` 가 있으면 `kordoc.cmd` 를 직접 부르지 말 것 — 그 자리에서 이름이 잘린다.**
  위 `npx -y kordoc` 은 **안전하다**(2026-08-30 실측, Bash·PowerShell 둘 다 이름 온전).
  잘리는 것은 `.cmd` 껍데기를 직접 부를 때뿐인데, **npx 가 자동 승인 분류기에 막히면 그리로
  내려가게 된다** — 2026-08-28 에 `#비공개가` 의 `JR&I공문_….pdf` 가 그렇게 죽었고
  **그 뒤 파일까지 안 돌았다.** 그때 우회는 `.cmd` 가 아니라
  `node <npx 캐시>/kordoc/dist/cli.js` 다. **원인이 kordoc 이 아니라 `.cmd` 껍데기라
  버전과 무관하다** — 대조군을 4.10.0 과 4.12.0 에서 따로 돌려 같은 결과를 봤다
  (같은 명령에서 하나씩만 바꿈):
  ```
  A  kordoc.cmd  …\ab_test.pdf    → [kordoc] ERROR: ab_test.pdf     ← 이름 온전
  B  kordoc.cmd  …\a&b_test.pdf   → [kordoc] ERROR: a               ← & 에서 잘림
  C  node cli.js …\a&b_test.pdf   → [kordoc] ERROR: a&b_test.pdf    ← 이름 온전
  ```
  `fetch_slack_files.py` 는 `&` 를 안 바꾸므로(윈도우에서 쓸 수 있는 글자다) **캐시 경로에도
  `&` 가 그대로 남는다** — 위 `GLOB_UNSAFE` 우회를 걷어낸 뒤로는 더 그렇다
- **그래도 변환 뒤 개수 대조는 계속 한다** — kordoc 은 실패해도 **종료코드 0** 을 주므로
  다른 문자가 또 걸려도 에러로 안 보인다. `출력 md 개수 == 입력 파일 개수` 로 대본다
- **글자 수는 `![image](...)` 를 지운 뒤에 센다.** 그게 200자 미만이면 `--ocr` 로 재시도하고,
  성공하면 메타 `변환` 에 `OCR 사용` 을 적는다.
  전 페이지 강제는 `--ocr-force`, 페이지 범위는 `-p 1-3`

  ```bash
  python - <<'PY'
  import re, pathlib, sys
  for p in sorted(pathlib.Path(sys.argv[1] if len(sys.argv)>1 else '.').glob('*.md')):
      s = re.sub(r'!\[image\]\([^)]*\)', '', p.read_text(encoding='utf-8')).strip()
      print(('OCR 필요  ' if len(s) < 200 else '          ') + f'{len(s):>7}자  {p.name}')
  PY
  ```

  **파일 길이로 재면 안 된다.** 스캔본은 본문이 한 글자도 없어도 쪽마다 `![image](...)` 가
  한 줄씩 붙어 수백~수천 자로 잡힌다. 2026-08-04 에 사업장자 계약서 4건과 사업장타 공문 1건이
  414·446·734·3,166·62자로 나와 **5건 중 4건이 이 기준을 통과했는데 실제 텍스트는 전부 0자**였다.
  그대로 넣었으면 본문 없는 계약서가 아카이브에 들어가, 봇은 문서가 있다고 답하면서
  내용은 대지 못하는 상태가 된다 — 검색이 0건이 되는 것보다 알아채기 어렵다.

**실패해도 중단하지 않는다.** 사유를 스킵 목록에 적고 다음 파일로 간다.

#### 4-1. 개수 대조 — 변환한 뒤 **반드시** 돌린다

kordoc 은 **실패해도 종료코드 0** 을 돌려준다. 그래서 몇 건이 죽어도 화면은 성공처럼
보이고, **빠진 문서는 아카이브에 안 들어가며 봇은 그 자료를 「없습니다」로 답한다.**
2026-09-02 에 21건 중 3건이 이렇게 죽었고, 사람이 개수를 세어 보고서야 드러났다.

눈으로 세지 말고 아래를 돌린다. **어긋나면 종료코드 1 이고 어느 파일이 빠졌는지 찍는다.**

```bash
python - <<'PY' <입력폴더> <출력디렉터리>
import sys, pathlib
src, out = (pathlib.Path(p) for p in sys.argv[1:3])
SKIP = {'.png', '.jpg', '.jpeg', '.gif', '.bmp', '.xlsx', '.xlsm'}  # 4단계 밖
ins = [p for p in sorted(src.iterdir()) if p.is_file() and p.suffix.lower() not in SKIP]
made = {p.stem for p in out.glob('*.md')}
missing = [p.name for p in ins if p.stem not in made]
print(f'입력 {len(ins)} · 출력 md {len(made)}')
for n in missing:
    print(f'  빠짐: {n}')
sys.exit(1 if missing else 0)
PY
```

빠진 것이 나오면 **먼저 이름에 `[` `]` `'` 백틱 이 있나 본다** — 위 함정이면 경로만
윈도우식으로 바꿔 다시 돌리면 살아난다. 그게 아니면 사유를 스킵 목록에 적는다.

못 읽는 포맷:
- `.doc` → LibreOffice 로 **docx** 로, `.pptx` → LibreOffice 로 **pdf** 로 바꾼 뒤 다시 시도.
  없으면 스킵하고 index 에 남긴다.

  **pptx 를 docx 로 바꾸려 하면 안 된다** — LibreOffice 에 그 변환 필터가 없어
  `Error: no export filter ... aborting` 으로 끝난다. 프레젠테이션(Impress)에서 문서(Writer)로
  가는 길이 없기 때문이고, 옵션을 바꿔 될 일이 아니다. **pdf 를 거치면 된다**
  (2026-08-12 확인 — pptx 2건이 각 9,740자·10,954자로 정상 변환됐다. 그전까지 이 줄은
  `docx` 라고 적혀 있었는데, 그때까지 실제로 변환된 pptx 가 한 건도 없어 안 드러났다).
  **다만 표지·간지 슬라이드는 빈 표로 남고, 흰 글씨나 밑줄이 취소선(`~~`)으로 뽑히기도 한다** —
  취소선은 「철회된 항목」으로 읽히므로 **원본을 열어 대조한 뒤** 걷어내고 메타에 적는다.

  **윈도우에서는 `soffice` 를 그냥 부르면 안 된다** — 아래 형태여야 한다 (2026-08-05 확인):

  ```powershell
  & "$env:ProgramFiles\LibreOffice\program\soffice.com" `
    "-env:UserInstallation=file:///<전용프로필경로>" `
    --headless --norestore --convert-to docx --outdir <출력폴더> <파일>   # pptx 면 docx 대신 pdf
  ```

  세 가지가 다 필요하다.
  - **`soffice.com`** (`.exe` 아님) — `.exe` 는 GUI 앱이라 즉시 반환한다. 변환이 끝나기 전에
    다음 단계로 넘어가고 **결과 파일이 없는데 에러도 안 난다**
  - **`--norestore`** — 앞선 실행이 비정상 종료했으면 복구 대화상자를 띄우려다 멈춘다
  - **전용 프로필(`-env:UserInstallation`)** — 이게 없으면 떠 있는 LibreOffice 인스턴스와
    프로필 잠금이 겹쳐 조용히 실패한다

  실패하면 **`soffice` 프로세스가 남는다.** 남아 있으면 그 뒤 변환이 전부 막히므로,
  변환이 안 될 때 제일 먼저 `Get-Process soffice*` 를 보고 정리한다.
  변환 후에는 **생성된 md 의 글자 수를 확인한다** — 파일은 생겼는데 본문이 빈 경우가 있다
- 이미지는 **이번 범위 밖**이다. 변환하지 말고 index 「변환하지 못한 것」에만 올린다
- `.xlsx` 는 kordoc 이 아니라 **`xlsx_to_blocks.py`** 로 따로 다룬다 — 시트마다 회차
  블록 하나를 만드는 전용 변환기다. 아래 「엑셀 변환」 참고

### 엑셀 변환 — `xlsx_to_blocks.py`

엑셀은 5·6단계(정규화·분류 판단)를 거치지 않는다. `xlsx_to_blocks.py` 가 이미 계약에
맞는 블록을 만들어 내고, 사업장은 다른 파일과 똑같이 채널이다.

```bash
pip install -r .claude/skills/doc-archive/scripts/requirements.txt   # openpyxl, 처음 한 번

python .claude/skills/doc-archive/scripts/xlsx_to_blocks.py \
    --file ~/.doc-cache/<채널>/<파일ID>_<원본명>.xlsx \
    --date 2026-08-20 --source "<원본명>.xlsx" \
    --max-rows 1000
```

**행 상한은 1,000 이다** (기본값도 1,000 이라 안 줘도 같다). 실측이 정한 값이다 —
사업장가 산정내역의 모든 시트(최대 `CP(91)` 541행)가 살아남고, 사업장나 5.1MB 파일에서도
집계 시트인 `통합`(816행)·`3.호실별TM`(809행)은 남되 계약자 전원을 나열한 원장
`1-1.계약자list`(1,379행)만 빠진다. **400 으로 낮추면 그 집계 시트들이 함께
떨어진다** — 요약이 근거로 삼아야 할 자리다.

**유령 행은 변환기가 스스로 자른다** (2026-08-27 부터). 값 없이 서식만 있는 `<row>` 가
수십만 줄 붙은 파일이 실물에 있다 — `사업장라 요약본-260824.xlsx` 의 `정산` 시트가
104만 행인데 값이 있는 행은 71행까지뿐이고, 압축을 풀면 456MB · 셀 1,677만 개라
`openpyxl` 이 6GB 를 먹는다. 이제 로드 전에 그 꼬리를 잘라낸 **임시 사본**을 만들어
그것을 로드한다(사본은 변환이 끝나면 사라진다). **사람이 할 일은 없다.**

- 자를 것이 없으면 사본을 안 만든다 — 평상시 엑셀은 지금과 같은 경로로 돈다
- **병합셀·메모·표 범위가 값 바닥 아래를 가리키면 거기까지 남긴다.** 꼬리 끝까지
  걸쳐 있으면 그 시트는 손대지 않는다
- **`r`(행 번호)이 없는 `<row>` 가 하나라도 있으면 그 시트는 아예 안 자른다.** 그런
  행은 앞에 몇 행이 있었나로 번호가 정해져, 앞을 자르면 값이 지워지지 않은 채 **다른
  행 번호로 옮겨간다** — 아래 개수 대조로는 못 잡는 유일한 갈래다
- 자르기 전후로 **값 있는 셀 개수**를 대조해 다르면 그 시트만 원본으로 되돌린다
- 7.5 점검표에서 **자른 것만 있으면** 칸이 `✓ · 꼬리 행 잘람` 이고(⚠ 가 아니다 —
  사람이 할 일이 없다) **`손볼 곳` 목록에도 안 실린다.** 그 목록은 12줄에서 잘리는데
  자르기는 평상시에 일어나(실물 53MB 파일에서 5시트 중 4시트) 안 빼면 진짜 지적이
  12줄 밖으로 밀린다. 어느 시트를 몇 행까지 남겼는지는 **`--verbose`** 로 본다
- 봐야 할 것과 **함께** 있으면 헤드라인은 그쪽이 갖고 자른 줄은 칸의 `외 N건` 에
  접히지만, 사유에는 `값 없는 꼬리 행을 잘람: …` 으로 함께 적힌다
- **⚠ 로 뜨는 것은 `못 자른 유령 행: …` 쪽이고, 그 사유가 「되돌렸다」면 자르는
  코드의 결함**이니 넘어가지 말 것
- 메타 `수록 범위` 줄은 여전히 **사람이 쓴다** — 그 줄의 다른 이유들이 전부 사람 손이라
  하나만 자동이 되면 규칙이 갈린다

**2026-08-26 의 `data_bounds` 수정과 다른 고장이다.** 그쪽은 유령 셀 하나가
`ws.max_row` 를 끌어올려 시트가 상한에 걸리던 것이고 고친 자리는 「재는 자리」다.
`data_bounds` 는 `ws` 를 받으므로 로드 뒤에만 돌고, 이번에 터지는 자리는 로드 그
자체라 닿지 못한다. 설계: `docs/superpowers/specs/2026-08-27-xlsx-ghost-rows-design.md`

상한을 넘어 빠진 시트가 있으면 **남은 시트의 번호가 다시 매겨진다** (3개 중 하나가
빠지면 `시트 1/2`·`시트 2/2`). 그래서 **md 만 봐서는 무엇이 빠졌는지 알 수 없다** —
`meta.json` 의 `skipped_sheets` 와 7.5 점검표의 「엑셀」 칸이 그 유일한 기록이고,
메타 `수록 범위` 줄에 옮겨 적는 것이 사람 몫이다.

**`--out-dir` 은 이제 안 줘도 된다** — 생략하면 원본 바로 옆
`~/.doc-cache/<채널>/<파일ID>_<원본명>.xlsx.blocks/` 에 만들어진다. 폴더 이름에 채널과
파일 ID 가 들어 있어 같은 이름 파일이 두 채널에 있어도 안 충돌한다. 7.5 점검표
(`review_batch.py`)가 회차마다 여기서 `meta.json`(숨긴 시트·상한 초과로 뺀 시트·서식
미해석)을 찾는다 — 다른 자리에 두면 점검표가 그 정보를 못 읽는다. 저장소 밖이라
커밋에 섞일 수 없고, 점검이 끝난 뒤 캐시가 지워져도 상관없다(10단계).

수식 셀인데 엑셀이 캐시한 값이 없으면 `EmptyFormulaError` 로 멈춘다 — 엑셀이나
LibreOffice 로 한 번 열어 저장한 뒤 다시 돌린다.

**변환한 뒤 삽입 전에 `screen_personal.py` 로 훑는다.** 엑셀은 이 훑기를 거친 것만 넣는다.

**이 훑기가 세는 축은 5단계 규칙 4 와 같다** — 주민·법인·외국인등록번호 · 휴대폰 ·
유선전화 · 사업자등록번호 · 이메일 · **계좌**. 화면의 「잔여 0건」 줄이 그 여섯을
그대로 나열하므로, 안 세는 축이 생기면 그 줄에서 이름이 빠진다.

**계좌는 2026-09-03 에 더했다.** 그전까지 이 도구는 `INLINE_PATTERNS` 다섯만 가져오고
`ACCOUNT_WORD`·`ACCOUNT_NUM` 은 **임포트조차 안 했는데**, 화면 문구는 「전화·이메일·
주민번호 잔여 0건」이라 **계좌를 안 본다는 사실이 어디에도 안 적혀 있었다.** 이 절이
이 훑기를 삽입 전 관문으로 지정하고 있으니 그 ✓ 가 곧 통과로 읽힌다. 판정 조건은
변환기(`mask_inline`)와 **글자 그대로 같다** — 계좌 낱말이 **같은 칸**에 있고 날짜로
안 읽힐 때만. 조건이 갈리면 「0이 아니면 변환기 결함」이라는 뜻이 무너진다.

- **못 보는 자리**: 표에서 「계좌」가 **머리글 칸**에 있고 값이 다른 칸에 있는 모양.
  변환기도 그건 안 가리므로 여기서 잡으면 안 되고, **7.5 점검표가 회차 블록 전체를
  먹여서 보는 몫**이다(2026-08-26 에 그 경로로 진짜 은행 계좌 11건이 나왔다).
  화면의 ✓ 줄이 이 한계를 함께 찍는다
- **더한 뒤 실측**: 자료 저장소의 엑셀 회차 175개를 되살려 돌려 보면 계좌 낱말이 든
  칸이 43개 있는데 **잔여 0건**이다 (2026-09-03). 볼 데이터가 없어서 0인 것이 아니라
  보고 0이다. 헛걸림도 0건이라 화면이 시끄러워지지 않는다

**`✗ 훑을 시트가 없습니다` 는 통과가 아니다** (2026-09-03 부터). `sheet-*.md` 가 0개면
`✓ 잔여 0건` 대신 이 줄이 나온다 — 엑셀이 아닌 문서(pdf·hwp·docx) 폴더를 가리켰다는
뜻이다. 그전에는 **아무것도 안 훑고도 `✓ 잔여 0건`** 이 나와서 「안 쟀다」와 「안전하다」가
같은 화면이었고, 이 절이 그 훑기를 삽입 전 관문으로 지정하고 있으니 0건이 통과로 읽혔다.
요약 줄도 「훑음」과 「훑을 시트가 없음」을 갈라 센다. `--quiet` 로도 안 접힌다.

```bash
python .claude/skills/doc-archive/scripts/screen_personal.py \
    ~/.doc-cache/<채널>/<파일ID>_<원본명>.xlsx.blocks
# 여러 개를 한 번에: … screen_personal.py ~/.doc-cache/*/*.blocks --quiet
```

열 마스킹은 잘 걸린다 — 2026-08-25 전수 대조에서 핸드폰 424·EMAIL 350·주소 742개
고유값이 전부 `***` 였다. **다만 열 이름이 변형이면 이 대조에 애초에 안 잡힌다** —
2026-09-03 에 `주민(사업자)번호`·`거주지` 가 그래서 통째로 안 가려지고 있었다. 이
대조는 「가리기로 정한 열이 가려졌나」를 재지 「가려야 할 열을 알아봤나」를 안 잰다. **이름은 2026-08-26 부터 가리지 않는다** — 그전에 이 절이
「새는 것은 이름이고 열 밖 세 경로로 샌다」고 적고 있었는데, 그 셋(업체 열에 값으로
든 이름 · `○○○ (다일 E&C)` 처럼 한 칸에 섞인 것 · 자유 서술 메모 안의 실명)은
이제 새는 것이 아니라 정상이다.

**이름 낱말은 `NAME_COLUMN_WORDS` 에 있다 — `MASK_COLUMN_WORDS` 에서 지우면 안 된다.**
`find_header_row` 가 걸리는 낱말 2개로 머리글 행을 찾는데, 지우면 `대표자명 … 담당`
으로 겨우 문턱을 넘던 시트가 1개로 떨어져 머리글을 못 찾고 **시트가 통째로 안 실린다**.
`header_kind` 가 `keep` 을 주므로 세어지되 안 가려진다.

**머리글 행은 두 번 찾는다** (2026-08-27 부터).

1. **1차** — 위 10행에서 걸리는 낱말이 **2개 이상**인 첫 행 (`MIN_HEADER_HITS`)
2. **2차** — 1차가 실패했을 때만. 낱말이 1개이되 **그 칸이 라벨**(30자 미만,
   `HEADER_LABEL_MAX`)이고 **그 행의 값 있는 칸이 3개 이상**
   (`MIN_HEADER_CELLS_FALLBACK`)인 첫 행

2차가 필요한 이유는 **걸리는 낱말이 하나뿐인 표가 실물에 있어서**다 —
비공개나 「급여계좌」의 `구분 · 계좌번호 · 잔액 · 비고`, 사업장라 요약본의
`동호수 · 타입 · 계약자명 · …`. 문턱 2 만 두면 이런 시트가 통째로 빠졌다.

**「값 3칸」 문턱을 낮추지 말 것.** 「급여계좌」는 2행이 제목 `□ 급여계좌`(값
1칸)이고 3행이 진짜 머리글이다. 문턱이 없으면 2행을 잡아 은행명 열을 가리고
**계좌번호 6개가 그대로 나간다** (2026-08-26 측정에서 실제로 돌려 확인한 경로다).

**2차로 잡은 시트는 7.5 점검표에 「낱말 1개짜리로 머리글을 잡은 시트」로 뜬다.**
에러가 아니라 「열어 보라」는 표시다 — 진짜 머리글이 그 행보다 아래에 있으면
주소·계좌 열이 안 가려진 채 실린다. 막지는 않는다.

**2차로 잡은 시트는 md 메타에도 남긴다** — `> **시트**:` 줄 바로 다음에
`> **2차 머리글**: 급여계좌` (여럿이면 `·` 로 잇는다) 한 줄을 더한다. **언제
적나** — 7.5 점검표가 「메타에 적어 두세요 — `> **2차 머리글**: …`」라고 하면
그 문장을 그대로 옮긴다. **왜 적나** — 캐시 `meta.json` 은 `prune_cache` 가
커밋 뒤에 지운다. 안 적으면 「2차로 잡았다」가 그 회차와 함께 사라지고, 「몇 주
보고 잦으면 2차 판정을 좁힐지 정한다」를 나중에 셀 재료가 없어진다.

**시트를 통째로 빼는 것은 주소 · 생년월일 · 계좌 · 주민번호 · 주민등록번호 다섯과,
10자 이하일 때만 세는 거주지 · 송달장소 둘이다** (`DROP_TRIGGER_WORDS` +
`DROP_TRIGGER_PATTERNS` + `DROP_TRIGGER_SHORT_ONLY`, 2026-08-27 부터 ·
**뒤의 둘은 2026-09-03 에 더했다**. `sheet_drop_reason` 이 판정한다).
머리글을 1차·2차 다 못 찾았고 이 낱말이 **라벨 칸**에 있을 때만 뺀다.

- **거주지·송달장소만 길이를 재는 이유** (WHK 결정 2026-09-03). 실물로 갈렸다 —
  아카이브 전체에서 `거주지` 가 든 **머리글 칸은 0종**이고, 걸리는 것은 상담 메모·제출서류
  목록 **3종(20·25·28자)** 뿐이다. 반면 진짜 주소 머리글은 전부 짧다(`주소` 2 ·
  `도로명주소` 5 · `물건지 주소` 6 · `도로명상세주소` 7). `is_label_cell` 의 30자 문턱만으로는
  저 메모들이 통과해 **표 하나를 통째로 버린다** — 2026-08-26 사고와 같은 모양이다.
  **열 마스킹에서는 길이를 안 잰다** — 11자짜리 `거주지…` 열도 여전히 가린다.
- **남는 위험** — 머리글 행을 못 찾은 시트가 주소를 `주소` 가 아니라 **11자 이상의
  `거주지…`** 로 적으면 자택주소가 통째로 실린다. **그때 잡아 줄 것이 없다** —
  `screen_personal` 은 전화·이메일·등록번호·계좌를 *모양*으로 찾는데 **주소는 모양이 없다.**
  다만 「머리글을 못 찾아 시트를 뺐다」는 경로 자체가 문서 431개 중 **한 번** 발동했다.

- **주민번호·주민등록번호는 인라인 정규식의 좁은 구멍을 메우려고 넷째·다섯째로
  더했다** (WHK 결정 2026-08-27). 인라인 정규식은 `\d{6}\s*[-–]\s*\d{7}` 이라
  `6자리-7자리`처럼 구분자가 있으면 잡지만 `13자리 연속 숫자`처럼 구분자
  없이 적은 것은 못 잡는데, 엑셀에는 그렇게 적은 경우가 흔하다. 인라인만 믿으면
  표가 10행 밖에서 시작해 머리글을 못 찾고, 머리글이 `성명 · 주민등록번호 ·
  연락처` 라 주소·계좌가 없는 시트가 마스킹 없이 그대로 실린다. 좁은 경로지만
  가장 민감한 항목이라 안전 쪽을 골랐다. 구분자 없는 유선전화도 같은 모양의
  구멍이지만, 그것은 지금도 아카이브 전체에서 안 잡히는 것이라 여기서 달라지는
  게 없어 넣지 않았다
- **주민번호는 2026-09-03 부터 낱말이 아니라 꼴로 본다** (`주민[\s\S]{0,8}번호`,
  `MASK_COLUMN_PATTERNS`). 실무에 흔한 `주민(사업자)번호`·`주민/사업자번호` 는
  `주민번호` 의 부분 문자열도 `주민등록번호` 의 부분 문자열도 아니라 **한 건도 안
  걸렸고**, 같은 표에 `연락처` 가 있으면 머리글 행은 정상적으로 찾아지므로
  `sheet_drop_reason` 안전망도 안 돌았다. 픽스처로 재현했다 — 연락처만 `***` 가 되고
  주민등록번호·자택주소는 그대로인데 훑기는 「잔여 0건」, 7.5 점검표는 `mask_hits: []`.
  **낱말을 더 넣는 처방은 다음 변형(`주민(법인)번호`)에 또 뚫린다 — 끼어드는 말은
  닫힌 목록이 아니라 자리다.** 줄바꿈까지 받는 `[\s\S]` 인 이유는 이 아카이브에
  `물건<br>번호` 처럼 접어 적은 머리글이 실재하기 때문이다. 넓힌 값은 잰 뒤에 골랐다 —
  아카이브 md 433개·표 칸 44,919개에 고치기 전 코드와 나란히 돌려 **머리글 칸 2,645개
  중 판정이 바뀐 것 0개**였다. `주거지` 는 일부러 뺐다 — `제2종일반주거지역` 이 걸린다
- **전화 · 휴대폰 · 핸드폰 · 연락처 · EMAIL · 이메일은 빼는 이유가 아니다** — 열 머리글이 없어도 `mask_inline` 이
  모양으로 잡는다. 열 마스킹은 여전히 열세 개 전부로 한다
- **서술 문장 안의 낱말도 빼는 이유가 아니다** — 상담 메모의 「중도금이자계좌
  안됨」은 가려야 할 열이 있다는 뜻이 아니다. 이 문장 하나가 95행짜리 표를
  통째로 버리고 있었다 (2026-08-26 측정 2-1절)
- **`HEADER_LABEL_MAX`(30자)를 좁히려면 실물을 다시 재고 좁힌다.** 2026-08-27
  실측에서 주소·생년월일·계좌가 든 칸 44개의 라벨은 최장 15자, 문장은 최단 37자,
  16~36자는 0칸이었다. 그 44칸에는 안 들어가지만 실제 머리글로 확인된 것 중
  가장 긴 것이 25자다(사업장라 (축약) 반응도 4행 `내용증명 발송 이후 계약자
  반응도(6월 이후)`)

**이 도구는 판정하지 않는다.** 종료코드는 언제나 0이고 아무것도 막지 않는다.
좁혀서 보이기만 하고 갈래는 사람이 정한다 — 2026-08-25 에 자동 판정을 두 번
시도해 두 번 다 틀렸고 실패의 모양이 서로 반대였다(1판은 `구분`·`지분율` 을
이름으로 잡았고, 2판은 「여러 파일에 나오면 업무 용어」로 걸러 진짜 이름을 지웠다).

갈래는 넷이다 — **2026-08-26 부터 다섯에서 줄었다.** 이름 후보가 남아도 더는
「안 넣음」·「한 시트만 문제」로 가르지 않는다 — 이름은 이제 가리지도, 있다고
빼지도 않는다(WHK 결정 2026-08-26). 남은 실제 결함은 인라인 잔여(전화·이메일·
주민번호 등)뿐이다.

| 갈래 | 뜻 |
|---|---|
| 넣음 | 인라인 잔여가 0건이다. 이름 후보는 **참고일 뿐**이다 — 아카이브가 이미 발언자 이름을 담고 있고, 계약자·외부인 이름도 이제 가리지 않는다 |
| 변환기 결함 | 인라인 잔여(전화·이메일·주민번호 등)가 남았다. `xlsx_to_blocks.py` 를 고치고 다시 변환한다 |
| 변환 실패 | `EmptyFormulaError` 등. LibreOffice 로 다시 저장한 뒤 재시도 |
| 물림 | 같은 자료의 더 최신 판이 있다 |

**표의 첫 줄도 훑는다.** 변환기는 살아남은 첫 줄을 무조건 `<th>` 로 찍을 뿐 그것이 머리글인지
데이터인지 보지 않는다 — 안 훑으면 첫 줄이 실제 데이터인 시트에서 그 줄의 이름·전화가 통째로
안 보인다(WHK 결정 2026-08-25). 그래서 보고에 열 이름 자리에 `(머리글 줄)` 이 찍히고,
`대표자명`·`계약자명` 처럼 **열 이름 자체가 이름 후보로 뜬다** — 정상이다. 그 잡음은
스톱리스트가 받는다.

**스톱리스트** — `screen_personal_stoplist.txt` 에 「성씨로 시작하지만 사람이 아닌
말」을 한 줄에 하나씩 쌓는다(`조정액`·`이자율`). **글자 전체가 정확히 같을 때만**
걸리므로 `이자` 한 줄이 `이자현` 이라는 사람을 삼키지 않는다. 뺀 것은 보고에 개수와
함께 항상 찍힌다. **사람 이름일 수 있는 말은 넣지 말 것** — 애매하면 그냥 두고 매번
눈으로 본다. 여기에 무엇을 넣든 **아카이브에 들어가는 글자는 한 자도 안 바뀐다.**

**훑기가 0건이라고 안전하다는 뜻이 아니다.** 못 잡는 것이 셋 있다 — 성씨 목록에
없는 이름(외국인의 한글 표기), 성 없는 표기(`영희`·`민수 대리`), 그리고 `rowspan`
때문에 열이 밀렸을 때의 머리글. 앞의 둘은 호칭 그물(`님`·`계약자`·`매수자` 등이 든
칸을 통째로 보인다)이 일부를 받치지만 전부는 아니다. 이 도구는 **볼 곳을 좁히는
것**이지 보증이 아니다.

**시트를 1→N 순으로, `--source` 에 시트 이름까지 넣어서 삽입한다:**

```bash
for f in ~/.doc-cache/<채널>/<파일ID>_<원본명>.xlsx.blocks/sheet-*.md; do
  header=$(head -n 1 "$f")
  src=$(echo "$header" | sed -E 's/^\*\*[0-9]{4}-[0-9]{2}-[0-9]{2} · (.*)\*\*$/\1/')
  python .claude/skills/doc-archive/scripts/insert_entry.py \
      --file "$DATA/documents/projects/<사업장>/<문서>.md" \
      --date 2026-08-20 --source "$src" --content-file "$f"
done
```

지키지 않으면 **조용히** 틀리는 것이 둘이다:

- **`--source` 에 반드시 `— 시트 n/N: 이름` 까지 포함한다** (위처럼 블록 헤더에서 그대로
  뽑는다. 원본 파일명만 주지 않는다). `insert_entry.py` 의 중복 판정(`already_has`)은 `source in lines[i]` 로 **회차 헤더 줄 안에 그 문자열이 있는지**만 본다.
  `--source` 를 `<원본명>.xlsx` 만 주면 그 문자열은 시트 1 의 헤더에도 들어 있으므로,
  시트 2 부터는 "같은 날짜·같은 원본의 회차가 이미 있다"고 오판해 **SKIP 되어 조용히
  사라진다** — 에러 없이 종료코드 2 뿐이라, 화면을 안 보면 시트 하나만 들어간 줄 모른다.
- **시트를 반드시 1→N 오름차순으로 부른다.** `insert_entry.py` 는 같은 날짜 안에서
  새 회차를 **맨 위(최신 자리)**에 끼운다(`insert_entry` 의 같은-달 갈래) — 그래서 1→N 순으로 부르면
  시트 1 이 자연히 맨 위에 남는다. 거꾸로(N→1) 부르면 시트 N 이 맨 위로 올라온다.
  **일일 요약과 검색 클리핑은 그 md 의 위쪽 블록을 먼저 읽는다** — 순서가 틀리면
  봇이 "산정내역" 대신 "부록" 같은 엉뚱한 시트를 근거로 답한다.

메타에는 **`수록 회차` 대신** 두 줄을 쓴다 — 시트는 개정 이력이 아니라 한 파일의
구획이라, 회차로 세면 `documents.js` 의 `isSeriesDoc()` 이 시리즈로 굳혀 색인에서 영원히 안 접힌다.

```markdown
> **시트**: 산정내역 · 이자계산 · 상환스케줄
> **값 표기**: 엑셀 화면 표시 그대로 (서식으로 반올림된 자리가 있음)
```

둘째 줄은 설계 ④ 의 「반올림」 규칙이다 — 이게 있어야 봇이 원 단위까지 따지는
질문에 "원본 확인이 필요하다"를 덧붙인다(스캔본의 `변환` 메타 `OCR 사용` 줄과 같은
구실이다). 개인정보를 가린 열이 있으면 셋째 줄에 `마스킹` 을, 숨겼거나 안 실은 시트가
있으면 넷째 줄에 `수록 범위` 를 더한다.

**단위가 시트마다 다를 수 있고, 셀에 표시가 없을 수 있다.** 2026-08-23 실측으로
`260714_사업장나 잔금수금 업무보고(VAT별도).xlsx` 는 `1.잔금수금 일일보고` 가
**백만원**(`619562.8`), `수금실적 통계` 가 **천원**(`619562800`) 인데 1~7행에
`단위` 라는 글자가 없다. 봇이 시트를 잘못 짚으면 **1,000배 틀린 값**을 인용하고
에러는 안 난다. 그래서 메타 `주요 항목` 에 **어느 시트의 어느 단위인지**를 적는다.

```markdown
> **마스킹**: EMAIL · 대표자명 · 연락처 · 우편물주소1 · 우편물주소2 · 핸드폰 (84행 · 인라인 6건)
> **수록 범위**: 지난 날짜 상담 시트 27장(0408~0709)은 싣지 않았다 — 같은 파일 안에
> 날짜별로 쌓인 것이라 최신 1장만 실었다. 숨긴 시트 47장, 마스킹 불가 시트 2장도
> 싣지 않았다. backdata 시트(4,180행)는 상한을 넘어 뺐다 — 원본은 슬랙 #<채널>
```

`마스킹` 줄은 `meta.json` 의 `masked` 를 **옮겨 적을 뿐 지어내지 않는다** — 아래 틀에
그 안의 네 값을 그대로 넣으면 된다.

```
> **마스킹**: <columns 를 · 로 나열> (<rows>행<comments_dropped > 0 이면 ' · 메모 N건 제외'><inline > 0 이면 ' · 인라인 N건'>)
```

- `columns` — 가운뎃점(`·`)으로 나열. 줄이 되는 자리.
- `rows` — 괄호 안에 항상 `N행` 으로 적는다. 마스킹 열에 실제 값이 있던 행 수.
- `comments_dropped` — **0 이면 그 구절 자체를 뺀다.** 0 보다 크면 `· 메모 N건 제외`
  를 이어 붙인다(가려진 열 위에 있어 같이 뺀 셀 메모 수).
- `inline` — **0 이면 그 구절 자체를 뺀다.** 0 보다 크면 `· 인라인 N건` 을 이어 붙인다
  (열 마스킹을 안 탄 칸 안에서 전화번호·이메일·주민번호를 따로 지운 건수).

`260710_사업장가 일보.xlsx` 의 실제 값(`rows: 84, comments_dropped: 0, inline: 6`)을
넣으면 위 `마스킹`·`수록 범위` 예시가 그대로 나온다 — `comments_dropped` 가 0 이라 그 구절만 빠졌다.
**셋 다 있는 경우**(`rows: 84, comments_dropped: 3, inline: 6`)는 이렇게 된다:

```markdown
> **마스킹**: EMAIL · 대표자명 · 연락처 · 우편물주소1 · 우편물주소2 · 핸드폰 (84행 · 메모 3건 제외 · 인라인 6건)
```

`수록 범위` 는 한 시트가 안 실리는 **네 가지 다른 이유**를 한 줄에 모은다 — 서로
뜻이 달라 섞어 적으면 뭐가 왜 빠졌는지 못 가린다.

- `folded_date_sheets` — 같은 파일 안에 날짜별로 쌓인 시트(예: `상담(MMDD)`) 중 최신
  1장만 남기고 접은 것. "지난 날짜 OO 시트 N장은 싣지 않았다 — 최신 1장만 실었다"
- `hidden_sheets` — 엑셀에서 숨겨 둔 시트. "숨긴 시트 N장도 싣지 않았다"
- `unmaskable_sheets` — 머리글 행을 못 찾아 개인정보 열을 가릴 방법이 없어 통째로
  뺀 시트. "마스킹 불가 시트 N장도 싣지 않았다"
- `skipped_sheets` — 행 수가 상한을 넘어 뺀 시트. "OO 시트(N행)는 상한을 넘어 뺐다"
  (시트 이름과 행 수는 지어내지 않는다 — `meta.json` 의 `skipped_sheets` 배열에
  `xlsx_to_blocks.py` 가 그대로 적어 둔 `name`·`rows` 값을 옮긴다)

네 이유를 한 줄에 몇 개를 이어 적든 **끝에 `원본은 슬랙 #<채널>` 을 한 번만** 붙인다
(위 `마스킹`·`수록 범위` 예시의 `backdata` 줄) — 이유마다 반복하지 않는다.

`verify_format.py` 의 5-1 검사는 두 가지를 본다(둘 다 ✗ 다). ① 메타의 `시트` 개수·이름과
본문의 시트 헤더가 갈리는지. ② **본문에 시트 헤더가 있는데 `시트` 줄 자체가 없는지** —
이쪽이 더 조용한 쪽이다. 봇의 `isSheetDoc` 이 그 한 줄로만 엑셀을 가르므로, 빠뜨리면
시트가 회차로 세어져 그 문서가 6,000자 색인에서 **영원히 안 접히는 줄**이 된다(실측: 엑셀
4건이 메타가 있으면 `그 외 4건` 으로 접히고, 없으면 네 줄을 그대로 차지한다).
`review_batch.py` 의 「엑셀」 칸도 같은 둘을 회차 표에서 보여준다(아래 7.5단계).

5-2 검사는 `마스킹` 줄과 본문의 가린 칸(`***`)이 **둘 다 있거나 둘 다 없는지**를 본다 —
한쪽만 있으면 ✗ 다. 본문에 `***` 가 있는데 `마스킹` 줄이 없으면 봇이 빈칸을
"자료에 없다"로 읽고, 거꾸로 `마스킹` 줄만 있고 `***` 가 없으면 메타가 낡았거나
마스킹이 실제로는 안 걸린 것이다.

**이 검사는 줄이 있는지만 본다 — 줄 안의 값은 안 본다.** 8개 열을 가렸는데 `마스킹`
줄에 5개만 적거나, `rows` 숫자가 틀리거나, 열 이름을 잘못 써도 ✓ 로 통과한다.
그래서 위 틀은 손으로 짓지 말고 그 문서를 변환할 때 나온 `meta.json` 의 `masked` 값을
그대로 옮겨 적는다.

**가릴 낱말이 들었지만 사람의 것이 아닌 열은 예외로 연다** — `xlsx_to_blocks.py` 의
`NOT_PERSONAL_HEADERS` 다. 지금 든 것은 셋이다 — `물건지 주소`(감정평가 대상
부동산의 소재지이지 사람이 사는 곳이 아니다, WHK 결정 2026-08-25),
`신탁계좌가압류`(신탁계좌에 가압류를 걸었나 여부(ㅇ/빈칸)이지 계좌번호가
아니다 — `계좌` 가 부분 일치로 걸려 118행이 통째로 가려져 있었다, 2026-08-26
사업장파 원본 확인), 그리고 `계좌잔액`(비교 시트 C열이
`계좌잔액·미납잔금·재판매수입금…` 인 **항목 이름 열**인데 맨 위 칸이 걸려 이름
23칸이 `***` 가 됐고, 금액은 옆 열이라 남아 **어느 돈인지 알 수 없는 표**가 됐다,
WHK 결정 2026-08-28, 커밋 `730aff8`). **정확 일치라 `계좌잔액 (8/20기준)` 은 그대로
가려진다** — 그런 시트가 실제로 있다.

- **머리글 전체가 정확히 같을 때만 걸린다.** 부분 일치가 아니다 — `물건지 주소1`·
  `계약자 물건지 주소` 는 그대로 가려진다. `KEEP_COLUMN_WORDS` 를 제외에 쓰지 않는
  이유(`팀` 이 `팀장 성명` 을 삼킨다)가 여기에는 없다
- **여기 한 줄을 더하는 것은 그 이름의 열을 앞으로 전부 여는 일이다.** 한 문서만
  열려면 그 열의 머리글을 바꾸는 편이 낫다
- **연 것은 `meta.json` 의 `masked.not_personal` 과 7.5 점검표의 `안 가림(예외)` 줄에
  남는다.** 가린 것은 md 에 `***` 로 눈에 띄지만 **안 가린 것은 평범한 값으로 실려
  표에서 아무 표시가 없다** — 그래서 점검표가 유일하게 보이는 자리다
- **가린 칸이 하나도 없으면 `마스킹` 줄을 넣지 않는다.** 예외로 열어 `***` 가
  0개가 되는 일이 실제로 있다(2026-07-20 어느 감정결과 안내 문서: 나머지 마스킹 열
  둘이 원본에서 비어 있었다). 그때 줄을 넣으면 5-2 검사가 ✗ 를 낸다.
  **무엇을 왜 안 가렸는지는 `수록 범위` 에 적는다**
- **정규식은 `xlsx_to_blocks.py` 의 `INLINE_PATTERNS` 한 곳에만 있다** (2026-08-26).
  `review_batch.py`·`screen_personal.py` 가 가져다 쓴다. 전에는 두 벌이 「같아야 한다」
  는 주석에 기대고 있었고, 한쪽만 고쳐도 에러가 안 나서 **변환기는 가리는데 점검표는
  ✓ 를 찍는** 상태가 조용히 났다. 패턴을 더할 때는 그 한 곳만 고친다

**워드 주석(코멘트)은 kordoc 이 md 에 안 넣는다 — 따로 뽑아야 한다.**
본문은 멀쩡한데 **그 파일을 올린 이유가 통째로 빠진다.** 2026-08-05 에 실제로 그럴 뻔했다:
`사업장가 임대차 계약서_갑사 검토의견 추가` 는 이전 판과 본문 차이가 서명란뿐이었고,
검토의견 9건(886자)이 전부 주석에 있었다. 같은 배치의 사업장가 합의서 v1 도 1,026자(23건)가
주석이었다. 글자 수 검사도 통과한다 — 본문은 충분히 길기 때문이다.

`.docx`(LibreOffice 로 바꾼 것 포함)를 다룰 때는 **변환 전에 주석 유무를 먼저 센다.**

```bash
python - <<'PY'
import zipfile, glob, re, os
for f in sorted(glob.glob('<docx 폴더>/*.docx')):
    z = zipfile.ZipFile(f); c = 0
    if 'word/comments.xml' in z.namelist():
        c = len(re.sub(r'\s+',' ', re.sub(r'<[^>]+>',' ', z.read('word/comments.xml').decode('utf-8','ignore'))).strip())
    d = z.read('word/document.xml').decode('utf-8','ignore')
    ins, dele = len(re.findall(r'<w:ins ', d)), len(re.findall(r'<w:del ', d))
    if c or ins or dele:
        print(f'주석 {c}자 · 삽입 {ins} · 삭제 {dele}  {os.path.basename(f)}')
PY
```

주석이 있으면 **뽑는 것은 스크립트가 한다** (2026-08-29 부터).

```bash
python .claude/skills/doc-archive/scripts/extract_comments.py <docx경로>
python .claude/skills/doc-archive/scripts/extract_comments.py <docx경로> --count  # 건수만
```

나온 절을 회차 본문 끝에 그대로 붙인다.

```markdown
### 문서 주석 (검토의견)

원본 워드 파일의 **주석(코멘트)**에만 있는 내용이다. 본문에는 나오지 않는다.

- **[홍길동 · 2026-08-28]** 최종 결정의 의미가 모호합니다 …
- **[김철수 차장(○○팀)]** [갑사] 위약벌 기준의 경우 …
```

- **붙이는 것은 사람이 한다.** 스크립트는 절 본문을 만들어 줄 뿐 md 를 고치지 않는다 —
  주석에도 개인정보가 들어갈 수 있어 마스킹 판단이 걸린다
- 머리는 `[이름 · 날짜]` 이고 원본에 `w:date` 가 없으면 `[이름]` 이다. **두 모양 다
  아카이브에 이미 있다** — `.doc` 를 LibreOffice 로 바꾸면 날짜가 없어진다
- 절 제목은 `review_batch.py` 의 `COMMENT_SECTION` 과 **같아야 한다.** 어긋나면 붙여
  놓고도 7.5 점검표가 「주석이 빠졌다」고 계속 ⚠ 를 낸다. `test_extract_comments.py`
  가 그 문자열을 그 모듈에서 읽어 대본다
- **`.doc`·`.hwp` 는 이 스크립트가 못 읽는다** — docx(zip) 만 연다. `.doc` 는 4단계에서
  LibreOffice 로 docx 로 바꾼 **그 파일**을 주면 된다
- 변경내용추적(`<w:ins>`·`<w:del>`)은 **안 싣는다.** 같은 자리에 있지만 「문서가 어떻게
  고쳐졌나」라 「사람이 무엇을 지적했나」와 축이 다르다. 필요해지면 그때 함께 정한다

**파일명에 `검토의견`·`mark up`·`의견` 이 들어 있는데 주석이 0자면 의심할 것** — 이름과 내용이
어긋난다는 뜻이고, 대개 변환 단계에서 잃은 것이다. 개정 판본 중 무엇을 실을지 정할 때도
**본문 유사도만 보면 안 된다** — 본문이 99% 같아도 주석이 다르면 다른 문서다.

**한글(`.hwp`·`.hwpx`)도 변환 전에 변경 내용 추적을 센다 — 위 `w:ins`·`w:del` 과 같은 자리다.**

한글은 화면에 **「최종본」만 보여 준다.** 그래서 추적이 켜진 채 저장된 파일은 **사람이
원본을 열어도 안 보이고**, 그대로 변환하면 고치기 전 값과 고친 뒤 값이 **한 칸에 붙어**
나온다. 2026-08-28 어느 사업장의 현황보고 hwp 가 그랬다 — 변경 기록
138건이 켜져 있었고 변환본에 겹친 숫자가 9곳이었다.

```
3,100845 (→3,845억)   1,200770 (→770억)   41.238.5   15.611.2   7.35.8
8,31210,104           5,2074,613          3,1512,976            812804
```

**`3,100845` 는 자릿수가 이상해 눈에 띄지만 `812804`·`15.611.2` 는 그냥 숫자로 보인다.**
그리고 **취소선을 찾는 검사로는 못 잡는다** — 그 파일의 글자모양 81개에 취소선 속성이
하나도 없었다.

```bash
python .claude/skills/doc-archive/scripts/count_track_changes.py ~/.doc-cache/<채널>/*.hwp
python .claude/skills/doc-archive/scripts/count_track_changes.py --quiet <파일들>  # 걸린 것만
```

종료코드는 **0 없음 · 1 있음 · 2 못 읽음**이다. **2 를 0 으로 읽지 말 것** — 「깨끗하다」와
「못 봤다」는 다르다. 의존성은 없다(표준 라이브러리만 쓴다).

**위 4단계의 경로 함정이 여기도 똑같이 걸린다** — Git Bash 에서 `[`·`'` 가 든 이름을
`/c/...` 경로로 주면 이 스크립트도 파일을 못 찾는다. `cygpath -m` 으로 감싸면 된다
(2026-09-03 실측: `[최종본 기준]…hwpx` 가 그냥 주면 종료코드 2, 감싸면 0). **다행히
0 이 아니라 2 가 나오므로 「추적 없음」으로 오해되지는 않는다.**

- **hwp5 는 확실하다.** DocInfo 의 태그 96(변경 기록)·97(작성자)를 세고, FileHeader
  문서속성의 비트 14(「변경 추적 문서」)도 함께 본다. 2026-09-03 실측 — 위 실물이
  **138건·작성자 2명·플래그 켜짐**으로 나왔고, 평범한 hwp 38개는 전부 0건·플래그 꺼짐이었다
- **hwpx 는 「없다」고 단정하지 않는다.** 설정은 `Contents/header.xml` 의
  **`hh:trackchageConfig`** 에 적히는데 **한컴 오타라 `change` 가 아니라 `chage` 다.**
  그래서 `trackChange` 로 찾으면 **켜져 있든 아니든 0 이 나온다** — 2026-09-02 에 hwpx
  1건이 0 으로 나온 것은 이 때문이고, 그 0 은 아무것도 뜻하지 않았다. 2026-09-03 에
  이 PC 의 hwpx 33개를 재니 전부 `flags="56"` · 본문 변경표시 0개였다. **추적이 켜진
  hwpx 실물을 못 구해서 「켜지면 무엇이 달라지나」는 확인 못 했다** — 그래서 스크립트는
  그 기준선과 조금이라도 다르면 통과시키지 않고 사람에게 넘긴다
**켜져 있으면 — 막지 말고 메타에 적는다** (WHK 결정 2026-09-03).

**변환을 막지 않는다.** 막으면 그 문서가 통째로 아카이브에 안 들어가고 봇은 「자료가
없습니다」로 답한다 — 같은 날 kordoc 건에서 본 실패 모양 그대로다. 대신 **사람이 반드시
보게** 한다.

1. `count_track_changes.py` 를 **변환 전에** 돌린다 (위 명령).
2. 결과를 그 회차의 md 메타에 적는다 — 0건이어도 적는다:
   ```
   > **변경추적**: 138건 · 작성자 2명 (2026-09-03 측정)
   > **변경추적**: 0건
   ```
3. 0건이 아니면 **원본을 한글에서 「변경 내용 표시」로 열어 겹친 숫자를 대조하고**,
   무엇을 고쳤는지 그 회차의 `수록 범위` 에 적는다.

**7.5 점검표가 이것을 본다** (`track_change_note`). hwp·hwpx 회차인데
① `변경추적` 메타가 **없으면** 「안 쟀다」고 말하고 ② 0건이 아니면 겹친 숫자를 보라고
말한다. **「안 쟀다」와 「0건」을 같은 화면으로 두지 않는 것이 핵심이다** — 같으면 안 센
회차가 통과로 읽힌다. 이미 아카이브에 든 hwp 문서 **104개**가 매번 울리지는 않는다 —
점검표는 **이번 배치에 새로 들어오거나 다시 변환된 회차**만 본다.

`변경추적` 줄만 고친 것도 `meta_changed` 가 알아보므로 「새 회차도 메타 변경도 못
찾았습니다 ⚠」가 뜨지 않는다.

**개별 파일을 일부러 빼기로 했으면 `decide.py` 로 적는다** (JSON 을 손으로 고치지 않는다).

```bash
python .claude/skills/doc-archive/scripts/decide.py <선택자> --skip  --reason "…"   # 영구 제외
python .claude/skills/doc-archive/scripts/decide.py <선택자> --later 14 --reason "…" # 이번엔 보류
```

선택자는 슬랙 파일 ID · 매니페스트 번호 · 파일명 조각이다. 아직 변환 전인 파일을
가리키려면 2단계에서 만든 `--manifest` 를 함께 준다. 여럿에 걸리면 목록을 보이고 멈춘다.

- **`--reason` 은 필수다.** 왜 뺐는지가 없으면 다음 사람이 되돌릴 수 없다
- **이미 다른 칸에 결정이 있으면 멈춘다.** 영구 제외였던 것을 `--later` 하면 앞서 적어 둔
  사유와 「누가 언제 정했나」가 지워진다 — 등기부등본을 개인정보 때문에 뺐다는 근거가
  사라지고, 만기가 지나는 순간 후보로 돌아와 다음 사람이 그냥 넣는다.
  정말 바꿀 것이면 `--force`, 아니면 `--clear` 먼저

개인정보가 든 등기부등본, 같은 날짜의 초안 같은 것들이다. `index.md` 에 글로만 적으면
코드가 못 읽어서 **위생 점검이 매일 "미변환" 으로 다시 알린다.** 줄지 않는 숫자가 매일 오면
사람은 곧 알림 전체를 안 읽게 되고, 그때 진짜 밀린 것도 같이 묻힌다.
(2026-08-03: 이 자리를 만들기 전 「미변환 35건」 중 실제로 변환이 필요한 것은 2건이었다.)

```json
"excluded": {
  "F0EXAMPLE02": {
    "channel": "사업장타",
    "name": "…등기부등본 (○○동 ○○호).pdf",
    "reason": "개인 인적사항이 들어 있다. 필요하면 원본을 열 것",
    "decided": "2026-08-03 (WHK 확인)"
  }
}
```

### 5. 정규화 — 4규칙, 건너뛰지 말 것

kordoc 결과를 그대로 붙이면 포맷 계약이 깨진다.

| # | 규칙 | 어기면 |
|---|---|---|
| 1 | **본문 최상위 헤딩이 `###` 이 되도록** 전체를 같은 폭만큼 강등 (최대 `######`). 이미 `###` 이하면 그대로 둔다 | `readChannel` 월 섹션이 문서 중간에서 잘린다 |
| 2 | 본문에서 `^\*\*(\d{4}-\d{2}-\d{2})[^*]*\*\*\s*$` 에 **실제로 매칭되는** 줄 앞에 공백 1칸 | 문서 안 날짜 볼드가 가짜 회차로 오분할된다 |
| 3 | kordoc 의 `📑 문서 구조:` — 단발은 유지, **시리즈 회차에서는 제거** | 회차마다 같은 목차가 반복돼 검색이 잡음으로 찬다 |
| 4 | **주민·법인·외국인등록번호 · 사업자등록번호 · 휴대폰 · 유선전화 · 이메일 · 계좌번호** 마스킹. **사람 이름은 가리지 않는다** (WHK 결정 2026-08-26) | git 에 개인정보가 영구 기록된다 |

2번은 **정규식에 실제로 걸리는 줄만** 손댄다. `**2026. 06. 17 / 작성부서**` 처럼
점으로 쓴 날짜는 걸리지 않으니 그대로 둔다.

**이름을 안 가리는 이유** — 계약자 이름은 슬랙에서 이미 실명으로 논의 중이고,
글 문서(pdf·워드)에는 애초에 실명이 그대로 실려 있었다. 엑셀만 가리고 있어서
두 갈래가 어긋나 있었고, 그것 때문에 자료 27건이 통째로 빠져 있었다
(설계: `docs/superpowers/specs/2026-08-26-masking-rules-v2-design.md`).

**유선전화를 가리면 회사 대표번호도 함께 가려진다** (`02-1234-5678` 같은 것).
모양으로는 개인 것과 안 갈린다 — 덜 가리는 쪽이 사고이고 더 가리는 쪽은 자료를
조금 잃을 뿐이라 가리는 쪽으로 정했다.

**계좌번호는 「계좌·예금주·입금계좌·가상계좌」 낱말이 같은 줄에 있을 때만 가린다.**
모양만 보면 `2026-08-26` 이 그대로 걸린다. 대가로 낱말 없이 덩그러니 적힌 계좌는
못 잡는다.

**계좌 정규식의 구분자를 넓히지 말 것 — 재 봤고 헛걸림이 폭발한다** (2026-09-03 실측).
`ACCOUNT_NUM` 만 구분자가 `[-–]` 이고 다른 다섯 패턴은 `[-–.\s]` 라 비대칭이 눈에
띄지만, 자료 저장소 md 483개에 나란히 돌려 보면 **줄 단위 1건 → 20건**이 되고
늘어난 19건은 **전부 점으로 쓴 날짜**(`26.08.31`·`24.07.19`·`2026.06.26`)이거나
스캔본 숫자 표의 공백 세 칸(`500 00.000`)이었다. 날짜를 지키는 `looks_like_date` 가
`-`·`–` 만 보기 때문이다. 토막 수까지 2~4 로 풀면 47건이 되고 `2026-08` 같은
연월까지 걸린다.

**「토막이 넷일 때 마지막 토막이 안 가려지던 것」은 고쳤다** (2026-09-03, 커밋
`3f5f27f`). `mask_inline("입금계좌 301-1234-5678-90")` 이 `입금계좌 ***-90` 을
냈었다 — **가려진 것처럼 보이는데 안 가려진 모양**이라 눈으로도 안 잡힌다. 같은
483개에 「구분자는 그대로, 토막만 3~4」로 재니 **헛걸림 0건**이라 그 처방만 넣었다
(`ACCOUNT_NUM` 뒤에 `(?:[-–]\d{1,8})?` 선택 그룹).

**같은 기전이 사업자등록번호 패턴에도 있었고 그것도 고쳤다** (2026-09-03).
`\d{3}-\d{2}-\d{5}(?!\d)` 의 뒤 경계가 `-` 를 통과시켜 `301-12-34567-8` 에서
`***-8` 이 남았다 — `mask_inline` 이 인라인 다섯을 먼저 돌리므로 `ACCOUNT_NUM` 이
아니라 **이쪽이 먼저 먹는다.** 처방은 계좌와 글자 그대로 같다.

**뒤 경계를 `(?![\d-–])` 로 바꾸는 길은 쓰지 말 것 — 재 봤고 마스킹이 느슨해진다**
(2026-09-03 실측). 하이픈이 붙는 순간 매치를 **통째로 포기**하므로 `***-8` 이
`301-12-34567-8` **원문 그대로**가 된다. 반쯤 가리던 것이 아예 안 가려지는 쪽이다.
시험이 이 방향을 잡는다(`test_xlsx_to_blocks.py` 의 `BIZ_TAIL` 절).

**코드 수정은 앞으로 변환할 것에만 듣는다.** 이미 커밋된 md 의 잔여는 따로 고쳐야
한다 — 2026-09-03 에 자료 저장소에서 `***-8`·`***-559`·`***-191`·`***-176` 넷을
`***` 로 닫았다. 같은 것을 다시 찾으려면
`grep -rnoE "\*\*\*[-–][0-9]+" documents --include=*.md`.

**주민·법인·외국인등록번호 패턴의 뒷자리 첫 글자는 묶지 않는다** (`\d{6}-\d{7}`,
2026-08-26 에 `[1-8]` 에서 넓혔다). 그 자리가 성별·국적 코드인 것은 **주민등록번호
뿐**이고 법인등록번호의 같은 자리는 일련번호라 0~9 아무 값이나 온다. 좁혀 뒀다가
아카이브에서 4건을 놓쳤고, 그중 사업장카 건은 **같은 등기부 표에서 옆 줄은
잡히고 이것만 안 잡혀** 반쯤 가려진 표가 됐다. 근거는 같은 등기소(`110111`) 아래
법인 7곳의 그 자리가 `{0,3,4,7,7,8,8}` 로 흩어져 있다는 것이다 — 코드라면 같아야
한다. **다시 좁히지 말 것.**

**아카이브 전체에서 남은 것을 찾으려면:**

```bash
python .claude/skills/doc-archive/scripts/review_batch.py --mask-sweep
```

**범위는 자료 저장소 전체다** — 문서 아카이브(`documents/`)뿐 아니라 **대화
아카이브(`slack-export/`)와 저장소 뿌리의 운영 노트까지** 훑는다. 첫 줄에 어느
뿌리를 훑었는지 찍고, 끝줄에 **훑은 md 개수·잔여 건수·읽기 실패 건수**가 라벨별로
나뉘어 나온다 — 예:

```
■ 훑는 뿌리: /opt/hermes/archive
■ md 483개를 훑어 6건 · 읽기 실패 0건 — 계좌 1 · 사업자등록번호 1 · 이메일 2 · 휴대폰 2
```

**2026-09-03 까지는 `documents/projects` 하나만 훑으면서 「전체」라고 적고 있었다.**
그래서 **대화 아카이브 md 는 이 도구로 한 번도 안 훑렸다.** 넓힌 그날 재 보니
md 431개·2건 → **483개·7건**이 됐고, 늘어난 5건은 **전부 진짜 값**이었다(정규식
잡음 0건). 갈래는 셋이다 — **처음 보는 것 1건**(대화 아카이브에 사람이 슬랙에 직접
적은 미마스킹 휴대폰. 그 자리에서 가렸고 그래서 지금 재면 6건이다), 이미 「안 가린다」로
정해 둔 회사 계좌 1건이 색인 문서에 인용된 것(라벨 둘로 세어져 2건), 운영 노트·명부에
적힌 이메일 2건. 개인정보가 git 에 영구 기록되는 것은 문서 트리 밖에서도 똑같다.

**읽기 실패를 잔여 건수와 따로 찍는 이유** — 섞으면 "잔여 0건"이 "0건 확인함"인지
"못 읽어서 못 셌다"인지 갈리지 않는다. 「0건」과 「안 셌다」를 이렇게 구별한다.

> **이 훑기는 아무것도 안 고친다.** 읽기만 한다 — `--gate`·`decide.py` 와 달리
> 자료 저장소에 쓰지 않고, `.review-stamp.json` 도 안 남긴다.

### 6. 분류 · 시리즈 판정

**분류** — **판단이 필요 없다. 채널이 곧 사업장이다.** 슬랙 외의 경로가 없으므로(3단계)
모든 파일에 출처 채널이 있다. 추측하지 않는다.

**공개 승인 옮겨 적기** — 비공개 채널(`privateChannels`) 파일은 2단계 수집이
`스레드에 [공개] 태그가 달린 첨부 N건` 으로 알려준다. 그 목록에 있는 파일만
메타에 `**공개승인**` 을 적는다(위 「메타 블록 규칙」). 목록에 없으면 적지 않는다 —
사람이 기억으로 적으면 승인 없는 문서가 열린다. 매니페스트의 `public_tag` 가 같은 값이다.

> **이 목록은 이번에 새로 변환하는 파일만 다룬다.** 승인은 대개 문서가 아카이브에 들어간
> **뒤에** 나오는데, 그때는 수집이 그 파일을 이미 다룬 것으로 보고 태그를 버린다
> (`fetch_slack_files.py` 의 `classify()` 가 `known` 으로 거르면, 그 앞에서 읽어 둔
> `public_tag` 는 그 자리에서 버려진다). 그래서 **`doc-archive` 를 아무리 다시 돌려도 안 뜬다.**
> 그 경우는 **매일 09:00 위생 점검이 「팀이 `[공개]` 로 승인했는데 봇은 아직 막고 있는 자료」로
> DM 을 보낸다**(2026-08-07 부터). 받으면 **아래 「승인 반영」을 돌린다 — 다시 변환하지 않는다.**
> 재변환하면 같은 문서가 두 벌 쌓인다.
> (2026-08-07 발견: 워크스페이스의 `[공개]` 1건이 8/5 부터 이 상태로 묻혀 있었고,
> 그 사이 이 스킬을 두 번 돌렸지만 한 번도 뜨지 않았다.)

**시리즈 판정** — 파일명에서 날짜(`YYMMDD`, `YYYYMMDD`, `YYYY.MM.DD`, `26년 N차`)를 빼고
공백·특수문자를 압축한 이름이 정규화명이다.

- 기존 시리즈의 `pattern` 과 일치 → 그 시리즈 md 에 회차로 붙인다
- 같은 사업장에 같은 정규화명이 **3건 이상** → 새 시리즈 md 를 만든다
- 2건 이하 → 단발 md. **3건째가 오면 시리즈로 승격**하고 보고에 명시한다
  - **승격하면 합친 단발들의 `slack_files[*].doc` 을 새 시리즈 경로로 고친다.** 안 고치면
    그 키가 **없어진 md 를 가리킨 채 남고**, 나중에 `decide.py --undo` 가 그 문서를 찾다가
    「이름 조각이 걸리는 다른 문서」를 조용히 보류한다(아래 「한 문서 되돌리기」의 경고와
    같은 자리). 합치는 일은 코드가 아니라 사람·모델이 하므로 **이 걸음이 없으면 갱신할
    주체가 없다** — 2026-09-21 에 실제로 어느 채널의 4건이 그 상태였고, 그 때문에
    본부별-주간보고 0818 회차 재변환을 포기했다
- `_수정`·`_v2`·`_최종` 개정본은 같은 날짜 회차가 이미 있으면 **교체할지 사용자에게 묻는다**

**엑셀은 시리즈 md 를 만들지 않는다** (설계 2026-08-23). 정규화명이 같은 엑셀이
**2건만 되어도 가장 최근 1건만 변환**하고 나머지는 `.doc-state.json` 의 `superseded`
에 적는다. 개수 문턱을 두지 않는 이유는, 두면 2건일 때만 옛 판이 본문으로 남아
규칙이 개수에 따라 갈리기 때문이다.

`superseded` 는 `excluded`(사람이 판단해서 뺀 것)와 **다른 칸**이다 — 뺀 것이 아니라
최신이 대신한 것이고, 새 판이 오면 어제 것이 여기로 내려와야 한다. 한 칸에 섞으면
「판단해서 뺀 것」과 구별이 사라진다.

```json
"superseded": {
  "F0EXAMPLE03": {
    "channel": "비공개나",
    "name": "이슈사항_260807.xlsm",
    "kept": "이슈사항_260814.xlsm",
    "kept_archived": true,
    "at": "2026-08-26"
  }
}
```

적는 법: `decide.py <선택자> --superseded "<최신파일명>"`. 키가 **파일 ID** 인 것은
`excluded`·`deferred` 와 같다 — 세 칸이 다른 키를 쓰면 수집 필터가 갈린다.

`kept_archived` 는 그 최신 판이 실제로 아카이브에 들어갔는지를 **적는 순간의 값**으로
남긴다. 그 최신이 개인정보 때문에 `excluded` 이거나 크기 때문에 `deferred` 면 `false` 가
된다 — **「최신이 대신한다」가 항상 참은 아니다.** 실물 물림 3건 중 2건이
`kept_archived: false` 였다(최신도 옛 판도 아카이브에 없다). **화면(`--list`)의 경고는
이 저장값이 아니라 그 자리에서 `slack_files` 를 다시 재서 낸다** (2026-09-22 부터,
`decide.py` 의 `kept_in_archive`) — 사슬이 한 칸 늘면 저장값은 낡는데, 화면이 그것을
읽으면 없는 파일을 「있다」고 말하기 때문이다.

**추이는 회차 요약 표로 남긴다.** 최신 1건만 담으면 지난 값이 사라지므로, 그 자료에
회차 요약 표가 있는 md 가 이미 있으면 거기에 한 줄을 더한다(원본이 pdf 든 xlsx 든
같은 표를 쓴다). 값을 뽑는 자리는 자료마다 다르므로 사람이 연다.

### 7. md 쓰기

신규 문서는 Write, 기존 문서는 삽입 스크립트로. **기존 md 를 Write 로 통째 재생성하지 않는다**
(slack-sync 와 같은 규칙 — 손으로 다듬은 메타가 날아간다).

```bash
python .claude/skills/doc-archive/scripts/insert_entry.py \
    --file "$DATA/documents/projects/<사업장>/<문서>.md" \
    --date 2026-07-31 --source "260731_보고.pdf" \
    --content-file /tmp/block.md --summary "수금률 88.2%, 미수금 000억"
```

날짜를 보고 알맞은 자리에 넣고(월 섹션 생성 포함), 메타의 `기간`·`수록 회차` 를 다시 계산한다.
같은 날짜·같은 원본 파일 회차가 이미 있으면 종료코드 2로 건너뛴다.

> **블록 파일의 첫 줄이 회차 헤더여야 한다** — `**YYYY-MM-DD · 원본파일명**` 다음에 빈 줄,
> 그 아래가 본문이다. 스크립트는 블록을 **그대로 붙일 뿐 헤더를 만들어주지 않는다.**
> 빠뜨리면 본문이 어느 회차에도 안 붙어 검색에서 통째로 사라지는데, 파일은 멀쩡해 보이고
> 회차 수만 하나 모자란다 (2026-08-04 에 실제로 겪었다. 8단계 검사가 이제 이걸 잡는다).
>
> **2026-09-21 부터 스크립트가 첫 줄을 보고 막는다** (`ERROR` + 종료코드 1). 전에는
> 헤더가 없어도 **`OK 삽입`** 을 찍었고, 시리즈 md 면 기존 회차 수까지 멀쩡하게 붙어
> 화면에 아무 기미가 없었다 — 그래서 2026-09-20 재변환 파일럿에서 같은 일이 **다시**
> 났다. 헤더는 여전히 **만들어 주지 않는다**: 날짜·원본명은 곧 봇의 인용 출처라
> 사람이 정하는 자리다.
>
> `--summary` 는 표의 **한 칸**으로 들어간다. 회차 요약 표의 열이 3개보다 많으면
> (`잔금수금-업무보고.md` 는 4열) 값 사이에 `|` 를 직접 넣어 열을 맞춘다.

**본문 손질은 삽입 전에 블록 파일에서 한다 — 넣은 뒤 md 전체에 정규식을 돌리지 않는다.**
회차가 쌓인 md 는 대부분이 **남의 회차**다. 내 것 하나를 고치려고 파일 전체를 훑으면
이미 커밋된 회차까지 함께 바뀌는데, **에러도 경고도 없고 `verify_format.py` 도 통과한다** —
계약이 안 깨지기 때문이다. 2026-09-06 에 어느 정기보고 시리즈 md 에서 실제로 그랬다.
새 회차의 죽은 이미지 링크 1개를 걷어내려고 파일 전체에 `![image](...)` 지우기를 돌려
**이미 커밋돼 있던 47회차의 링크 44개를 함께 지웠다** (`git checkout --` 으로 되돌리고
블록만 손대 다시 넣었다).

- **편집 대상은 내가 만든 블록 파일이다.** 목적지 md 는 `insert_entry.py` 만 건드리게 둔다
- 그래도 목적지 md 전체를 손봐야 하면 **바꾼 개수가 내 블록 안의 개수와 같은지 대본다.**
  다르면 남의 회차를 건드린 것이다 — 위 사고에서 잡아 준 것이 「45 → 0」 이라는 숫자
  하나였고(내 블록에는 1개), 안 찍었으면 그대로 커밋됐다
- **한 문서에서 내린 판단을 다음 문서에 옮기기 전에 그 문서의 실물을 먼저 센다.**
  위 사고의 앞 문서는 이미지 링크가 0개였고 그래서 걷어내는 것이 맞았다. 다음 문서
  메타의 「그래프는 이미지(emf)라 본문에 없다」를 같은 뜻으로 읽었는데 다른 것을
  말하고 있었다 — 그 파일에는 링크가 44개 있었다
- 커밋 전 `git diff --stat` 으로 **삭제 줄이 내가 넣은 분량과 맞는지** 본다

**검증(생략 금지)** — 손으로 눈검사하지 말고 반드시 이걸 돌린다:

```bash
python .claude/skills/doc-archive/scripts/verify_format.py --all
```

제목 개수·`## ` 헤딩·회차 정렬·월 소속·메타 `열람`·수록 회차 일치, 그리고 **월 섹션 안의 본문이
전부 회차 헤더 아래에 있는지**를 한 번에 본다.
**하나라도 ✗ 면 커밋하지 않는다.** 계약이 깨져도 Hermes 는 에러를 내지 않고
검색만 조용히 0건이 되므로, **문서가 검색되게 만드는** 방어선은 여기 하나뿐이다.
**그리고 여기서 놓치면 남의 일이 멈춘다** — VM 의 대화 자동 반영이 커밋 직전 관문에서
이 스크립트를 그대로 돌리고, 실패하면 그날 대화까지 통째로 롤백한다
(위 「내 산출물이 남의 일을 멈춘다」).

**통과했다고 회차가 들어갔다는 뜻은 아니다.** 삽입 스크립트가 찍는
`회차 N건, 시작 ~ 끝` 줄이 **기대한 수와 맞는지 그 자리에서 확인한다** — 8단계 검사를 붙이기 전에는
헤더 없는 본문이 통과했고, 이 줄의 숫자가 하나 모자란 것이 유일한 신호였다.

### 7.5 건별 점검 — 커밋 전 관문 (생략 금지)

```bash
python .claude/skills/doc-archive/scripts/review_batch.py
```

**여기가 「전부 반영」을 「사안별 반영」으로 가르는 자리다.** 지금까지는 변환이 끝나면
곧바로 커밋 승인을 물었고, 사람이 볼 수 있는 것은 「변환 12건」 같은 합계뿐이었다.
그런데 이 파이프라인이 **조용히 틀리는 자리는 전부 건별**이다 — 한 건의 열람 판정이
어긋나고, 한 건이 이미지만 있고, 한 건의 검토의견이 통째로 빠진다. 에러는 안 난다.

스크립트는 **git 작업 트리**에서 이번에 생기거나 고쳐진 md 를 찾아 회차마다 한 줄씩 낸다.
별도 장부가 없어도 되고, 「승인 반영」으로 메타 두 줄만 고친 것도 같은 표에 실린다.

```
[변환 후 점검표 — 커밋 전]

#  사업장/문서                    열람      본문     주석     마스킹      시리즈    엑셀   뭉침   계약검사
1  사업장나/잔금수금-업무보고 (…)  공개      3,421자  —        ✓           회차 8건  —      ✓      ✓
2  비공개가/260808-이사회자료 (…)    공개 ⚠    0자 ⚠    —        ✓           단발      —      ✓      ✗ 1건
3  사업장가/합의서-v2 (…)          공개(승인) 8,533자  1,026자 ⚠ ⚠ 주민번호  교체? ⚠   —      2칸 ⚠  ✓
4  사업장버/자금현황 (…)          공개      2,890자  —        ✓           —         시트 메타 3 ≠ 본문 4 ⚠  ✓  ✓
```

여덟 축은 전부 **이 문서 다른 절에 흩어져 사람 기억에 의존하던 것**이다 — 열람(메타 블록
규칙 + 2단계 비공개 경고), 본문 글자 수(4단계), 워드 주석(4단계), 마스킹(5단계 규칙 4),
시리즈(6단계), **엑셀**(시트 개수 불일치·상한 초과로 뺀 시트·숨긴 시트/행·서식 미해석·
본문의 엑셀 오류 문자열 — `xlsx_to_blocks.py` 의 `meta.json` 과 메타 `시트`, 「엑셀 변환」
절 참고. `시트` 메타가 없는 문서는 `—`), **뭉침**(아래), 파싱 계약(7단계,
`verify_format.py` 의 `check()` 를 그대로 부른다).

**「뭉침」 축** (2026-09-21). 표 칸에 숫자 둘이 붙어 버린 것을 찾는다 — `13,473` 과
`1,076` 이 `13,4731,076` 이 되는 식이다. 잣대는 `scripts/detect_merged_numbers.py` 한
벌이고 점검표가 그것을 임포트한다(정규식을 베끼면 조용히 갈린다).

- **옛 문서 청소가 아니라 지금도 나는 문제다.** 같은 원본 25문서를 옛 판과 kordoc
  4.14.0 으로 돌려 짝지어 재니 93칸 → 145칸으로 **늘었다**(2026-09-21 실측).
  **다시 변환해도 안 고쳐진다** — 그래서 이 자리에서 사람이 가른다
- **봇은 본문을 무가공으로 받는다** — `read_document` 가 md 글자를 그대로 도구 결과로
  돌려준다. 뭉친 칸은 에러를 안 내고 그대로 **하나의 금액으로 인용된다**
- **이번에 들어온 줄만 본다.** 안 그러면 시리즈 md 에 새 회차를 넣을 때마다 그 파일의
  옛 회차에 남은 유산 뭉침이 되풀이 ⚠ 가 된다 — 그 자리에서 못 고치는 ⚠ 가 쌓이면
  관문이 꺼진다
- **막지 않는다.** 원본이 아직 `~/.doc-cache` 에 있을 때(7.5 는 10단계 전이다) 대조해
  가르고, 가를 수 없으면 **값을 고치지 말고** 메타 `수록 범위` 에 경고를 단다
  (강릉 Tr.A 소계 전례 — WHK 결정 2026-09-21)
- **그래프 눈금이 한 칸에 몰린 것은 `N칸(눈금)` 으로 갈라 적고 ⚠ 를 안 붙인다** —
  뭉친 것은 사실이지만 표의 금액이 아니라 사람이 할 일이 없다
- **없어서 실제로 난 사고 둘** — 2026-09-17 에 4.14.0 으로 변환된 경영실적 보고가
  `2868,373`·`7901,076` 을 품은 채 아무 검사 없이 들어갔다. 어느 사업장에서는 사람이
  뭉친 `1,000900` 을 1,000억으로 읽어 머리말 `주요 항목` 에 옮겨 적었고 **봇이 그 값을
  인용했다**(아이엠뱅크 몫 900억이 통째로 빠진 값이다)

**표 아래에 「봇 색인 문장」 절이 붙는다** (2026-09-04). 메타 `주요 항목` 과 회차 요약
표의 칸은 **모델이 쓴 문장**인데 어느 축에도 안 실려서, 사람이 한 번도 안 읽은
문장이 그대로 커밋됐다 — `주요 항목` 은 일일 요약의 문서 소개(gist)에 그대로 쓰이고
(`documents.js` 의 `buildDocumentsBrief` 가 싣는 봇 색인 줄에는 2026-09-10 부터 안 실린다),
회차 요약 표는 추이 답변의 근거다. 절은 **이번에 새로
생기거나 바뀐 문장만 전문으로** 보인다(새 문서면 전부 새 문장이니 전부) — 전부 다
보이면 표가 길어져 관문이 성가셔지고, 성가신 관문은 꺼진다. 실측(최근 15커밋)으로 바뀐
줄만이면 회차당 대개 0~21줄이다(시리즈 재편 회차 하나만 54줄 — 그때는 전부 새 문장이라
다 보이는 것이 맞다). **이 절은 12줄에서 안 잘린다** — 잘린 문장은 또 아무도 안 읽은 채
커밋되기 때문이다. 회차 요약 절만 고쳐진 md 는 본문 칸에 `요약만` 으로 뜬다(⚠ 아님 —
그 전문이 이 절에 있다). 강제 장치는 따로 안 만들었다 — 도장이 md 전체 해시라, 이 절이
화면에 나온 뒤 문장을 또 고치면 기존 관문이 그대로 막는다.

**「서식 해석 못 함」에는 사유가 함께 나온다** (2026-08-23 부터):

```
서식 해석 못 함 392셀 (openpyxl 이 못 푼 내장 서식 390 · 반올림이 렌더러마다 갈림 2)
```

개수만 적혀 있던 동안, 한 파일이 **14.69%** 였는데 그것이 전부 한 원인이었는데도 표에서는
알 수 없었다. 사유는 `xlsx_to_blocks.py` 가 **판정하는 그 순간에** `meta.json` 의
`unformatted_reasons` 로 적어 보낸다 — 점검표는 그것을 읽어 보이기만 하고 셀에서 다시
알아내지 않는다(그러면 판정이 두 벌이 되어 조용히 갈린다). 많은 사유부터 셋까지 펼치고
나머지는 `그 외 N갈래` 로 접는다. **사유 키가 없는 옛 변환분은 `사유 미기록 — 옛 변환분`**
이라고 적는다 — 「사유가 없다」와 「안 남긴 변환분이다」는 다른 사실이다.

자주 보게 되는 사유:

| 사유 | 무엇을 봐야 하나 |
|---|---|
| `openpyxl 이 못 푼 내장 서식` | 한국·일본어 로케일 전용 내장 날짜 서식(27~36·50~58번). 날짜가 `45730` 처럼 일련번호로 나갔는지 본다 |
| `반올림이 렌더러마다 갈림` | 조 단위를 소수 둘째 자리까지 적는 표. 고장이 아니라 「못 정한다」는 뜻이다 (`_QUANT_SIG_LIMIT` 주석) |
| `General — 지수 표기 구간` | 아주 크거나 작은 수. 엑셀과 LibreOffice 가 다른 글자를 내 확정할 수 없다 |
| `구역이 넷을 넘음` · `서식에 조건·숫자 치환` | 서식이 `[<0]` 같은 조건을 쓴다. 통째로 해석하지 않는다 |

**10단계 전에 돌린다** — 주석 대조에 `~/.doc-cache` 의 원본이 필요하다.
그리고 8·9단계 전이라 **되돌리기가 md 한 곳으로 끝난다**(색인도 상태 파일도 아직 안 썼다).

표를 사용자에게 보이고 **번호로 답을 받는다.** 답은 넷 중 하나다:

| 답 | 하는 일 |
|---|---|
| 그대로 반영 | 8단계로 |
| 고쳐서 반영 | 지적된 것을 고치고 `review_batch.py` 를 다시 돌려 ⚠ 가 사라진 것을 확인 |
| 빼 (이번에도 앞으로도) | `decide.py --undo … --skip --reason "…" --manifest <수집 매니페스트>` |
| 나중에 | `decide.py --undo … --later 14 --reason "…" --manifest <수집 매니페스트>` |

- **`[초안 — Clio 생성 · 검수 전]` 이 보이면 무조건 「빼기」. 파일 이름의
  `[초안-검수전]` 도 같다** — Clio(문서 초안 봇)가 만든 검수 전 초안이다. 사람이
  완성하며 이 표식을 지우기 전에는 아카이브에 넣지 않는다. 넣으면 Hermes 가 검수
  안 된 초안을 근거로 답한다.
  - **본문 첫 줄만 보면 안 된다** (2026-09-07 부터). Clio 의 「양식 칸 채우기」는
    원본 양식에 내용을 되돌려 넣는 방식이라 표식을 맨 앞에 못 붙인다 — 문서에 따라
    **제목 아래 둘째 문단**으로 들어가고, 넣을 자리가 없으면 **본문에는 아예 없고
    파일 이름만** `[초안-검수전] 제목.hwpx` 가 된다. 첫 줄만 보는 검사는 그 둘을
    통째로 놓친다.
  - 그래서 보는 자리가 둘이다 — **변환 결과 본문 어디든** 그 문자열이 있나,
    그리고 **원본 첨부 파일 이름**이 `[초안-검수전]` 로 시작하나.

```bash
python .claude/skills/doc-archive/scripts/decide.py --undo \
    --file "$DATA/documents/projects/<사업장>/<문서>.md" \
    --date 2026-08-08 --source "260808_이사회 안건.pdf" \
    --later 14 --reason "확정본 나오면 그때 넣는다" \
    --manifest /tmp/doc-manifest.json
```

**`--manifest` 를 반드시 함께 준다** — 2단계 수집이 만든 그 파일이다. 여기는 9단계
(상태 저장) 전이라 이 첨부는 `.doc-state.json` 어디에도 아직 없고, 매니페스트가
없으면 `--later`·`--skip` 이 **적을 대상을 못 찾는다.** 회차는 물려지지만 판정이
안 남아, 다음 실행이 이 첨부를 새것으로 보고 그대로 다시 넣는다(그때 화면에
「보류 기록은 못 남겼습니다」가 뜬다 — 뜨면 매니페스트를 주고 다시 부른다).

물리기와 결정을 한 줄에 줄 수 있다. **대상은 물리기 전에 확정한다** — `--undo` 가
상태 기록을 먼저 지우면 그 뒤의 선택자가 그 파일을 못 찾고 **이름 조각이 걸리는 다른
문서를 골라 조용히 보류한다**(만들면서 실제로 그랬다. 화면에는 성공으로 보였다).
`초안.pdf` 처럼 사업장마다 있는 흔한 이름은 `--file` 로 준 md 를 보고 좁힌다.
그래도 여럿이면 목록을 보이고 **아무것도 안 하고 멈춘다.**

**낡은 `doc` 포인터가 이 자리를 밟는다.** `.doc-state.json` 의 `slack_files[*].doc` 이
**없어진 md** 를 가리키고 있으면(단발을 시리즈로 합치면서 안 고친 것 — 6단계 참고)
`--undo` 가 그 문서를 못 찾아 같은 길로 간다. 물리기 전에 그 키의 `doc` 이 실재하는
md 인지 한 번 보고, 아니면 **먼저 고친다.**

> **깨끗한 건은 ✓ 한 줄이다.** 전건 심사가 아니라 ⚠ 만 보면 되므로, 볼 것이 없으면
> 「전부」 한마디로 지나간다. 16:00 마감이 급하다고 이 관문을 건너뛰지 말 것 —
> 늦어도 요약은 정상적으로 나가고 하단에 `미반영 N건` 이 붙을 뿐이다(0단계).
>
> **이 표를 승인받은 것은 커밋 승인이 아니다.** 커밋·push 는 11단계에서 **다음 턴에** 따로 받는다.

**건너뛰면 커밋이 막힌다** (2026-08-11 부터). 이 관문은 사람이 손으로 부르는 것뿐이라
**빼먹어도 아무 흔적이 없었다** — 나중에 확인할 방법이 커밋 메시지에 적혔나뿐이었다.
그래서 표를 낼 때 그 md 의 해시를 `documents/.review-stamp.json` 에 적고,
`.githooks/pre-commit` 이 커밋에 담긴 문서 md 중 기록에 없는 것을 찾아 **커밋을 멈춘다**.

```
커밋을 멈춥니다 — 7.5 건별 점검을 안 거친 문서 md 가 있습니다.
  · documents/projects/사업장더/20260811-…통보.md  (점검한 뒤에 또 고쳐졌습니다)
```

- **점검 뒤에 고치면 해시가 달라져 다시 막힌다** — 「고쳐서 반영」도 다시 돌려야 통과한다.
  그 확인을 사람 기억에 맡기지 않으려는 것이다
- **보는 것은 스테이징이지 작업 트리가 아니다.** 변환하다 만 md 를 옆에 둔 채 딴 일을
  커밋하는 것까지 막으면 관문이 곧 성가신 것이 되어 꺼진다
- **기록은 저장소에 안 들어간다**(`.gitignore`). 「이 PC 에서 사람이 표를 봤다」는 사실이지
  문서가 아니라서, 다른 PC·VM 의 기록이 섞이면 그 뜻이 사라진다
- **훅은 코드 저장소 안에 있고**(`.githooks/pre-commit`, 2026-08-12 부터) **켜는 것은 한
  줄이다** — `git config core.hooksPath <코드 저장소>/.githooks`. **상대경로 `.githooks` 를
  쓰지 않는다**: 자료 저장소에는 그 폴더가 없어서 거기서 그렇게 걸면 아무 훅도 안 켜지고
  이미 걸려 있던 것까지 꺼진다. 걸 값은 `archive-run` 상황판의 `켜기:` 줄이 그대로 낸다.
  **거는 것은 사람이다** — 기계마다 절대경로라 저장소에 안 실리고 새 PC 에서는 다시 건다.
  **VM 에는 걸지 않으므로 대화 자동 반영 커밋은 이 검사와 무관하게 돈다** — 의도한 것이다.
  그전에는 `.git/hooks/` 에만 있어 클론하면 사라졌는데, 그런데도 문서 네 곳이 「막힌다」고
  적고 있었다 — 받는 사람에게 거짓인 문장이었다
- **관문 스크립트가 없는 저장소에서는 훅이 아무것도 안 하고 통과한다.** 스킬을 일부만
  가져간 곳에서 남의 커밋을 전부 막지 않으려는 것이다. **임포트 사슬 끝까지** 확인한다 —
  이 관문은 `fetch_slack_files.py` 와 `verify_format.py` 를 임포트한다. 하나라도 없으면
  ImportError 로 죽고, 그 종료코드 1 은 「관문 위반」과 구별되지 않아 **그 저장소의 모든
  커밋이 트레이스백과 함께 막힌다** (2026-08-12 에 `verify_format.py` 가 목록에서 빠져
  있던 것을 고쳤다. 별개 저장소에서 재현해 확인했다)
- **관문이 대는 것은 스테이징이지 작업 트리가 아니다** (2026-08-12). 점검표를 낼 때
  찍는 도장은 작업 트리에서 나오지만, 커밋을 막을지는 **인덱스에 담긴 내용**으로 정한다.
  둘을 같게 두면 `git add -p` 로 조각만 담았을 때 표에서 못 본 조합이 통과한다 —
  작업 트리는 그대로라 해시가 맞고, 뚫려도 화면에 아무 표시가 없다.
  줄끝(CRLF↔LF)만 다른 것은 같은 내용으로 본다
- **관문이 git 을 못 읽으면 「볼 것 없음」이 아니라 멈춤이다** (2026-08-12). 스킬을 다른
  깊이에 깔면 `ROOT` 가 엉뚱한 곳을 가리키는데, 전에는 그때 조용히 통과했다 — 훅은 걸려
  있는데 아무것도 안 지키는 상태였다
- 검사만 따로 돌려 보려면 `review_batch.py --gate` (표 없이 종료코드만)

### 8. index.md 갱신

사업장별 목록과 「변환하지 못한 것」 절, 하단 갱신일을 다시 쓴다.
「변환하지 못한 것」은 **반드시 남긴다** — 이게 없으면 봇이 엑셀 안의 숫자를
"자료가 없습니다"로 오답한다.

**적을 자리가 둘이다.** 「변환하지 못한 것」은 봇 색인에 통째로 실리고,
그 아래 「제외 경위 (봇 색인 밖)」은 안 실린다. 가르는 기준은 하나다 —
**사람이 그 자료를 물었을 때 봇이 틀린 답을 하나.**

| 적을 것 | 어느 절 |
|---|---|
| 있는데 아직 못 읽는 것 (미변환·범위 밖) | 변환하지 못한 것 |
| 실었지만 믿음이 제한되는 것 (OCR·뒤섞인 문장·발송 전) | 변환하지 못한 것 |
| 개인정보 때문에 뺀 것 — 물으면 「원본을 열어야 한다」고 답해야 한다 | 변환하지 못한 것 |
| 이전 판·중복본을 왜 안 넣었나 (최종본이 아카이브에 있다) | 제외 경위 |
| 우리 운영 규칙 (두 채널에 같은 자료면 한 벌만 등) | 제외 경위 |

**위 절에 적는 것은 공짜가 아니다** — 접히지 않고 통째로 실려 색인의 바닥을
영구히 먹는다. 해소된 예외의 줄은 지운다.

> ⚠️ **봇이 프롬프트에 싣는 색인은 `index.md` 가 아니다.** `documents.js` 의
> `buildDocumentsBrief` 가 **각 md 의 메타**(제목·종류·기간·회차·주요 항목)에서 한 줄씩
> 만든다. `주요 항목` 은 봇 색인 줄에는 실리지 않고(2026-09-10 부터) 일일 요약의
> 문서 소개(gist)에 쓰인다. `index.md` 에서 가져가는 것은 「변환하지 못한 것」 절 하나뿐이다.
> 그러니 `index.md` 에서 문서를 접어도 봇 색인은 줄지 않는다. 색인 크기에 영향을 주는
> 손잡이는 **시리즈로 묶기** 하나다 — `주요 항목` 은 색인 줄 자체에 없어(2026-09-10 부터)
> 더는 손잡이가 아니다.

> ⚠️ **다만 그 손잡이도 「바닥」에는 반대로 듣는다.**
> **시리즈로 묶기** — 이미 `그 외 N건` 으로 접혀 있던 단발들을 묶으면 **가장 나중에
> 접히는 줄이 새로 생겨 바닥이 오른다**(아래 표의 순위 0 — 2026-09-10 시리즈 접기 확장
> 뒤로는 시리즈도 결국 접히지만, 가장 늦게 · 오래된 것부터일 뿐이다). 줄어드는 것은
> 그것들이 아직 펼쳐져 있을 때뿐이다. 접혀 있는 것을 묶어 색인을 줄이려 하면 역효과다.
> **「색인 여유」라는 것은 없다** — 상한 안에서 최대한 펼치는 구조이기 때문이다.

색인 크기를 확인한다:

```bash
npm run check                                 # [4/6] 문서 색인 공통분 N자 (상한 N자) · 추가분 최대 N자
                                               #       문서 색인 바닥 N자 · 접힌 시리즈 N건 — 조각들
```

**볼 것은 「공통분」이 아니라 「접힌 시리즈」다.** 공통분은 상한 안에서 최대한 펼치는
구조라 무엇을 해도 늘 상한 근처여서 정보가 없다. 2026-09-10 부터 시리즈도 가장 마지막
순서로·오래된 것부터 접히므로, 바닥이 상한에 닿는 일은 구조적으로 없다 — 경보는 바닥이
아니라 **「접힌 시리즈 N건」** 줄이다.

```
⚠ 접힌 시리즈 2건 — 시험/[산정내역] 시험 엑셀 · 시험/주간보고
  (색인 공간이 모자라기 시작했습니다. 바닥 6,120자 — 예외표 … · 접힘줄 … · 시리즈 … · 사업장 … · 머리말 …)
```

이 줄이 뜨면 색인 공간이 실제로 모자라기 시작했다는 뜻이다 — 접혀도 `search`에는
그대로 걸리지만, 색인에 이름이 없으면 봇이 그 문서의 존재를 짐작할 힌트가 준다.
0건이면 `ok` 로 「문서 색인 바닥 N자 · 접힌 시리즈 0건」을 정보로만 찍는다.

**넘으면 코드가 알아서 접는다.** `buildDocumentsBrief` 가 예산을 넘는 동안
아래 순서로 뒤에서부터 접어 사업장별 `- 그 외 N건 (종류·종류·종류 등)` 한 줄로 바꾼다.

| 순위 | 대상 | 접히나 |
|---|---|---|
| 0 | 시리즈(회차 2건 이상) | **가장 늦게, 오래된 것부터 접힘**(2026-09-10 부터 — 그 전엔 절대 안 접혔다) |
| 1 | 계약서·약정서·정관·협약 | 시리즈 다음으로 늦게 접힘 |
| 2 | 최근 `docBriefRecentMonths`(기본 3)개월 문서 | |
| 3 | 그 이전 단발 문서 | 가장 먼저 접힘 |

기준값은 `config.json` 의 `limits.docBriefMaxChars`(기본 6000)·`docBriefRecentMonths`.

**색인은 두 덩이로 실리고 예산도 따로다** (2026-08-11 부터, 커밋 `8468500`). 공개 문서는
`docBriefMaxChars`(6000), 비공개 채널 문서는 `docBriefPrivateMaxChars`(1500)를 쓴다. 한 예산을
나눠 쓰던 때는 비공개 채널 멤버가 **공개 문서까지 더 접힌 색인**을 봤고, 그러면 색인의 공개
부분이 사람마다 달라져 프롬프트 캐시가 안 걸렸다. 위 표를 볼 때 **줄일 대상은 공개 몫**이다 —
`npm run check` 가 찍는 「공통분」이 그것이고, 상한을 넘는지 보는 것도 그 값이다.

**접힌 문서는 검색에서 빠지지 않는다.** `searchDocuments`·`readDocument` 는
`listDocuments()` 로 파일을 직접 훑고 거르는 조건은 `private` 하나뿐이다.
색인 머리말에도 "목록에 없어도 없다고 답하지 말고 `search` 를 먼저 쓰라"고
적혀 있다 — 이 문장이 없으면 봇이 접힌 문서를 "자료가 없습니다"로 오답한다.

### 9. 상태 저장

자료 저장소의 `documents/.doc-state.json` 을 **실행 끝에 한 번만** 쓴다.
기존 파일의 구조를 그대로 따르고 항목만 더한다 — 일곱 갈래다:

- `slack_files` — 키는 **슬랙 파일 ID**. 값: `channel · name · ts · doc · date · converted_at · ocr`
- `local_files` — 키는 **sha256**. 값: `path · project · doc · date · converted_at · ocr`
- `series` — 키는 문서 경로. 값: `pattern · count`
- `skipped` — 키는 위와 같음. 값: `path · reason`
- `excluded` — **영구 제외.** 값: `channel · name · reason · decided`
- `deferred` — **만기가 붙은 보류.** 값: `channel · name · reason · until · decided`
- `superseded` — **최신 판이 대신한 옛 판.** 값: `channel · name · kept · kept_archived · at` (아래 4단계 「엑셀」)

뒤 셋은 손으로 적지 않는다 — `decide.py --skip`·`--later`·`--superseded` 가 적는다.

**`excluded` 는 `documents/excluded.md` 에 사람이 읽는 표로도 남는다** (2026-08-27 부터).
`decide.py` 가 상태 파일을 쓸 때 **같은 자리에서 함께** 다시 그린다 — 따로 부르게 두면
「상태 파일에는 적혔는데 목록에는 없는」 제외가 생기고, 그 어긋남은 에러가 아니라 낡은
문서로만 드러난다. 상태 파일을 손으로 고쳤으면 `decide.py --render` 로 맞춘다.
**갈래(개인정보·중복·이전 판…)로 묶지 않고 채널별로 묶는다** — 갈래는 상태 파일에 없어
사람이 붙여야 하고, 그러면 `--skip` 으로 새로 들어온 건이 분류 없이 남아 조용히 낡는다.
**봇은 이 파일을 안 읽는다**(`documents.js` 는 `projects/` 아래만 훑는다) — 그래서 색인
바닥이 안 오르고, 뒤집어 말하면 봇이 「자료가 없다」고 오답하면 곤란한 것은 `index.md` 의
「변환하지 못한 것」에 **따로** 적어야 한다.
**`deferred` 는 만기가 지나면 필터에서 저절로 빠져 미변환 후보로 돌아온다.** 기록은
남긴다. 만기를 필수로 둔 이유는 다시 가져오는 장치가 없는 보류가 곧 삭제와 같기 때문이다
(위키 `[[적어둔-일은-돌아오지-않는다]]`). 이 판정을 보는 곳이 넷이라 한 군데만 고치면
숫자가 갈린다 — `fetch_slack_files.active_deferred` 가 원본이고,
`apply_approvals.py` 와 Hermes `archive-health.js` 의 `activeDeferred` 가 같은 규칙이다.

키를 파일 ID·sha256 으로 두는 이유: 파일을 옮기거나 이름만 바꿔도 다시 변환하지 않는다.

**`excluded`·`deferred` 를 거를 때는 파일 ID 와 `name_key`(채널+확장자 뺀 이름)를 둘 다
본다.** 같은 자료를 hwpx 와 pdf 로 함께 올리거나 다시 올리면 파일 ID 가 새로 생기는데,
판정은 그 **자료**에 대해 내린 것이라 따라가야 한다. ID 만 보면 위생 점검은 「0건」인데
수집은 후보로 올리고, `apply_approvals.py --apply` 는 보류해 둔 문서를 실제로 공개로 연다.

**`excluded` 는 2026-08-12 까지 ID 로만 봤다.** 영구 제외한 자료를 다시 올리면 세 숫자가
갈렸다 — 일일 요약 하단은 이름으로 봐서 「미반영 0건」, 09:00 점검·상황판은 새 ID 라
「미변환 1건」, 수집은 후보로 다시 내려받아 **제외 결정이 무효화**됐다. 지금은 셋 다
ID+이름이다. **한쪽만 바꾸면 그 순간 갈리므로 바꾸려면 세 곳을 함께** —
`fetch_slack_files.py` 의 `excluded_names`, `archive-health.js` 의 `excludedNames`
(미변환 후보·승인 후보 두 자리), `unconvertedAmong`.
갈렸는지는 코드 저장소의 `scripts/check-shared-rules.js` 가 본다.

### 10. 원본 정리 — 변환 끝난 것은 지운다

```bash
python .claude/skills/doc-archive/scripts/prune_cache.py --apply    # 9단계 뒤에 바로
python .claude/skills/doc-archive/scripts/prune_cache.py            # 목록만 보고 싶을 때
```

`~/.doc-cache/` 는 변환하려고 잠깐 받아두는 자리지 보관처가 아니다. 원본의 보관처는 슬랙이다.
안 지우면 계속 쌓인다 — 2026-08-04 에 처음 비웠을 때 307건 282MB 였다.

> **이 단계를 빠뜨려도 다음 수집이 스스로 지운다** (2026-08-23 부터, WHK 결정).
> 2단계 `fetch_slack_files.py` 가 **받기 전에** 같은 판정으로 먼저 턴다
> (`autoprune`, `--dry-run` 에서는 안 지운다). 여기 넣은 이유는 **이 단계가 사람 손이라
> 건너뛰어도 아무도 안 알려주기 때문**이다 — 09:00 위생 점검은 VM 에서 도는데 캐시는
> 이 PC 에 있어 볼 수가 없고, 작업 스케줄러에도 정리를 부르는 작업이 없다. 수집은
> 이 스킬을 돌릴 때마다 반드시 지나가는 자리라 빠뜨릴 수가 없다.
>
> **그래도 여기서 돌리는 편이 낫다** — 자동 정리는 *다음* 실행 때 걷으므로, 안 돌리면
> 이번 회차 원본이 그때까지 남는다. 그 사이에 7.5 점검표를 다시 볼 수 있다는 뜻이기도
> 하다(주석 대조에 원본이 필요하다).
>
> **엑셀 중간 산출물 `<파일ID>_<원본명>.xlsx.blocks/` 도 함께 지운다** — 원본 바로 옆에
> 있고 폴더 이름 맨 앞의 파일 ID 로 맞춘다. 대상은 `slack_files`(변환 완료) ·
> `excluded`(판단해서 뺀 것) · `superseded`(최신이 대신한 것) 세 칸이고, `deferred`
> (만기 보류)·`skipped`(변환 실패)는 원본과 마찬가지로 남긴다. 전에는 이름으로만
> 맞추는 어림이라 산출물이 영영 안 지워지고 「아직 변환 안 된 원본」으로 잘못
> 세어졌다 — 2026-08-23 실측 85건 중 76건이 이것이었다.

**지워도 다시 안 받아온다.** 2단계 수집이 "이미 다룬 것"을 판정하는 기준은 캐시에 파일이
있는지가 아니라 `.doc-state.json` 에 기록이 있는지다(`fetch_slack_files.py` 의 `load_filters()`
가 그 기록으로 `known` 집합을 만든다). 캐시 존재 확인(`plan_fetch()` 에 넘기는 `is_cached` —
`dest_of(r).exists()`)은 그 필터를 통과한 것, 즉 **아직 변환 안 된 것**에만 걸린다.

그래서 이 스크립트는 **상태 파일에 기록이 있는 것만** 지우고 미변환분은 남긴다
(9단계 뒤에 돌려야 이번 회차분이 기록에 들어가 있다). 미변환분까지 지우면 다음 회차가
그걸 다시 내려받아 헛돈다. 점(`.`)으로 시작하는 파일은 건드리지 않는다.

`남깁니다 — 아직 변환 안 된 원본 N건` 이 찍히면 **그 N건은 이번에 처리하지 못한 것**이다.
보고에 그대로 옮긴다.

### 11. 커밋 · push

**커밋 전에 원본이 섞여 들어갔는지 반드시 확인한다:**

```bash
git -C "$DATA" -c core.quotepath=false ls-files -- documents \
  | grep -v '\.md$' | grep -v 'doc-state.json'
```

> **`-C "$DATA"` 를 빠뜨리면 이 검사가 통째로 헛돈다.** 문서는 자료 저장소에 있는데
> 코드 저장소에서 치면 git 은 없는 경로라고 화내지 않고 **빈 출력에 종료코드 0** 을 낸다 —
> 아래 「아무것도 출력하지 않아야 한다」를 만족시키면서 **아무 파일도 안 본다.**

`core.quotepath=false` 를 빠뜨리면 안 된다. git 이 한글 경로를 `"\354\262\255..."` 로 감싸 출력해서
끝이 `.md"` 가 되고, `.md$` 가 안 걸려 **멀쩡한 md 가 전부 바이너리로 오탐**된다.
이 아카이브는 파일명이 거의 다 한글이다.

**이 명령이 아무것도 출력하지 않아야 한다.** 뭔가 나오면 커밋하지 말고 원인을 찾는다.
저장소에 한 번 들어간 바이너리는 히스토리에서 지우기 어렵다.

> **빈 출력이 "원본이 없다"는 뜻은 아니다.** 자료 저장소 `.gitignore` 의 `documents/**`
> 네 줄이 이미 그 아래를 `.md` 와 `.doc-state.json` 만 추적하게 막고 있어서,
> 이 검사는 **`git add -f` 로 강제 추가한 경우에만** 걸린다. 게다가 `git ls-files` 는
> 추적 파일만 보므로 **작업 트리에 굴러다니는 원본은 안 걸린다.** 그것까지 보려면
> `git -C "$DATA" status --porcelain --ignored -- documents` 를 따로 봐야 한다
> (원본이 있으면 `!! documents/xxx.pdf` 처럼 나온다. 2026-08-04 실측 확인 —
> 가짜 pdf 를 놓았을 때 이 명령은 잡았고 위의 `ls-files` 검사는 못 잡았다).
> **`!! …/.review-stamp.json` 한 줄은 정상이다** — 7.5 관문이 남기는 점검 기록이지 원본이 아니다.
> 이 검사가 조용한 이유를 gitignore 가 막은 것인지 정말 없는 것인지 구분할 것.

**`local_files` 가 비어 있는지도 확인한다.** 슬랙 외 출처는 넣지 않는다(3단계).

```bash
python -c "import sys,json;d=json.load(open(sys.argv[1],encoding='utf-8'));print(len(d.get('local_files',{})))" \
  "$DATA/documents/.doc-state.json"
```

`0` 이 아니면 슬랙 아닌 자료가 섞인 것이니 커밋하지 말고 어디서 왔는지 찾는다.

```bash
git -C "$DATA" add documents && git -C "$DATA" commit
```

**여기서 `pre-commit` 훅이 7.5 관문을 안 거친 md 를 찾아 커밋을 멈춘다.** 막히면
`--no-verify` 로 넘기지 말고 `review_batch.py` 를 돌려 표를 보인다 — 훅이 막는 것은
**사람이 아직 못 본 문서**다.

**커밋·push 는 둘 다 WHK 승인을 받고 한다.** Hermes 는 GCP VM 에서 돌고 저장소를 `git pull` 로만 받는다(15분 간격).
push 하지 않으면 로컬만 새것이고 봇은 계속 옛 자료로 답하는데, 그 사실이 어디에도 드러나지 않는다 —
그래서 변환을 마치면 **"커밋·push 해야 봇에 반영됩니다"를 반드시 말하고 기다린다.**
급하면 VM 에서 `sudo systemctl start hermes-archive-pull`.

**Hermes 코드나 config.json 을 함께 고쳤다면 `sudo systemctl restart hermes` 도 필요하다.**
md 만 바뀐 경우에는 재시작이 필요 없다.

## 승인 반영 — 나중에 달린 `[공개]` 를 메타에 옮긴다

**위 11단계 흐름과 별개로 혼자 돈다.** 첨부를 받지도 변환하지도 않는다. 고치는 것은
**이미 아카이브에 있는 문서의 메타 두 줄**뿐이다.

**언제 도나** — Hermes 위생 점검(매일 09:00)이 「팀이 `[공개]` 로 승인했는데 봇은 아직
막고 있는 자료」로 DM 을 보낸다. 그때, 또는 "승인 반영해줘" 라고 할 때.

```bash
python .claude/skills/doc-archive/scripts/apply_approvals.py            # 뭐가 열릴지만 본다
python .claude/skills/doc-archive/scripts/apply_approvals.py --apply    # 걸린 승인 전부
python .claude/skills/doc-archive/scripts/apply_approvals.py --only "<사업장>/<파일명>.pdf" --apply
python .claude/skills/doc-archive/scripts/apply_approvals.py --channel <채널> --apply
```

**건별로 고르되, 번호가 아니라 이름으로 고른다** (2026-08-10 수정). `--apply` 만 주면 걸린
승인을 전부 여는데, 그 순간 그 문서들이 **팀 전원의 답변 근거**가 된다. 하나만 열 날이
대부분이다.

**번호는 실행할 때마다 다시 매겨진다.** 이 목록은 슬랙에서 새로 만들어 다시 정렬하므로,
목록을 본 뒤 명령을 치는 사이에 승인이 하나 늘거나 반영되면 **같은 번호가 다른 문서를
가리킨다** — 그 문서가 비공개면 그 순간 팀 앞에 열린다. 그래서 목록이 항목마다
`--only "채널/파일명"` 을 함께 찍어 준다. 번호도 여전히 받지만 경고가 붙는다.

이름은 파일명 조각·`채널/파일명`·md 경로 어느 것으로도 된다. **조각이 둘 이상 걸리면
아무것도 안 열고 멈춘다** — 짧은 조각(`주간`·`보고`)이 보지도 않은 문서를 함께 여는 것은
번호 문제의 완화판이라 같이 막는다. 걸린 후보를 이름으로 찍어 주니 그중 하나를 그대로 준다.
`--only` 에 맞는 것이 없으면 조용히 넘기지 않고 그 토큰을 짚어 알린다 — 오타 하나로
열릴 줄 알았던 문서가 안 열리면, 팀은 승인했는데 봇은 계속 막는 상태가 그대로 이어진다.

고친 뒤에는 **7.5 관문을 그대로 쓴다** — `review_batch.py` 가 git 작업 트리를 보므로
메타 두 줄만 바뀐 것도 표에 「메타만」으로 실려 열람 판정이 다시 검사된다.

무엇을 하나:

```
> **열람**: 비공개                    →   > **열람**: 공개
> **비공개 사유**: …                       > **공개승인**: 슬랙 스레드 [공개] 댓글 · 2026-08-05 12:53 · WHK
```

승인 시각과 이름은 **그 `[공개]` 댓글**에서 가져온다 — 사람이 기억으로 적지 않는다.

지켜야 할 성질 셋:

- **여는 일만 한다. 닫지 않는다.** 슬랙에는 승인을 취소하는 태그가 없어서, 열린 문서를
  여기서 닫으면 근거 없이 닫는 것이 된다. 이미 열린 문서는 건너뛴다(그래서 몇 번 돌려도 같다)
- **비공개 채널 문서만 본다.** 공개 채널 문서에 `공개승인` 을 적으면 검사가 ✗ 를 낸다
- **커밋·push 는 사람 승인.** 스크립트는 md 만 고치고 멈춘다. push 하는 순간 그 문서가
  팀 전원의 답변 근거가 되므로, 올릴지 정하는 것은 사람의 자리다

**고친 뒤 `verify_format.py --all` 을 돌린다.** 메타를 건드렸으므로 7단계와 같은 이유다.

**메타 값 안에 `**열람**:` 같은 표기를 쓰지 말 것.** 파서가 그것을 키로 잡는다.
2026-08-07 에 「비공개 사유」 값 안에 설명하려고 적었다가 그럴 뻔했다 — 그 줄에 마침
가운뎃점이 없어 값이 안 끊겼고 비공개가 유지됐다. 가운뎃점 하나만 있었으면 비공개 채널
문서 10건의 `열람` 이 '공개' 로 덮였다. 지금은 `verify_format.py` 가 잡는다
(「열람·공개승인 은 자기 줄에 혼자」).

## 한 문서 되돌리기

```bash
python .claude/skills/doc-archive/scripts/decide.py --undo \
    --file "$DATA/documents/projects/<사업장>/<문서>.md" \
    --date 2026-08-08 --source "260808_원본.pdf"
python .claude/skills/doc-archive/scripts/verify_format.py --all
```

회차 블록과 요약 표 행을 지우고, 빈 월 섹션을 걷어내고, 메타의 기간·수록 회차를 다시
계산한다. 회차가 하나도 안 남으면 md 를 지우고 `series` 기록도 정리한다. `.doc-state.json`
에 그 키가 있으면 함께 지운다 — **7.5 관문에서 부르면 아직 없는 것이 정상**이다(9단계 전).

`index.md` 는 손대지 않는다 — 8단계에서 통째로 다시 쓰므로 그때 반영된다. 이미 커밋한
문서를 되돌린 것이라면 8단계를 한 번 돌려 색인을 맞춘다. **커밋·push 는 승인 뒤.**

되돌리기를 스크립트로 만든 이유: 손으로 네 곳을 고쳐야 하면 「빼」라는 결정이 실제로는
집행되지 않고 「일단 두자」로 흐른다. 7.5 관문이 성립하려면 무르는 값이 싸야 한다.

문서 아카이브 전체는 파생물이다. 통째로 지우고 다시 만들어도 원본은 슬랙에 그대로 있다.
`~/.doc-cache/` 는 10단계에서 비우므로 **손에 남는 사본이 아니다** — 되돌린 뒤 다시 변환하려면
`.doc-state.json` 에서 키를 지우고 2단계 수집을 다시 돌려 슬랙에서 받아야 한다.
