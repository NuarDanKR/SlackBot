# archive-run

**남은 일을 한 표로 보이고, 마감 순서대로 기존 스킬에 넘긴다.**

절차는 여기 없다. `slack-sync`·`doc-archive`·`archive-inbox` 가 그대로 갖고 있고,
이 스킬이 아는 것은 넷뿐이다 — **무엇이 얼마나 남았나 · 어느 순서인가 · 마감이 언제인가 ·
지금 돌려도 되나.**

절차를 여기 옮겨 적지 않는 이유: `doc-archive` 만 해도 길고 매주 바뀐다. 복사하면 원본이
바뀔 때 **에러 없이 낡는다.**

## 어디서 돌리나 — 저장소가 둘이다

2026-08-31 부터 코드와 자료가 갈렸다. **명령은 코드 저장소 뿌리에서 친다** — 이 파일도
`board.py` 도 `node scripts/` 도 거기 있다. 대화·문서·`config.json` 은 **자료 저장소**에
있고, 그 뿌리는 `.env` 의 `HERMES_DATA_ROOT` 다.

```bash
cd ~/hermes/code                     # 코드 저장소 (VM 은 /opt/hermes/code)
DATA=$(node -e "import('./src/config.js').then(m=>console.log(m.DATA_ROOT))")
```

**자료를 다루는 git 은 `git -C "$DATA"` 로 친다.** 코드 저장소에서 그냥 `git` 을 치면
자료가 아니라 코드를 본다 — 없는 경로를 대도 git 은 화내지 않아서, 에러가 아니라
**빈 결과와 종료코드 0** 이 나온다. 둘이 같은 곳을 보는지는 `node scripts/check-roots.js`.

> **관문(`core.hooksPath`)의 값도 저장소마다 다르다.** 자료 저장소에는 `.githooks/` 가
> 없어서 거기에 상대경로를 걸면 이미 켜져 있던 것까지 꺼진다. 걸 값은 **코드 저장소의
> 절대경로**이고, 상황판이 그 값을 그대로 낸다(`board.py` 의 `켜기:` 줄).

## ⚠️ 먼저 알아야 할 것 셋

1. **화면의 값은 네 가지다 — 셌다(숫자) · 일부만 셌다(`최소 N건`) · 안 셈(`--fast`) ·
   조회 실패(`!`).** 뒤 셋은 **0건이 아니다.** 그중 하나라도 있는 동안은 「할 일 없음」이라고
   말할 수 없고, 화면도 그렇게 닫지 않는다.
   「일부만 셌다」는 슬랙 채널 몇 개를 못 읽었다는 뜻이다 — 봇이 초대 안 된 채널이거나
   속도 제한이다. **그 채널의 것은 숫자에 안 들어 있다**
2. **상황판을 본 것은 커밋 승인이 아니다.** 커밋·push 는 구간마다 다음 턴에 따로 받는다
3. **잠금은 자동으로 안 풀린다.** 오래된 잠금도 표시만 하고 푸는 것은 사람이다 —
   문서 수백 건 회차는 실제로 몇 시간이 걸린다

## 절차

### 0. 받아오기

```bash
git -C "$DATA" pull
```

**이걸 안 하면 어제 목록을 본다.** VM 이 07:00·17:00 에 목록과 아카이브를 push 한다.
**받는 곳은 자료 저장소다** — 목록도 아카이브도 거기 있다.

### 1. 상황판

```bash
python .claude/skills/archive-run/scripts/board.py
```

슬랙을 훑어 30초~3분쯤 걸린다(속도 제한을 만나면 더 걸린다). 급하면 `--fast` —
대신 **미변환 첨부·승인 미반영 두 줄이 「안 셈」으로 나온다.** 0건이 아니다.
`--json` 은 같은 값을 기계용으로 낸다(행마다 `count`·`error`·`skipped`·`partial`).

```
[아카이브 한 바퀴 · 2026-08-12 (수) 14:07]

준비   git 깨끗함 · origin 과 같음 · 잠금 없음

#  할 일              남은 것   마감                 넘길 곳
1  미변환 첨부        40건      17:00 (2시간 53분)   doc-archive
   · 최근 60일 범위 — 그보다 오래된 것은 여기 안 나온다
   · #사업장마 24 · #비공개사 14 · #사업장러 1 · #사업장다 1
-  새 채널 과거 대화  0건       07:00 (16시간 53분)  slack-sync 3.5
-  아침 보고          0건       07:00 (16시간 53분)  archive-inbox
-  수정·삭제          0건       —                    slack-sync 10
-  승인 미반영        0건       —                    doc-archive
-  동기화 밀림        0일       —                    —

다음은 1번입니다.
```

채널을 다 못 읽은 회차는 이렇게 나온다. **숫자가 있어도 그게 전부가 아니다:**

```
1  미변환 첨부        최소 12건  17:00 (2시간 53분)   doc-archive
   · 최근 60일 범위 — 그보다 오래된 것은 여기 안 나온다
   · #사업장나 12
   · 읽기 실패 #사업장마(not_in_channel) · #비공개가(ratelimited)
...
일부만 센 줄이 있습니다 (「최소」). 못 읽은 채널의 것은 이 숫자에 안 들어 있습니다.
```

`not_in_channel` 은 봇이 그 채널에 없다는 뜻이라 초대해야 하고(`npm run check` 가 알려준다),
`ratelimited` 는 잠시 뒤 다시 돌리면 된다. **0건이라도 번호가 붙는다** — 가서 봐야 한다.

**준비 줄이 깨끗하지 않으면 시작하지 않는다.** 작업 트리에 변경이 있으면 다른 창의
작업일 수 있고, 커밋이 그것까지 쓸어 담는다 (2026-08-04 에 승인 대기 중이던 204개가
그렇게 나갔다).

**「모른다」도 깨끗함이 아니다.** `git` 명령이 실패하면 「작업 트리 확인 못 함」·「origin 대조
못 함」이라고 적힌다 — 그 상태로 시작하면 무엇이 함께 커밋될지 모르는 채로 하는 것이다.
`--fast` 는 `git fetch` 를 건너뛰므로 늘 「origin 대조 안 함」이다.

**「커밋·push 관문 꺼져 있음」이 뜨면 훅이 안 돈다** (2026-08-12부터 봄). 훅은 **코드 저장소**
안(`.githooks/`)에 있지만 git 은 훅을 복제하지 않아서, `git config core.hooksPath` 를
걸어야 돈다. **걸 값은 상대경로가 아니라 코드 저장소의 절대경로이고**, 그 값은 상황판이
`켜기:` 줄에 그대로 낸다 — 자료 저장소에는 `.githooks/` 가 없어서 거기에 `.githooks` 라고
상대경로를 걸면 **아무 훅도 안 켜지고 이미 걸려 있던 것까지 덮어 꺼진다.**
**스위치는 그 한 줄뿐이고, 걸면 `.githooks/` 의 훅이 전부 돈다** —
`pre-commit` 관문 셋과 `pre-push` 관문 하나(2026-08-30 부터). 안 걸면 **7.5 점검·요약 승인을
안 거친 커밋과, 승인 목록에 없는 커밋이 섞인 push 가 그냥 통과**하는데, 그 사실을 알려주는
신호가 「막히지 않는 것」뿐이라 정상 동작과 구별되지 않았다.
켜져 있으면 아무 말도 안 한다 — 정상인 것을 매번 적으면 준비 줄이 길어져 안 읽힌다.
**여기서 걸어주지는 않는다.** git 설정을 바꾸는 것은 사람의 자리다.

**추적 안 되는 파일은 개수만 따로 적는다.** 받은편지함·프로젝트 폴더에 상시로 있어 전부
세면 준비 줄이 영영 안 깨끗해지기 때문이다. 다만 그것이 자료 저장소의 `documents/`·
`slack-export/` 아래면 **다른 창이 문서 변환 중일 수 있다**고 따로 알린다 — `doc-archive` 가
만드는 새 md 는 전부 추적 안 되는 파일이다.

### 2. 잠금

```bash
python .claude/skills/archive-run/scripts/board.py --lock doc-archive
```

`slack-sync` 와 `doc-archive` 를 **겹쳐 돌리면 안 된다** — 둘 다 상태 파일과 `index.md` 를
실행 끝에 통째로 쓰므로, 겹치면 나중에 쓰는 쪽이 앞 세션의 추가분을 모르는 채 덮는다.
이미 잠겨 있으면 종료코드 2 로 멈춘다.

**이 잠금을 보는 것은 `archive-run` 뿐이다.** 스킬을 직접 부르면 아무것도 안 막고, VM 의
07:00·17:00 자동 반영도 이 잠금과 무관하게 돈다. 즉 잠금은 **이 화면을 거쳐 들어오는
사람끼리** 겹치지 않게 하는 표시이지, 저장소를 잠그는 것이 아니다.

### 3. 한 구간씩 넘긴다

표의 번호 순서대로 하나씩. **각 스킬의 절차를 그대로 따른다.**

| 줄 | 넘길 곳 | 그 스킬에서 하는 일 |
|---|---|---|
| 새 채널 과거 대화 | `slack-sync` **3.5단계** | 기준점 이전 대화를 거슬러 읽는다 |
| 아침 보고 | `archive-inbox` | 건별로 반영/빼/나중에 → 요약 편집 → `--show` |
| 수정·삭제·중복 | `slack-sync` **10단계** | `apply_edits.py --only … --apply` |
| 미변환 첨부 | `doc-archive` | 변환 → 7.5 건별 점검 → index → 상태 |
| 승인 미반영 | `doc-archive` 「승인 반영」 | `apply_approvals.py --only "채널/파일명"` |

### 4. 구간이 끝나면 커밋 — **승인을 따로 받는다**

```bash
git status                              # 내가 만든 것만 들어 있나
git log --oneline origin/main..HEAD     # push 전: 내 커밋만 나가나
```

**커밋도 push 도 WHK 승인을 다음 턴에 받는다.** 구간 안에서 받은 건별 승인(7.5 점검표·
아침 보고 결정)은 **커밋 승인이 아니다.** push 한 내용은 15분 안에 봇이 팀 앞에서
인용하는 근거가 된다.

구간마다 따로 커밋한다 — 이력이 성격별로 나뉘고, 되돌릴 때 한 구간만 되돌린다.

### 5. 상황판으로 돌아온다

```bash
python .claude/skills/archive-run/scripts/board.py --fast
```

방금 처리한 줄이 줄었는지 본다. 첨부를 처리했으면 슬랙을 다시 훑어야 하므로 `--fast`
없이 돌린다.

### 6. 잠금 풀기

```bash
python .claude/skills/archive-run/scripts/board.py --unlock
```

**끝나면 반드시 푼다.** 안 풀면 다음 세션이 막히고, 4시간 뒤에야 「오래됨」으로 뜬다.

## 순서는 마감이 정한다

표는 마감이 가까운 순으로 정렬된다. 마감의 근거:

| 줄 | 마감 | 놓치면 |
|---|---|---|
| 새 채널 과거 대화 | 다음 **07:00** | 자동 반영이 기준점만 잡고 지나가 **그 채널의 과거 대화가 영영 안 들어온다** |
| 아침 보고 | 다음 **07:00** | 목록이 새로 만들어진다 (안 정한 것은 나이가 늘고 설정의 `pendingEditDays`(기본 3일)를 넘으면 09:00 점검에 뜬다) |
| 미변환 첨부 | **17:00** | 17:00 자동 반영이 `git pull` 로 들이는 시점을 놓쳐 **그날 요약에 안 실린다** (하단에 `미반영 N건` 만 붙는다) |
| 수정·삭제·중복 | (없음) | 설정의 `pendingEditDays`(기본 3일)를 넘기면 09:00 점검에 뜬다 |
| 동기화 밀림 | (상태) | 설정의 `syncWarnDays` 에 경고, **14일 넘으면 실시간 조회로도 안 메워진다** |

**동기화 밀림은 할 일이 아니라 상태다.** 경고선을 넘을 때만 번호가 붙는다.

## 값이 어디서 오나 — 새로 세지 않는다

| 줄 | 출처 |
|---|---|
| git 상태 | **자료 저장소**에서 `git status --porcelain` · `rev-list @{upstream}..HEAD` · 그 반대 (추적 브랜치가 없으면 `origin/main` 으로 물러서고 준비 줄에 그렇게 적는다) |
| 마감 시각 | 자료 저장소 `config.json` 의 `digest.ingest`·`ingestPre` 크론 |
| 아침 보고 · 새 채널 | `archive-inbox` 의 `review_work.py --json` |
| 수정·삭제·중복 | `slack-export/.pending-edits.json` |
| 동기화 밀림 | `slack-export/.sync-state.json` 의 `last_sync` |
| 미변환 첨부 · 승인 미반영 | 코드 저장소 `scripts/board-docs.js` → `archive-health.js` 의 `pendingDocuments()` |

미변환 첨부 줄은 **09:00 위생 점검이 쓰는 함수를 그대로 부른다.** DM 본문(한국어 산문)을
파싱하지 않는다 — 문구가 바뀌면 **에러 없이 0건**이 된다.

**마감 시각도 여기 적지 않고 설정에서 읽는다.** `config.json` 의 크론을 바꾸면 상황판이
따라온다. 다만 읽는 것은 `0 7 * * *` 처럼 **하루 한 번**인 크론뿐이라, `0 7,17 * * *` 같이
여러 번 도는 것은 이 칸에 적을 수가 없다 — 그때는 기본값(07:00·17:00)으로 가되 **그 줄
밑에 「기본값을 씁니다」라고 적는다.** 말없이 물러서지 않는다.

**`.pending-work.json`·`.pending-edits.json` 이 없는 것은 0건이다.** 쓰는 쪽이 남은 것이
없으면 파일을 지운다(`pending-work.js` 의 `runPendingWork`·`slack-archive.js` 의 `ingestConversations` 안 `PENDING_FILE` 쓰기). **있는데 못
읽는 것만 실패로 본다.**

**미뤄 둔 것은 만기까지 안 보인다.** `.pending-edits.json` 은 미룬 건을 `items` 에 그대로
남기고 **보고에서만 뺀다**(`slack-archive.js` 의 `ingestConversations` 안 「나중에」 제외). 그래서 상황판도 `.sync-state.json` 의
`deferred` 로 같은 규칙(`until` 이 오늘 이후)으로 걸러 센다 — 안 그러면 07:00 보고·09:00
점검이 조용한 건이 여기서만 되살아난다. 뺀 개수는 `보류 N건` 으로 보인다.

**미변환 첨부의 숫자는 성공한 채널만 센 값이다.** 채널 조회가 실패해도 `pendingDocuments()`
는 나머지만 세서 돌려준다(`archive-health.js` 의 `pendingDocuments` 의 채널 순회). 그래서 실패가 하나라도 있으면
**「최소 N건」으로 적고 그 줄은 언제나 손볼 것으로 센다.**

## 상태 파일

| 파일 | 누가 쓰나 | 저장소 |
|---|---|---|
| `slack-export/.archive-run-lock.json` | `board.py --lock` | **안 들어감** (`.gitignore`) |

잠금이 저장소에 안 들어가는 이유: 이 기계에서 두 세션이 겹치는 것을 막는 표시라,
push 되면 다른 PC·VM 이 남의 pid 를 보고 「돌고 있다」고 읽는다.
