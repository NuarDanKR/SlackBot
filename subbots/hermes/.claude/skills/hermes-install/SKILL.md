# hermes-install

**코드 저장소만 받은 팀을 0~8단계로 밀어, 「과거를 근거로 답한다」까지 끌고 간다.**

> **뜨는지 확인만 하려면 이렇게 여세요.**
>
> ```
> claude --permission-mode plan --disallowed-tools Bash Edit Write NotebookEdit
> ```
>
> 여는 것까지는 안전한데, **밟으면 진짜 일이 벌어지는 단계가 둘**이다 — 6단계
> (`join_channels.py --confirm`)는 봇이 실제로 슬랙 채널에 들어가 「참여함」이 팀원에게
> 보이고, 7단계(`npm run backfill -- --all-channels`)는 **진짜 아카이브에 쓴다.** 둘 다
> 셸 명령이라 `--disallowed-tools Bash` 하나로 **구조적으로 못 밟는다.**
> `--permission-mode plan` 은 그 위에 파일을 못 고치게 한 겹 더 둔다.
>
> **플래그를 빼면 그냥 설치가 진행된다** — 구경만 할 때는 빼지 말 것. (2026-09-02 에 이
> 조합으로 마법사가 뜨는 것과 저장소가 시험 전후 동일한 것을 실측했다. 플래그 이름은
> 2026-09-03 에 `claude --help`(2.1.220)로 다시 확인했다.)

절차는 여기 없다. 각 단계가 실제로 부르는 것은 `npm run doctor`·`slack-app-manifest.yaml`·
`npm run init-archive`·`.env.example`·`npm run check`·`join_channels.py`·`npm run
backfill`·`doc-archive` 스킬·`check-fixtures.json` 이고, 이 스킬이 아는 것은 **순서 ·
무엇을 부르나 · 무엇을 확인하나 · 어디까지 됐나** 뿐이다. 0~8단계 뒤의 VM 배포·검증은
`deploy/README.md` 와 `npm run ask` 를 따로 부른다 — 아래 해당 절 참조.

절차를 여기 옮겨 적지 않는 이유: `deploy/README.md` 도 `README.md` 「처음 설치」 절도 이미
있고 매번 바뀐다. 복사하면 원본이 바뀔 때 **에러 없이 낡는다** — `archive-run` 이 세 스킬의
절차를 안 베끼는 것과 같은 이유다. **단계 번호는 `README.md` 「처음 설치」 절의 `### N.`
헤더와 이 표가 같아야 한다** — `scripts/check-install-wizard.js` 가 그 번호 집합이 갈리면
막는다.

## 어디서 도나

**노트북, 코드 저장소 뿌리에서.** VM 이 아니다. clone 한 코드 저장소 폴더에서 Claude Code 를
열고 "헤르메스 설치하자" 라고 하면 이 스킬이 뜬다. VM 배포에서도 이 스킬 자체는 노트북에
남아 있다 — VM 에 붙는 것은 사람이고, 이 스킬은 붙여넣을 명령줄만 만든다.

## 닭과 달걀 셋 — 순서는 취향이 아니라 이 제약이 정한다

| 막히는 것 | 왜 | 언제부터 되나 |
|---|---|---|
| 슬랙을 읽는 모든 것 | `.env` 에 봇 토큰이 없다 | 1단계 뒤 |
| `npm run check`·`backfill`·`ask` | `src/config.js:40` 이 자료 저장소의 `config.json` 을 못 찾으면 **던진다** | 3단계 뒤 |
| 자료 저장소를 제대로 가리키기 | `HERMES_DATA_ROOT` 가 비면 코드 옆 `hermes-archive` 로 **조용히 물러선다** (`src/config.js:24`) | `.env` 를 적은 뒤 |

세 번째가 가장 위험하다 — 에러가 아니라 엉뚱한 폴더를 보는 상태다. `src/config.js` 는 못
찾았을 때 **찾은 경로와 그 값이 어디서 왔는지(HERMES_DATA_ROOT 인지 폴백인지)를 함께**
찍으므로, 그 출력을 그대로 사람에게 보이고 다음으로 넘어간다.

`npm run init-archive` 는 예외다 — `config.js` 를 안 부르므로 자료 저장소가 아직 없는
상태에서도 돈다. 끝에 「다음에 할 일」을 이미 찍으니 그 출력을 읽어 주고 하나씩 민다.

## 0~8단계

| 단계 | 부르는 것 | 끝에서 확인하는 것 |
|---|---|---|
| **0 준비물** | `npm run doctor` | 종료코드가 0 인가 · **⚠ 목록에 python 이 있나** (있으면 7단계에서 막힌다) · 커밋·push 관문이 켜졌나 |
| 1 Slack 앱 | `slack-app-manifest.yaml` | 봇 토큰으로 `auth.test` 가 통하나 |
| 2 Anthropic API 키 | (콘솔에서 발급 — 부르는 명령 없음) | `.env` 에 넣을 `sk-ant-…` 키를 받았나 |
| 3 자료 저장소 만들기 | `npm run init-archive -- <자료저장소경로>` | 아카이브 틀·`config.json` 이 생겼나 · 커밋·push 했나 |
| 4 `.env` 파일 만들기 | `.env.example` 복사 | 봇 토큰·앱 토큰·API 키 세 줄 + `HERMES_DATA_ROOT` 를 채웠나 |
| 5 점검 | `npm run check` | 종료코드가 0 인가 · **봇이 아직 초대되지 않은 채널 목록**이 뭔가 |
| 6 채널 참여 | `.claude/skills/doc-archive/scripts/join_channels.py` | 봇이 든 채널 수 · **비공개 채널 중 `/invite` 가 아직 안 된 것 목록** |
| 7 백필(대화·문서) | `npm run backfill -- --channel <이름>` / `--dry-run` / `--since YYYY-MM` / `--all-channels`, **첨부 문서는 `doc-archive` 스킬이 따로 채운다** | 채널별 「가장 오래된 날짜」 표 · `documents/index.md` 에 실린 건수 |
| 8 검사 질의 만들기 | `check-fixtures.json` | `npm run check` 의 검사 셋이 실물 질의로 도나 (「재지 못했습니다」로 건너뛰지 않는가) |

**여기까지가 「설치」다.** 봇은 뜨고 과거를 답할 수 있는 상태가 된다. 이어서 **VM 배포**와
**최종 검증**을 하는데, 팀마다 이미 도는 VM 이 있거나(기존 인스턴스를 손보는 경우) 순서가
달라질 수 있어 **번호를 안 매긴다** — 아래 두 절이 그대로 그 일이다.

**0단계는 이 기계에 준비물이 있나만 본다.** `npm run doctor` 가 ✗(지금 막힘) ·
⚠(나중 단계에서 막힘) · ?(못 쟀음)로 갈라 준다. ✗ 와 ? 는 먼저 닫는다.

**⚠ 중에 `python` 이 있으면 그것만은 여기서 닫는다 — 7단계에서 물린다.**
나머지 ⚠(openpyxl · LibreOffice · npx)는 7단계의 문서 채우기(`doc-archive`)에서 쓰는
변환 도구라 미뤄도 된다. python 은 다르다: 7단계의 `npm run backfill` 이 끝에 파생값을
다시 세면서 파이썬 스크립트를 부르고 (`src/ingest/util.js` 의 `python()` 이 못 찾으면
던진다), 설치가 끝난 뒤에도 매일 07:00·17:00 자동 반영과 09:00 위생 점검이 같은 함수를
부른다. **「엑셀 첨부가 없으면 파이썬은 안 쓰인다」가 아니다.**

**그리고 이것은 종료코드로 안 걸린다.** `scripts/check-prereqs.js` 는 python 없음을 ⚠ 로
내고 ⚠ 는 종료코드에 안 들어가서, python 이 없어도 `npm run doctor` 가 **0 으로 끝난다** —
위 표의 0단계 합격 조건(「종료코드가 0 인가」)을 그대로 통과한다. 그래서 0단계에서는
종료코드만 보지 말고 **화면의 ⚠ 목록을 사람에게 그대로 보이고**, 거기 python 이 있으면
그 자리에서 닫는다.

> VM 쪽은 따로다 — VM 배포의 `deploy/setup.sh` 가 VM 에 python3 를 직접 깐다.
> 여기서 닫는 것은 **이 노트북**의 python 이고, 7단계 백필이 도는 곳이 노트북이다.

**미룬 ⚠ 는 7단계(문서 채우기) 시작 전에 다시 본다.** 0단계와 7단계 사이가 며칠 벌어질 수
있어서(슬랙 앱 승인을 기다리거나 백필이 오래 걸린다), 0단계에서 본 ⚠ 를 잊은 채 7단계에
도착하게 된다. **7단계를 시작하기 전에 `npm run doctor` 를 한 번 더 돌려** 남은 ⚠ 를
사람에게 보이고 닫을지 묻는다. 남은 것이 문서 변환 도구뿐이면 안 닫아도 진행은 된다 —
엑셀 첨부를 만나면 `ModuleNotFoundError` 로 죽으면서 깔 명령이 화면에 나온다.

**커밋·push 관문은 여기서 걸어 준다.** 훅은 저장소 안(`.githooks/`)에 있지만 git 은
훅을 복제하지 않으므로 clone 직후에는 꺼져 있고, **꺼져 있다는 신호가 어디에도 안 난다** —
그대로 두면 팀은 승인 관문이 도는 줄 알고 일한다. doctor 가 낸 `고치기:` 줄을 그대로
실행하고, **`git config --get core.hooksPath` 를 다시 읽어 사람에게 보인다.**
**이 코드 저장소에 절대경로로 건다** — 상대경로 `.githooks` 로 걸면, 나중에 자료
저장소(별도 저장소·별도 설정)에 거는 같은 함정에 그대로 걸린다.

**6단계 확인이 7단계의 전제다.** 백필은 봇 토큰으로 읽으므로 **봇이 안 든 채널은 통째로
건너뛴다.** 6단계에서 짚지 않으면 백필이 정상 종료하고 그 채널만 조용히 비어 있게 된다 —
`not_in_channel` 로 끝에 이름이 나와도 "0건이 아니다"로 읽어야 한다.

**`npm run backfill` 은 인자 없이 부르면 막힌다.** 전 채널을 실제로 쓰려면 `--all-channels`
를 명시해야 한다(인자 없는 실행이 전 채널 백필을 시작한 사고가 실제로 있었다). 처음에는
**채널 하나로 먼저 해 보고**(`--channel`) 결과를 확인한 뒤 `--all-channels` 로 넘어가게
안내한다.

**백필이 끝나면 채널별 「가장 오래된 날짜」 표가 나온다.** 슬랙 요금제에 따라 과거가 90일치
만 남기도 하는데 그때도 백필은 **정상으로 끝난다** — 이 표를 사람에게 그대로 보이고 「여기
까지가 전부입니다」를 확인시킨다. 안 보이면 그 상태가 「과거를 다 채웠다」로 잘못 읽힌다.

## VM 배포

**`setup.sh` 가 아니라 `deploy/README.md` 를 편다.** 그 문서는 일곱 부분이고 `setup.sh`
는 그중 ④⑤뿐이다. 스크립트 이름만 주면 **저장소 둘의 배포키(⑥)** 로 가는 길이 없어서
거기서 막힌다 — 코드만 받은 팀이 실제로 서는 자리가 그곳이다. `deploy/README.md` ①~⑦ 을
따라 명령줄을 만들어 주고, **사람이 붙여넣는다** — 이 스킬은 VM 에 SSH 로 붙지 않는다.
끝에서 확인하는 것은 사람이 되돌려준 `systemctl status` 출력이다.

**무엇이든 고쳤으면 `sudo systemctl restart hermes` 까지가 배포다.** `config.json` 과
소스는 **기동할 때 한 번만** 읽힌다. 15분마다 도는 `git pull` 은 파일을 가져올 뿐 재시작을
안 하므로, 고친 것이 안 붙은 채 `git log` 에는 새 커밋이 보이고 pull 도 성공한다 —
**에러도 경고도 없다.** `privateChannels` 같은 사람 판단을 이 자리에서 고치게 되는 일이
잦아 이게 바로 물린다. 자세한 것은 `deploy/README.md` 의 「코드를 고쳤을 때」.

## 검증

```
npm run check
npm run ask -- "..."
```

`npm run check` 가 전부 통과하고, `npm run ask` 로 과거 대화에 대해 물었을 때 봇이 근거를
대며 답하면 그때 설치가 끝난 것이다.

## 재개

상태는 **코드 저장소 뿌리**의 `.hermes-install.json` 에 둔다(이미 `.gitignore` 에 있다).
다시 부르면 그 파일을 읽어 「N단계까지 됐습니다. N+1단계부터 갑니다」로 잇는다. 설치는 며칠에
걸칠 수 있다 — 슬랙 앱 승인을 기다리거나 백필이 오래 걸리거나. **8단계까지 다 됐으면
VM 배포·검증이 남았는지를 사람에게 물어 잇는다** — 상태 파일은 0~8단계만 번호로 센다.

## 상태 파일은 「했다」로 안 적고 「확인이 통과했다」로만 적는다

각 단계의 「끝에서 확인하는 것」이 통과해야 그 단계 번호가 `done` 에 들어간다. 명령을
돌리기만 하고 확인이 실패했으면 그 단계는 안 찍힌다 — 안 그러면 상태 파일은 「8단계까지
끝」인데 봇은 실제로 안 도는 상태가 된다.

## 이 마법사가 안 하는 것

- **커밋·push 를 대신 안 한다.** 단계마다 「지금 커밋할 것」을 보이고 승인을 받는다 —
  `git push` 는 이 스킬이 절대 하지 않는다
- **GitHub 저장소를 안 만든다**
- **VM 에 SSH 로 안 붙는다** — 명령줄만 만들어 주고 사람이 붙여넣는다
- **토큰·API 키를 대신 받아오지 않는다** — 클릭은 사람이다
- **`config.json` 의 판단 값을 대신 안 정한다.** 특히 `privateChannels` 는 슬랙에서 읽은
  실제 `is_private` 를 보여 주고 **고르게 한다** — 손으로 적어 어긋난 사고가 이미 있었다
