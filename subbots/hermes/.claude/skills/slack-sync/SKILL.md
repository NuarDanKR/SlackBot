# slack-sync

Slack 대화 아카이브(자료 저장소의 `slack-export/`)를 **증분**으로 갱신한다.
전체를 다시 읽지 않는다 — 마지막 동기화 시각 이후 새 메시지만 가져온다.

## 어디서 돌리나 — 저장소가 둘이다

2026-08-31 부터 코드와 자료가 갈렸다. **명령은 코드 저장소 뿌리에서 친다** — 이 파일도
스크립트도 `node scripts/` 도 거기 있다. 대화 아카이브와 `config.json` 은 **자료 저장소**에
있고, 그 뿌리는 `.env` 의 `HERMES_DATA_ROOT` 다.

```bash
cd ~/hermes/code                     # 코드 저장소 (VM 은 /opt/hermes/code)
DATA=$(node -e "import('./src/config.js').then(m=>console.log(m.DATA_ROOT))")
```

**자료를 다루는 git 은 `git -C "$DATA"` 로 친다.** 코드 저장소에서 그냥 `git` 을 치면
자료가 아니라 코드를 본다 — 없는 경로를 대도 git 은 화내지 않아서, 에러가 아니라
**빈 결과와 종료코드 0** 이 나온다. 둘이 같은 곳을 보는지는 `node scripts/check-roots.js`.

## ⚠️ 자동 반영과 겹친다 — 돌리기 전에 읽을 것

**원문 반영은 Hermes 가 VM 에서 자동으로 한다**(코드 저장소의 `src/ingest/`).
봇 토큰으로 여기 3~6단계와 같은 일을 하고, 상태 파일 `.sync-state.json` 을 갱신한 뒤 push 한다.
(**2026-08-04 부터 켜져 있다 — 매일 07:00, 그리고 2026-08-06 부터 요약 직전 17:00 에 한 번 더.**
`config.json` 의 `digest.ingest.enabled`·`ingestPre`. 17:00 회차는 원문만 넣고 요약 대조·수정 감지는 끈다.)

그래서 이 스킬은 **평상시에 돌리지 않는다.** 계속 필요한 경우는 셋뿐이다.

| 언제 | 왜 |
|---|---|
| 새 채널의 과거 대화 추출 | 자동은 기준점만 잡고 DM 으로 알린다 → **3.5단계** |
| 미수집 초기 구간 채우기 | 증분이라 `last_ts` 이전은 자동으로도 안 채워진다 → **3.5단계** |
| **6.5 상단 요약 대조·수정** | 자동은 후보를 DM 으로 보고만 한다. 고치는 것은 사람 |
| **10 슬랙 수정·삭제 반영** | 자동은 찾아서 DM 으로 알리기만 한다. 원문을 고치는 것은 사람 |

> **돌리기 전에 반드시 `git -C "$DATA" pull`.** VM 이 `last_ts` 를 갱신하고 push 하므로, 안 받고 돌리면
> 상태가 갈라져 메시지가 중복되거나 빠진다. 자동 반영 쪽은 작업 트리가 더러우면 멈추므로
> 이쪽 작업이 커밋되지 않은 채 남아 있으면 그날 자동 반영이 통째로 건너뛰어진다.

> 🚨 **새 채널을 발견했으면 다음 07:00 전에 끝내고 push 한다.** 자동 반영은 새 채널을 만나면
> **기준점만 잡고 상태 파일에 등록한 뒤 push** 한다. 그러면 그다음부터는 이 스킬도 그 채널을
> 신규로 안 보고(상태에 있으니), 3단계는 `oldest = last_ts` 로만 읽어 **과거 대화가 영영 안
> 들어온다.** 늦었으면 3.5단계로 거슬러 읽어야 한다.
> (2026-08-06: `#비공개나`·`#사업장카` 을 07:00 6시간 전에 잡았다. 하루 늦었으면
> 각각 9건·3건이 통째로 빠진 채 굳었다.)

## 전제

- **한 번에 한 세션에서만 돌린다.** 다른 창(다른 터미널)에서 이 스킬이나 `doc-archive` 가
  돌고 있으면 끝나기를 기다린다. 상태 파일(`.sync-state.json`·`.doc-state.json`)과 `index.md` 를
  **실행 끝에 통째로** 쓰기 때문에, 겹치면 나중에 쓰는 쪽이 앞 세션의 추가분을 모르는 채 덮는다.
  커밋도 서로 쓸어담는다 — 2026-08-04 에 다른 터미널의 세션이 자기 작업을 커밋하며
  **승인 대기 중이던 변경 204개까지 함께 push 했고**, VM 이 15분 안에 pull 해 팀 앞 근거가 됐다.
  커밋 전에 `git status` 로 **내가 만든 것만 들어 있는지** 확인한다
- Slack MCP 커넥터가 인증되어 있어야 한다. `mcp__claude_ai_Slack__*` 도구가 안 보이면 사용자에게 `/mcp` → **claude.ai Slack** 선택을 안내하고 중단한다. (커넥터는 계정 인증 후 **Claude Code 재시작**이 필요할 수 있다.)
- 아카이브가 이미 존재해야 한다. 자료 저장소의 `slack-export/index.md`가 없으면 "먼저 전체 추출이 필요합니다"라고 알리고 중단한다.

## 상태 파일

자료 저장소의 `slack-export/.sync-state.json`

```json
{
  "last_sync": "2026-08-01T18:30:00+09:00",
  "channels": {
    "C0EXAMPLE01": { "name": "사업장가",  "last_ts": "1785481236.428419", "summary_reviewed_ts": "1785481236.428419" },
    "C0EXAMPLE02": { "name": "비공개가",    "last_ts": "1785481185.830069", "summary_reviewed_ts": "1785481185.830069" }
  }
}
```

`last_ts`는 그 채널에서 **마지막으로 아카이브에 반영한 메시지의 Slack ts**다.

`summary_reviewed_ts`는 **상단 요약 대조(6.5단계)를 마친 지점**이다. `last_ts`와 별개다 —
원문은 반영됐지만 요약 변경은 보류될 수 있기 때문이다. 자세한 것은 6.5단계.

> ⚠️ **필드가 없는 채널을 "이미 대조함"으로 취급하지 않는다.** 6.5단계 도입(2026-08-03) 때
> 기존 채널 전부에 `last_ts` 값을 그대로 찍어 넣었는데, 그 채널들은 한 번도 대조된 적이 없다.
> 그래서 `#사업장나` 요약표의 중도금대출이 2026-07-15 원문에서 A → B 로 바뀐 것을
> 6.5단계가 구조적으로 못 잡았다(2026-08-03 손으로 전수 대조하다 발견). **대조한 적 없는 것이
> 대조 완료로 기록돼 있으면 아무도 다시 묻지 않는다.**
>
> 필드가 없으면 **요약 섹션의 기준일**(`## 자금 구조 요약 (2026-06-29 기준)` 의 날짜, 또는 표 안의
> 항목별 기준일 중 가장 오래된 것)을 시작점으로 삼는다. 기준일도 없으면 사용자에게 묻는다.
> 범위가 넓어 한 번에 다 못 보면 그 사실을 보고에 적는다 — 조용히 자르지 않는다.

## 수행 절차

### 0. 상태 파일 확인 — 없으면 베이스라인 모드

```bash
ls "$DATA/slack-export/.sync-state.json"
```

**없으면** → 베이스라인 모드로 진입한다. 각 채널의 **현재 최신 ts만 기록**하고 본문은 건드리지 않는다.
사용자에게 이렇게 알린다: *"기준점만 잡았습니다. 지금부터 올라오는 메시지가 다음 실행 때 반영됩니다."*
베이스라인은 `limit: 1`로 채널당 1건씩만 읽어 ts를 딴다.

### 1. 채널 목록 확보 + 신규/개명 감지

`slack_search_channels`로 전체 채널을 훑는다. 이 워크스페이스에서는 **`query: "a"`가 전 채널을 반환**한다(한글 채널명에도 매칭됨). `channel_types: "public_channel,private_channel"`, `limit: 20`으로 커서 페이지네이션.

- **상태에 없는 채널 ID** → 신규 채널. 전체 히스토리를 읽어 새 md 파일을 만든다.
- **상태의 name과 현재 name이 다름** → 채널 개명. md 파일명·헤더를 갱신하고, 본문에 개명 사실을 한 줄 남긴다.

### 2. 활동 채널 선별 — **먼저 검색 한 번으로 좁힌다**

45개 채널을 전부 읽지 말 것. `slack_search_public_and_private` 한 번이면 **어느 채널에 새 글이 있는지** 알 수 있다.

```
slack_search_public_and_private(
  query           = "after:2026-07-31",     # 마지막 동기화 전날
  sort            = "timestamp",
  sort_dir        = "desc",
  limit           = 20,
  include_context = false,
  response_format = "concise"
)
```

- 결과가 0건이면 **거기서 끝낸다.** "새 메시지 없음"만 보고.
- 결과에 나온 채널만 3단계로 넘어간다. 보통 하루 1~3개 채널이다.
- 20건을 꽉 채우면 커서로 더 읽거나, 밀린 날이 많다는 뜻이므로 채널별 조회로 전환한다.
- `after:`는 **날짜 단위**라 경계일 메시지가 딸려 온다. 정확한 필터링은 다음 단계의 `oldest`가 담당한다.

> 검색은 **본문이 없는 메시지(파일만 올린 글)를 놓칠 수 있다.** 주 1회 정도는 검색을 건너뛰고 전 채널 `oldest` 조회로 빠짐없이 훑는 것이 좋다. 사용자가 "전체 확인"이라고 하면 검색을 생략한다.

### 3. 채널별 증분 조회

2단계에서 선별된 채널에 대해:

```
slack_read_channel(
  channel_id = <ID>,
  oldest     = <상태의 last_ts>,
  limit      = 100
)
```

- 결과가 없으면 그 채널은 건너뛴다.
- **중복 방어**: Slack의 `oldest`는 경계 포함 여부가 애매하다. 반환된 메시지 중 ts가 `last_ts`와 **같은 것은 버린다**.
- `pagination_info`에 다음 커서가 있으면 이어서 읽는다(하루치면 대개 1페이지).

### 3.5. 과거 구간 채우기 — `oldest` 가 아니라 `latest`

3단계는 `oldest = last_ts` 라 **앞으로만** 읽는다. 새 채널의 과거 대화와 미수집 초기 구간은
여기서 채운다. 방향이 반대다 — **`latest` 로 끝을 정하고 거슬러 읽는다.**

```
slack_read_channel(
  channel_id = <ID>,
  latest     = <채울 구간의 끝 ts>,   # 새 채널이면 생략(= 처음부터 전부)
  limit      = 100
)
```

`pagination_info` 에 다음 커서가 있으면 이어 읽는다. 스레드는 4단계와 같이 `slack_read_thread`.

**넣는 자리**

- **채널 md 가 아예 없으면** Write 로 새로 만든다. 형식은 6단계와 같고, 기존 파일 하나를
  열어 그대로 베낀다(첫 줄 `# #채널명`, `>` 메타 블록, `---`, `## YYYY-MM`, 하단 `## 참여 기록`,
  `_출처: …_`). **비공개 채널이면 첫 줄에 `🔒 비공개` 를 붙인다.**
- **이미 있는 파일의 앞 구간을 채우는 것이면** Write 가 아니라 `insert_messages.py --month
  --at-month-end` 로 달마다 넣는다. 한 달 안에서는 최신이 위가 되도록 뒤집어 넘긴다.
  하단 「미수집 구간」 줄도 함께 지운다.

  > **그 메모를 남긴 채로는 그 md 를 커밋할 수 없다.** `verify_archive.py` 가 「수집 실패
  > 표식」으로 잡고 `pre-commit` 이 멈춘다 — 아카이브가 스스로 「여기는 비었다」고 적은 상태로
  > 굳는 것을 막으려는 것이다(2026-08-13 에 이렇게 두기로 정했다). `sync_index.py --all` 로는
  > 안 풀린다. **구간을 채우고 그 줄을 지우는 것이 정상 경로**이고, 오래 남길 기록이면
  > 채널 md 가 아니라 `slack-export/index.md` 에 적는다 — 거기는 이 검사 대상이 아니고,
  > 2026-08-07 에 구간을 다 채운 기록도 실제로 그 파일에 있다.

  ```bash
  python .claude/skills/slack-sync/scripts/insert_messages.py \
    --file "$DATA/slack-export/channels/<채널>.md" \
    --month "2026-06" --at-month-end --content-file "$TMP/block.md"
  ```

  > **`--at-month-end` 를 빼면 시간 순서가 뒤집힌다.** 기본값은 맨 위에 붙이는 것이고
  > (평상시 넣는 것은 새 메시지니까 그게 맞다), 여기서 넣는 것은 **이미 있는 것보다
  > 오래된** 메시지다. `#사업장가` 6월 절에는 이미 6/16 이후분이 있어서, 그냥 넣으면
  > 6/15 가 6/16 위로 올라간다. 없던 달을 채울 때도 `--at-month-end` 가 본문 **맨 뒤**에
  > 만든다 — 없던 달은 기존 어느 달보다 오래된 달이다.
  > (2026-08-07 추가. 그 전에는 이 자리를 Edit 으로 손수 넣어야 했다.)

**상태 파일**(9단계)에 그 채널을 넣는다. `last_ts` 는 **훑은 것 중 가장 최근 ts** 로 잡는다 —
참여 로그처럼 본문에 안 넣는 메시지도 포함해서 센다. 안 그러면 다음 실행이 그 구간을 매번
다시 훑는다.

> **`last_sync` 는 건드리지 않는다.** 그건 "워크스페이스 전체를 언제까지 훑었나"이고,
> 여기서 한 일은 채널 한둘을 채운 것뿐이다. 앞당겨 적으면 위생 점검의 「대화 동기화 N일 밀림」이
> 거짓으로 통과하고, 자동 반영의 수정 감지 기준선(`editedSince`)도 함께 앞당겨져 그 사이 편집이
> 영영 안 잡힌다.

**끝나면 확인한다** — 넣은 것이 봇에게 한 건씩 보이는지, 그리고 비공개면 **공개 채널에서 막히는지**:

```bash
node --input-type=module -e "
import {splitMessages, readChannel, searchArchive} from './src/archive.js';
import {PUBLIC_ACCESS, FULL_ACCESS, accessFor, ARCHIVE_DIR} from './src/config.js';
import fs from 'fs'; import path from 'path';
const name='<채널>';                         // 채운 채널
const p=path.join(ARCHIVE_DIR,'channels',name+'.md');
const t=fs.readFileSync(p,'utf8');
const hdr=(t.match(/^\*\*\d{4}-\d{2}-\d{2} \d{2}:\d{2} · /gm)||[]).length;
console.log('메시지 헤더', hdr, '· 블록', splitMessages(t).length, hdr===splitMessages(t).length?'OK':'FAIL');
console.log('헤더 표기', /\*\*실제 메시지\*\*: (\d+)건/.exec(t)[1], '건');
console.log('그 채널 안에서:', readChannel({channel:name, access:accessFor([name])}).error ? 'FAIL' : 'OK');
console.log('공개 채널에서:', readChannel({channel:name, access:PUBLIC_ACCESS}).error ? 'OK 차단' : 'FAIL 열림');"
```

비공개를 채웠으면 **공개 권한으로 전 채널·색인까지 훑어** 그 내용의 특징적인 낱말이 한 건도
안 나오는지 본다. 채널 하나만 보고 닫으면, 다른 채널 md 나 `index.md` 에 사람이 적어 둔 참조
줄로 새는 것을 놓친다.

### 4. 스레드 답글

새 메시지에 `Thread: N replies`가 붙어 있으면 `slack_read_thread`로 답글을 가져온다.
**기존 메시지의 스레드에 새 답글이 달린 경우도 놓치지 않는다** — `slack_read_channel`은 부모 메시지의 `latest reply` 시각이 갱신되어도 부모를 다시 반환하지 않으므로, 상태 파일에 스레드를 함께 기록해 둔다:

```json
"threads": { "1785481236.428419": { "reply_count": 3, "latest": "1785482000.123456" } }
```

`reply_count`가 늘었으면 해당 스레드만 다시 읽어 **추가된 답글만** 기존 스레드 블록 끝에 덧붙인다.

토큰 절약을 위해 스레드는 `response_format: "concise"`로 읽는다.

> ⚠️ **알려진 한계**: 베이스라인(2026-08-01) **이전에 만들어진 스레드**는 `threads`에 기록이 없어, 거기에 새 답글이 달려도 감지하지 못한다. 오래된 스레드가 되살아나는 일은 드물지만, 신경 쓰이면 가끔 "예전 스레드도 다시 확인해줘"라고 요청하면 된다.
>
> (무인 자동 반영 쪽은 2026-08-05 부터 `threads` 목록이 아니라 부모의 `latest_reply` 로 판정해 이 한계가 없다 — 코드 저장소의 `src/ingest/slack-archive.js` 의 `grownThreads`.)

**정정 댓글 (`[정정] …`)** — 틀린 내용을 고치려고 나중에 스레드에 다는 답글이다. 원문은 **고치지 않고** 이 답글만 부모 블록 안에 덧붙인다. 넣는 자리·모양은 일반 답글과 같다:

```bash
python .claude/skills/slack-sync/scripts/insert_messages.py --file <채널md> \
  --append-thread '**2026-08-04 13:08 · 홍길동**' --content-file <답글줄들>
```

이미 들어 있는 답글은 건너뛰므로 다시 돌려도 쌓이지 않는다. 건너뛸지는 **줄이 아니라 답글 단위**로 판정한다 — 슬랙 답글은 여러 줄일 수 있어서, 줄 단위로 세면 한 답글이 N건으로 잡혀 스레드 건수가 부풀고 둘째 줄부터는 중복 판정에 안 걸려 **자동 반영이 돌 때마다 다시 쌓인다**(2026-08-10 수정). 이어지는 줄에는 `>` 를 붙여 인용 블록 안에 둔다. **부모가 Hermes 가 올린 메시지면 넣지 않는다** — 봇의 글은 아카이브에 블록이 없고, 자리를 만들어 넣으면 봇이 자기 글을 근거로 삼게 된다.

> **답글이 들어가는 자리는 부모 바로 밑이다.** 아카이브에는 `**2026-07-09 16:37 · 정수연** — 7/9 사업장나 입주일일보고 자료` 처럼 **한 줄로 줄여 적은 메시지가 38건** 있는데, 예전에는 블록 끝을 줄끝 앵커가 있는 헤더 모양으로만 봐서 그 38건을 헤더로 못 알아보고 건너뛰었다 — 정정이 **남의 발언 두세 개 아래**에 적혔다(2026-08-10 수정). 지금은 넣는 자리는 좁게 보고, **중복 검사만 넓게** 본다 — 옛 판정으로 이미 뒤쪽에 들어간 답글을 못 보면 같은 정정이 한 번 더 붙기 때문이다.

> **부모가 30일보다 오래된 정정은 자동으로 안 들어온다 — 무시하는 쪽으로 정했다**
> (WHK 결정 2026-08-06, 근거는 「어차피 30일 안에 업데이트가 된다」). 자동 반영은
> `limits.threadLookbackDays`(30일)만큼만 되짚어서 그보다 옛 스레드는 **답글이 늘어난 것
> 자체를 못 본다**(`slack-archive.js` 의 `ingestChannel` 안 `lookbackSec`). **경고도 안 뜬다.**
> **다만 이 스킬로 손수 넣는 길은 열어 둔다** (WHK 지시 2026-08-06). 무시하기로 한 것은
> **자동 반영**이지 이 경로가 아니다 — 부모가 아무리 오래됐어도 위 `--append-thread` 로
> 넣을 수 있고, 그렇게 넣은 정정은 여느 답글과 똑같이 부모 블록 안에 들어가 봇이 읽는다.
> 나이 제한은 이 명령에 없다.
>
> 대신 **시작이 사람이라는 것만 알고 있을 것** — 자동 반영이 그런 정정을 못 보므로
> DM 도 안 오고 경고도 안 뜬다. 즉 **누군가 「이거 정정됐다」고 가져와야 돌아가는 경로**다.
> 그래서 평소에는 30일 넘은 내용을 고칠 때 **그 채널에 새 메시지로** 올리는 쪽이 확실하고
> (새 메시지는 자기 날짜로 들어와 자동 반영된다), 이미 스레드에 달린 옛 정정을 발견했을
> 때 그것을 아카이브에 넣는 자리가 여기다.

> **부모는 이름이 아니라 시각으로 찾는다.** md 에는 기록 당시 이름이 박혀 있고 부르는 쪽은
> 지금 슬랙 이름으로 헤더를 만들기 때문에, 이름으로 맞추면 **표시 이름을 한 번 바꾼 사람의
> 옛 메시지에는 정정이 영영 안 붙는다.**
>
> **중복 방지는 「무엇이 같나」가 아니라 「몇 개가 이미 있나」로 판정한다** (2026-08-10 수정).
> 답글의 진짜 열쇠는 슬랙 ts 인데 md 에는 분까지만 적혀 있어서, 어느 한 값만 보면 반드시
> 한쪽이 깨진다 — 헤더(`시각 · 이름`)만 보면 **같은 1분 안의 두 번째 답글이 사라지고**
> (`[정정]` 이 바쁜 1분에 들어가면 흔적 없이 없어진다), 본문까지 요구하면 **표기가 흔들린 옛
> 답글이 회차마다 새 줄로 쌓인다**(초기 수기 추출분은 `-`↔`•`·띄어쓰기·첨부 표기가 다르고,
> `<#C…>` 를 채널 이름으로 풀게 되면서 흔들릴 자리가 하나 더 늘었다). 그래서 ① `시각 + 본문`
> 완전일치로 먼저 짝을 짓고 — 이름을 안 보므로 이름이 바뀐 답글도 여기서 걸린다 —
> ② 남은 것은 같은 `시각 · 이름` 자리가 아직 비어 있으면 이미 있는 것으로 본다.
> 같은 시각에 부모 후보가 둘 이상이면 헤더 줄이 통째로 같은 것으로 좁힌다 — 그래도 못
> 고르는 자리가 실제로 있다(2026-09-22 실측: 헤더 줄이 글자까지 같은 곳 57곳·118건, 파일
> 20개). 예전에는 첫 번째를 골라서 정정이 엉뚱한 발언에 붙을 수 있었다.
>
> **못 고르면 멈춘다. 다만 넣을 것이 하나도 없으면 멈추지 않는다** (2026-09-22 추가).
> 붙이려는 답글이 후보 블록 전부를 통틀어 **①완전일치로** 이미 다 있으면 「이미 반영됨」으로
> 끝낸다 — 어디에 넣을지 못 정하는 것이 문제인데 넣을 것이 없으면 그 질문 자체가 안 선다.
> ②(같은 `시각 · 이름` 자리) 구제는 여기서 **안 쓴다**: 한 블록 안에서는 표기 흔들림이지만
> 블록 여럿에 걸치면 **남의 스레드에 같은 분 같은 사람이 단 답글**이 그 조건을 만족해 진짜
> 새 답글을 조용히 삼킨다. 새것이 하나라도 있으면 종전대로 멈춘다.
>
> **봇 답변 건수(`--bot-added`)만은 이때 못 올린다** — 어느 블록의 꼬리말을 고칠지 정해야
> 쓸 수 있는 값이고, 그 자리가 바로 못 고르는 자리다. 그렇다고 멈추면 위 고리가 **봇이
> 답한 스레드에서만** 그대로 살아나므로(사람 답글 0건 · 봇 답변만인 회차가 실제로 온다),
> 멈추는 대신 **못 올렸다고 말한다** — `NOTE:` 로 시작하는 줄을 찍고 `slack-archive.js` 의
> `collectNotes` 가 그것을 아침 보고에 싣는다.
>
> **그 건수는 못 되찾는다.** 회차가 성공하므로 상태(`threads[부모].reply_count`)가 전진해
> 다음 회차에 다시 제안되지 않는다 — md 블록을 고쳐 헤더를 갈라도 **앞으로의** 봇 답변부터
> 올라간다. 그 블록에 `(봇 답변 — 미수록)` 표식 줄이 아직 없었으면 이번에 안 생기는데,
> 그 표식은 `archive.js` 의 `isEchoEntry` 가 「봇이 답한 자리」를 알아보는 데도 쓰인다.
>
> 이 갈래가 없을 때 무슨 일이 났나 — 답글이 이미 md 에 있어도 `find_parent` 가 **중복 검사보다
> 먼저** 터져 「이미 반영됨」에 못 닿았고, 부르는 쪽(`slack-archive.js` ④-b)이 그 실패로 채널
> 회차를 중단해 `last_ts` 가 저장되지 않았다. 되돌아보기 창이 `last_ts` 기준이라 그 자리에
> 얼어붙어 **같은 실패가 매일 되풀이됐다** (한 채널이 2026-09-17~09-22 엿새 동안).

### 5. md 파일에 반영

`scripts/insert_messages.py`를 쓴다. 메시지는 **최신이 위**이므로 새 메시지는 해당 월 헤딩 바로 아래에 **prepend**된다.

```bash
python .claude/skills/slack-sync/scripts/insert_messages.py \
  --file "$DATA/slack-export/channels/<채널>.md" \
  --month "2026-08" \
  --content-file "$CLAUDE_JOB_DIR/tmp/new_block.md"
```

스크립트는 메타데이터 블록 다음 첫 `---` 뒤에서 `## {month}` 헤딩을 찾아 그 아래 삽입하고, 없으면 헤딩을 새로 만든다.

넣는 것이 **그 채널의 가장 새 메시지가 아닐 때**는 `--in-order` 를 붙인다. 헤더의 시각을 읽어
기존 블록들 사이 제자리에 넣고, 그 달이 없으면 월 헤딩도 내림차순 자리에 만든다. 자동 반영이
며칠 전 봇 글에 달린 사람 답글을 담을 자리표시 블록을 만들 때 이 모드를 쓴다
(Hermes 글이면 `[정정]` 만, 다른 봇 글이면 답글 전부).
(`--at-month-end` 와 함께 쓸 수 없다 — 자리를 정하는 방식이 서로 다르다.)

⚠️ **새 월 헤딩은 상단 요약 섹션 아래에 만들어야 한다.** `#사업장나`·`#사업장거` 처럼
요약 섹션(`## 자금 구조 요약 …`)이 있는 채널에서 위에 만들면, 요약이 첫 메시지 헤더 **아래**로
밀려 `splitMessages` 에 **사람 발언 본문으로 딸려 들어간다.** 2026-08-02 동기화에서 실제로 났고,
봇이 자금 구조 표를 "2026-08-02 WHK 발언"으로 인용했다. 스크립트는 요약 섹션을 건너뛰도록
고쳤지만(`find_body_start`), 손으로 편집할 때도 같다. 삽입 뒤 확인:

```bash
node --input-type=module -e "
import fs from 'fs'; import path from 'path';
import {splitMessages} from './src/archive.js';
import {ARCHIVE_DIR} from './src/config.js';
const dir=path.join(ARCHIVE_DIR,'channels');
const ok=/^##\s+(\d{4}-\d{2}\s*\$|참여 기록)/;
let total=0;
for (const f of fs.readdirSync(dir).filter(x=>x.endsWith('.md'))) {
  const t=fs.readFileSync(path.join(dir,f),'utf8');
  const bad=splitMessages(t).filter(b=>b.text.split('\n').some(l=>l.startsWith('## ')&&!ok.test(l)));
  if (bad.length) { total+=bad.length; console.log(f,'->',bad.map(b=>b.text.split('\n')[0]).join(', ')); }
}
console.log(total===0?'OK — 요약 섹션이 메시지 블록에 섞인 채널 없음':('총 '+total+' 건'));"
```

**월 헤딩(`## YYYY-MM`)과 `## 참여 기록` 이 메시지 블록에 딸려 들어가는 것은 정상이다** —
`splitMessages` 는 메시지 헤더에서만 자르므로 각 달 마지막 메시지가 다음 헤딩을 품는다.
그 둘을 걸러내지 않으면 45개 채널 전부가 69건으로 오탐한다(2026-08-03에 실제로 그랬다).
이 검사는 역검증까지 마쳤다 — 고치기 전 두 파일에 돌려 결함 2건을 잡는 것을 확인했다.

요약 섹션은 반드시 `---` 로 닫혀 있어야 한다. 안 닫혀 있으면 스크립트가 위치를 추측하지 않고 멈춘다.

### 6. 포맷 규칙 — 기존 아카이브와 반드시 동일하게

> **이 포맷은 사람만 읽는 게 아니다.** 코드 저장소의 Hermes(슬랙 상주 봇)가 아카이브 md 를
> 정규식으로 파싱해 Q&A 근거로 쓴다. 아래 셋은 **기계가 의존하는 계약**이라 모양을 바꾸면 안 된다.
>
> | 요소 | 모양 | 쓰는 곳 |
> |---|---|---|
> | 메시지 헤더 | 줄 맨 앞 `**YYYY-MM-DD HH:MM · 이름**` (별표 사이에 `*` 금지) | `archive.js` splitMessages — 메시지 단위 분할 |
> | 월 헤딩 | `## YYYY-MM` | `readChannel({month})` — 월별 조회 |
> | 상단 메타 블록 | 파일 첫머리 연속된 `>` 줄 | `channelBrief` — 시스템 프롬프트의 채널 색인 |
>
> 깨져도 **에러가 나지 않는다.** 검색이 조용히 0건이 되고 봇은 "아카이브에 없습니다"라고 답한다.
> 원인 추적이 매우 어려우니, 포맷을 손보면 코드 저장소의 `src/archive.js` 를 함께 고칠 것.
>
> **2026-08-12 부터 `pre-commit` 이 이걸 막는다.** 스테이징된 채널 md 에 `verify_archive.py`
> 를 돌려 계약이 깨졌으면 커밋을 멈춘다. **관문은 「스테이징된 내용」을 본다**(`--from-index`,
> 2026-08-13 부터) — 작업 트리에서 고쳤으면 `git add` 를 다시 해야 반영된다. 반대로 고치다 만
> md 를 옆에 둔 채 다른 것을 커밋하는 것은 안 막는다. 그전에는 디스크를 읽어서, 깨진 판을
> 담고 작업 트리에서만 고치면 **그대로 통과했다**(별개 저장소에서 재현해 확인).
> 그전에는 강제 지점이 **09:00 위생 점검의 보고뿐**
> 이었다 — 문서 md 는 VM 반영 관문·7.5 표·훅 셋이 보는데 대화 md 는 아무것도 안 막아서,
> 여기서 헤더를 깨면 빨라야 다음 날 아침에 드러났다. 건수·기간이 낡은 것도 함께 걸리는데
> 그건 `sync_index.py --all` 한 줄이면 된다 (7·8단계).
> **VM 의 대화 자동 반영에는 안 걸었다** (WHK 결정) — 대화 반영이 통째로 롤백되는 자리를
> 늘리지 않는다.

> **동기화를 마치면 커밋·push 를 둘 다 WHK 승인받고 한다.** Hermes 는 GCP VM 에서 돌고,
> 그 VM 은 저장소를 `git pull` 로만 받는다(15분 간격). push 하지 않으면
> **로컬 아카이브만 새것이고 봇은 계속 옛 자료로 답한다.**
> 동기화 자체는 성공했고 md 파일도 갱신됐으므로 겉으로는 아무 문제가 없어 보인다 —
> 빠뜨렸다는 신호가 어디에도 뜨지 않는 종류의 실수다. 그래서 동기화를 마치면
> **"커밋·push 해야 봇에 반영됩니다"를 반드시 말하고 기다린다.** 말없이 하지도, 말없이 넘어가지도 않는다.
>
> ```
> 동기화 → (요약 대조 승인) → (커밋·push 승인) → git commit → git push → VM 이 15분 안에 자동 반영
> ```
>
> **승인 대기 중에는 커밋·push 하지 않는다.** 원문 반영분과 요약 수정분을 한 커밋으로 묶어야
> 봇이 "새 원문 + 옛 요약" 상태를 보는 구간이 생기지 않는다.
>
> 급하면 VM 에서 `sudo systemctl start hermes-archive-pull` 로 즉시 당겨올 수 있다.
> 다만 "최근·이번 주" 질문은 봇이 `fetch_recent_slack` 으로 슬랙을 직접 조회하므로
> 대체로 아카이브 신선도와 무관하게 답한다.
>
> **예외 하나** (2026-08-06 부터) — 그 도구의 스레드 되짚기는 7일이다
> (`config.json` 의 `limits.qaThreadLookbackDays`. 10단계 감지에 쓰는 30일짜리
> `threadLookbackDays` 와 **다른 키다**). 이 도구가 보는 부모의 나이는 (요청일수 + 되짚기)일이라
> 최대 44일에서 **21일로 줄었다.** 그 사이 스레드에 오늘 달린 답글은 실시간 조회로 안 잡힌다.
>
> 부모가 30일 안쪽이면 다음 07:00 자동 반영이 부모 블록 안에 넣어 하루면 닫힌다.
> **30일보다 오래된 부모는 안 닫힌다** — 자동 반영도 30일까지만 되짚어(아래 10단계와 같은 선)
> 아카이브에 아예 안 들어간다. 그 구멍은 원래부터 있었고 이 도구가 우연히 덮고 있었을 뿐이다.
> 그리고 동기화가 밀려 있으면 그 사이 구간은 아카이브에도 없어 **아무 데서도 안 보인다.**

```markdown
**2026-08-05 14:23 · 강태우**
메시지 본문 그대로. 볼드·불릿·줄바꿈 유지.
`white_check_mark(1), o(2)`
📎 첨부: `파일명.pdf`, `파일명2.hwpx`

> 💬 **스레드 (3) — 한 줄 요약(선택)**
> **└ 2026-08-05 14:30 · 박민수** — 답글 본문
> **└ 2026-08-05 14:35 · WHK** — 답글 본문
>   📎 첨부: `파일.pdf`
```

지켜야 할 것:

- **참여/이름변경 로그는 본문에 넣지 않는다.** `<@U...> 님이 채널에 참여함`, `채널 이름을 "X"에서 "Y"로 변경했습니다`는 파일 하단 **참여 기록** 문단에 한 줄로 합친다.
- **첨부파일은 이 스킬에서 파일명만.** Slack MCP는 바이너리를 base64로만 반환해 큰 PDF를 못 받는다. 실물은 형제 스킬 `doc-archive`가 **Hermes 봇 토큰(`files:read`)으로** 따로 받아 자료 저장소의 `documents/`에 md로 쌓는다. 두 트리를 잇는 것은 **파일명 하나**다 — 봇이 대화에서 이름을 보고 `search` 로 내용을 찾는다.
  **순서는 정확성 요건이 아니다.** `doc-archive` 는 `slack-export/` 를 한 줄도 읽지 않으므로 이 스킬을 기다리지 않아도 된다. 첨부만 밀렸으면 그쪽만 돌리면 되고, 이어서 돌리는 것은 대화와 첨부를 같은 시점으로 맞추려는 편의일 뿐이다.
  **반대 방향으로는 결합이 있다** — VM 의 대화 자동 반영이 커밋 직전 관문에서 `doc-archive` 의 `verify_format.py --all` 을 그대로 돌리고, 실패하면 **그날 대화 반영까지 통째로 롤백한다**(`src/ingest/verify.js` 의 `runGate`). 문서 md 가 깨진 채 push 돼 있으면 이 스킬이 하려던 일도 자동으로는 안 된다.
- **멘션 `<@U01234ABCDE|WHK>`는 `@WHK`로** 풀어 쓴다.
- **URL은 `<https://...|텍스트>` → `[텍스트](https://...)`**로 변환.
- **리액션(이모지 반응)은 아카이브에 넣지 않는다** (WHK 결정 2026-09-03) — 값어치가 없고,
  나중에 붙는 반응이 md 와 슬랙을 계속 어긋나게 한다. `renderMessage`·`renderReply` 둘 다
  안 싣고, 되살아나면 `scripts/check-thread-loss.js` ① 이 막는다.
- ⚠️ **봇이 쓴 것은 Hermes 든 다른 봇이든 아카이브에 넣지 않는다** (WHK 결정 2026-08-12).
  Hermes 답변은 이 아카이브를 읽어서 만든 2차 가공물이라, 넣으면 다음번에 봇이 **자기가 쓴 요약을 원본 근거로**
  삼아 답하고 한 번 잘못 요약한 숫자가 원문처럼 굳는다. `주간 체크인`·`항목 상태 알림` 같은 알림 봇도 함께 뺀다 —
  2026-08-12 까지는 "그건 원문"이라며 넣었고 실제로 11블록이 들어가 있었다(그날 걷어냈다).
  사람이 봇을 호출한 메시지(`@Hermes 최근 논의 정리`)는 남기고 — 무엇을 궁금해했는지는 기록 가치가 있다 —
  답변 자리에는 `💬 스레드 1건 (봇 답변 — 미수록)` 한 줄만 둔다.
  **사람이 앱에게 시켜 자기 이름으로 올린 글도 함께 빠진다** (WHK 결정 2026-08-26). 슬랙은 그것을 그 사람의
  메시지로 표시해서 화면상 사람 글과 구별이 안 되지만, 내용은 AI 가 만든 2차 가공물이라 같은 이유로 뺀다 —
  2026-08-26 #사업장마 에서 29분 사이에 올라온 두 건이 서로 날짜가 달랐다(같은 사업장 둘의 PF만기가
  한쪽은 9/2, 다른 쪽은 8/31). **그러니 슬랙에는 보이는데 md 에 없는 글이 있으면 누락이 아닐 수 있다** —
  본문 끝에 `*다음을 사용하여 보냄*` 이 붙어 있으면 그 경우다.
- **봇 글에 사람 답글이 달렸으면 「자리표시 블록」으로 담는다.** 헤더 `**날짜 시각 · 봇**` 과
  `(봇 발신 — 본문 미수록) · [원문](링크)` 한 줄뿐이고 그 아래에 사람 답글이 들어간다 — 봇의 문장은 한 글자도 안 들어간다.
  **작성자는 봇 이름이 아니라 늘 `봇`** 이다(표시 이름이 바뀌면 같은 글에 블록이 하나 더 생긴다). 어느 봇이었는지는 `[원문]` 으로 연다.
  담는 범위가 갈린다 — **Hermes 글에 달린 답글은 `[정정]` 만**(나머지는 봇 답변에 대한 반응이라 원문 없이는 뜻이 안 통한다),
  **다른 봇 글에 달린 답글은 전부**(알림에 대고 사람끼리 주고받은 업무 내용이다). 사람 답글이 하나도 없으면 블록 자체를 만들지 않는다.
- **봇의 채널 참여 로그**(`Hermes 님이 채널에 참여함`)도 본문에 넣지 않는다. 도입 사실은 `index.md` 팀 구성 표에 한 줄로 있다.

### 6.5. 상단 요약 대조 — 원문만 쌓이면 요약이 조용히 낡는다

여기까지가 **원문 붙이기**다. 각 채널 md 첫머리에는 사람이 쓴 **요약**이 따로 있고, 그건 위 단계들이 건드리지 않는다.
8월말에 PF 추가대출이 실제로 기표돼도 `#사업장나` 표에는 계속 기표 전 `PF대출` 금액이 남는다.
에러가 나지 않으므로 아무도 모른다.

이 단계는 **바뀐 것을 찾아 보고만** 한다. 고치는 건 승인 다음이다.

**대상**: 이번 실행에서 새 메시지가 들어온 채널만. 나머지 채널은 파일을 열지 않는다.
채널의 `summary_reviewed_ts` 이후 메시지가 대조 범위다.

> **VM 자동 반영이 이미 잡아 둔 후보를 되살릴 때** (그날 07:00 DM 을 못 봤거나 지나간 경우).
> 그 DM 은 저장소에 안 남는다 — 자료 저장소의 `hermes-log/` 에는 `qa`·`daily`·`health` 만 있고
> `ingest` 종류가 없다. 대신 **후보를 만든 코드를 그대로 다시 돌리면 같은 목록이 나온다.**
> 자동 반영의 대조 대상은 그날 새로 들어온 원문이고, 그 원문은 07:00 커밋에 그대로 있다:
>
> ```bash
> # 채널별로 그날 붙은 줄만 뽑아 transcript 로 쓴다
> git -C "$DATA" -c core.quotepath=false show --format= -U0 <07:00 커밋> -- <채널 md>
> ```
>
> `+` 로 시작하는 줄(맨 앞 `+` 제거)이 곧 `transcript` 이고, 이것을
> 코드 저장소의 `src/ingest/summary.js` 의 `checkSummaries([{channel, file, transcript}])` 에
> 넘기면 된다. **`-c core.quotepath=false` 를 빼면 한글 파일명이 8진 escape 로 나와 대상이
> 하나도 안 잡히고 조용히 0건이 된다** (2026-08-06 에 실제로 밟았다).
> 되살린 것도 **후보일 뿐이다** — 아래 대조 규칙대로 원문을 다시 열어 확인한다.
> 2026-08-06 에 이 방법으로 7건을 되살렸고, 그중 둘이 원문과 어긋났다(하나를 둘로 적은 것,
> 결론까지 간 건을 「검토 중」으로 적은 것).

**읽는 곳** — 채널 md 첫머리 두 군데:

1. `>` 메타 블록의 `**핵심 쟁점**` 줄 (있는 채널만)
2. 첫 `---` 다음부터 **첫 `## YYYY-MM` 헤딩 전까지**의 요약 섹션.
   큰 채널에만 있다 (`#사업장나`의 `## 자금 구조 요약 (2026-06-29 기준)` 표처럼). 없으면 이 항목은 건너뛴다.

**대조** — 새 메시지가 위 내용과 어긋나는지 본다. 세 가지만 잡는다:

| 유형 | 예 |
|---|---|
| 숫자·일정이 달라짐 | 요약 표는 `PF대출 1,000억`인데 새 메시지에 `1,500억` |
| 새 쟁점 | `핵심 쟁점` 줄에 없는 논의가 시작됨 |
| 끝난 쟁점 | `핵심 쟁점`에 있던 항목이 종결·철회됨 |

> 값은 **원문 메시지를 다시 읽고** 확인한다. 조금 전 만든 요약 문장이나 다른 채널에서 본 숫자로 판단하지 않는다.
> 사업장이 34개고 금액 단위가 비슷해서, 다른 현장 숫자가 흘러드는 게 여기서 가장 흔한 사고다.

**보고 형식** — 9단계 보고에 이어 붙인다:

```
#사업장나 — 상단 요약과 다른 것 2건

1. [자금 구조 요약 표] PF대출 1,000억 → 1,500억
   근거: 2026-08-03 09:12 박민수 "8월말 500억 PF 추가대출 기표 완료"
2. [핵심 쟁점] "입주 정산" 항목 종결 제안
   근거: 2026-08-02 17:40 홍길동 "잔금수금 100% 완료"

반영할 번호를 알려주세요. (전부 / 없음 도 됩니다)
```

- 여기서 **멈춘다.** 답을 듣기 전에는 요약을 한 글자도 고치지 않는다.
- 다른 값이 없으면 이 문단 자체를 내지 않는다.
- 승인받은 번호만 Edit으로 **그 줄만** 고친다. 요약 섹션 통째 재작성 금지.

**반영할 때 지킬 것**

- **원문(월 헤딩 아래)은 절대 건드리지 않는다.** 요약과 원문이 다르면 원문이 맞다.
- 기준일을 함께 갱신한다 — `## 자금 구조 요약 (2026-06-29 기준)` → `(2026-08-03 기준)`.
- ⚠️ **요약 섹션에 줄 맨 앞 `**2026-08-03 …**` 형태를 쓰지 않는다.**
  코드 저장소 `src/archive.js`의 `splitMessages` 헤더 정규식이 `**날짜…**`로 시작하는 줄을 **메시지 한 건으로 자른다** —
  있지도 않은 메시지가 봇 검색에 걸린다. 기준일은 헤딩 괄호나 표 안에 넣는다.
- `핵심 쟁점` 줄은 계속 `>` 로 시작해야 한다. `>` 가 끊기면 그 아래는 `channelBrief`가 못 읽는다.
- **요약 섹션이 없는 채널에 새로 만들지 않는다.** `핵심 쟁점` 줄만 대조한다. 새 요약 섹션은 사용자가 따로 요청할 때만.
- **한 칸에 기준일 하나.** 표의 값들이 서로 다른 시점 기준이 되면 기준일 열을 만들어 행마다 적는다.
  헤딩 괄호에 날짜 하나만 남기면 갱신한 행의 날짜가 나머지 행까지 덮어쓴 것처럼 읽힌다
  (`#사업장나` 표에서 PF대출은 6/29, 중도금대출은 7/15 기준이 됐다).
- **끝나면 요약 섹션이 첫 월 헤딩 위에 있는지 확인한다** — 5단계의 검사 명령을 그대로 돌린다.
  아래로 밀리면 요약이 사람 발언 본문으로 봇에 검색된다.
- **★ `핵심 쟁점` 줄은 채널당 400자를 넘기지 않는다** (WHK 결정 2026-09-21).
  **빼는 일은 손으로 하지 말고 `issue-trim` 스킬로 한다** — 거기에 검증(원본에서 글자를
  빼기만 했나)과 바이트 단위 적용(줄끝 보존)이 있다. 손으로 빼다가 새 문장이 섞이거나
  43개 파일의 줄끝이 통째로 바뀐 것이 그 스킬이 생긴 이유다(2026-09-21).
  **쟁점을 더할 때 그 줄이 400자를 넘으면, 더하기 전에 끝난 쟁점을 먼저 뺀다.**
  빼는 것도 반영이므로 이 절의 승인 절차를 똑같이 탄다 — 조용히 지우지 않는다.
  - **재는 법** — `npm run check` 의 `[3/6]` 이 **채널마다** 재서 넘는 것을 이름과 글자 수로
    보여 준다(`check-setup.js` 의 `ISSUE_LINE_MAX`). 그 옆의 「대화 색인 N자」는 **총합**이라
    채널당 규칙을 못 잰다 — 한 채널이 상한의 세 배여도 총합이 여유 안이면 조용하다
  - **★ 규칙이 생긴 날 이미 14채널이 넘고 있었다** (2026-09-21 실측 — 34채널 중 14개,
    가장 긴 것 1,331자). **이미 넘는 것을 지금 일괄로 줄이지 않는다.** 그 채널의
    `핵심 쟁점` 을 **만지게 될 때** 끝난 쟁점을 빼서 400 이하로 정리한다.
    검사도 **막지 않고 보이기만 한다** — 첫날부터 14건을 막으면 관문이 곧 꺼진다
  - **왜 상한인가** — 이 줄들이 **색인이 자라는 것의 93%**다(2026-09-20 실측).
    한 번 줄이는 것은 30일이면 원위치라, 줄이는 일이 아니라 **넘지 않는 규칙**이어야 한다.
    2026-09-21 에 경고선을 실제로 넘어(30,645자) 사람이 665자를 손으로 줄여 되돌렸다
  - **⚠ 짧게 만든다고 지우면 봇이 채널을 못 찾는다** — 이 줄은 봇이 **어느 채널을 볼지
    고르는 근거**다. 끝난 쟁점을 빼는 것이지 살아 있는 쟁점을 줄이는 것이 아니다.
    400자에 안 들어가면 **줄이지 말고 사람에게 묻는다**

> **왜 `핵심 쟁점` 줄이 특히 중요한가**: 첫머리 `>` 메타 블록은 Hermes 봇의 **시스템 프롬프트에 매 답변마다 통째로 실린다**
> (`archive.js`의 `channelBrief` → `archiveIndexBlock`). 여기가 낡으면 봇이 낡은 색인을 들고 답한다.
> 반면 `## 자금 구조 요약` 표는 `splitMessages`가 첫 메시지 헤더 앞을 버려서 **봇 검색에는 걸리지 않는다** — 사람이 읽는 자리다.

> **대화 색인은 문서 색인과 성질이 정반대다.** `archive.js` 의 `buildArchiveBriefSplit` 은
> **`slack-export/index.md` 전문 + 채널 md 상단 `>` 메타 블록**을 **접기도 상한도 없이**
> 그대로 프롬프트에 싣는다(2026-08-05 실측 18,416자). 문서 색인은 상한을 넘으면 접히지만
> 여기는 안 접힌다. 그래서 셋이 따라온다 —
> ① **`index.md` 를 고치면 봇이 보는 내용이 그대로 바뀐다**(문서 쪽은 각 md 의 메타에서
> 만들어져 `index.md` 를 고쳐도 안 바뀐다). ② `핵심 쟁점` 줄의 길이가 곧 프롬프트 부담이라
> **채널당 400자 상한**이 걸려 있다(위 「반영할 때 지킬 것」). ③ 반대로 **`>` 메타도 아니고 `**날짜 · 이름**` 메시지 블록도 아닌
> 중간 구역**(진행 파이프라인 표 등)은 봇이 프롬프트로도 검색으로도 못 본다 — 사람이 보는
> 자리다. 봇도 알아야 하는 내용이면 `핵심 쟁점` 줄에 넣는다.

### 7·8. 헤더와 index.md — **손대지 않는다. 명령 하나로 다시 계산한다**

채널 md 헤더의 `**기간**`·`**실제 메시지**` 줄과 `index.md` 의 건수 표·섹션 소계·총계·꼬리말
시각은 전부 **파생값**이다. md 파일에서 100% 계산되므로 사람이 정할 것이 없다.

```bash
python .claude/skills/slack-sync/scripts/sync_index.py --all --dry-run   # 무엇이 어긋났나
python .claude/skills/slack-sync/scripts/sync_index.py --all             # 맞춘다
```

**평상시에는 이것도 안 돌려도 된다** — 자동 반영이 회차마다 `src/ingest/derive.js` 로 같은
스크립트를 부른다(2026-08-10 부터). 손으로 돌리는 것은 이 스킬로 뭔가 넣은 직후에 상태를
바로 맞추고 싶을 때뿐이다. 값이 이미 맞으면 파일을 안 건드리므로 몇 번 돌려도 안전하다.

> **계산을 여기 다시 쓰지 말 것.** 두 곳에 두면 갈린다 — 2026-08-10 에 사람이 봇이 보는
> **블록 수**(55)를 세고 코드는 **사람 발언 수**(54, Hermes 자리표시 제외)를 세서 헤더를
> 틀리게 "고쳤다". 정의는 `slack-export/index.md` 「읽는 법」에 한 줄로 적혀 있다.

**기계가 안 하는 것 둘** — 이건 사람 몫이고, 스크립트가 `⚠` 로 알려준다.

- **표에 행을 새로 만들지 않는다.** 3번째 칸(성격)은 판단이고, 🔒 를 잘못 붙이면 비공개
  채널 이름이 전사에 나간다. 새 채널은 `missing_row` 로 뜨니 그때 한 줄 쓴다
- **링크 없는 행·깨진 링크**(`should_link`·`broken_link`·`stale_nonzero`)도 안 고친다

### 9. 상태 파일 저장 + 보고

`.sync-state.json`의 `last_sync`와 각 채널 `last_ts`·`summary_reviewed_ts`·`threads`를 갱신한다.

`summary_reviewed_ts`는 **승인 여부와 무관하게** 대조를 끝낸 지점까지 기록한다.
안 그러면 보류한 건을 다음 실행 때마다 다시 물어보게 된다. 보류한 건은 원문에 그대로 남아 있으니 사라지는 게 아니다.

사용자에게 이렇게 보고한다:

```
슬랙 동기화 완료 (2026-08-05)

새 메시지 12건 / 3개 채널
- #비공개가 6건 — 담보대출 전환 논의
- #사업장나 4건 — PF 기표 일정 확정
- #사업장거 2건 — 일일업무일지

새 스레드 답글 5건 (#비공개가 3, #사업장나 2)
새 채널 없음
요약 대조: 3개 채널, 제안 2건
```

이어서 6.5단계에서 찾은 제안 목록을 붙이고 **답을 기다린다.** 제안이 없으면 `요약 대조: 3개 채널, 다른 값 없음`으로 닫는다.

**새 메시지가 없으면** 파일을 건드리지 말고 "새 메시지 없음"만 알린다.

## 10. 슬랙에서 고쳐지거나 지워진 것을 md 에 반영

여기까지(1~9단계)는 **새 것을 넣는** 일이다. 이 단계는 **이미 들어간 것을 고치거나 지운다.**

슬랙에서 메시지를 편집하거나 삭제해도 아카이브는 그대로다 — 증분 조회는 `ts` 로 거르는데
본문을 고쳐도 `ts` 는 안 변해 다시 조회 범위에 안 들어온다. 자동 반영이 매일 이것을 **찾아서
DM 으로 알리고**(코드 저장소의 `src/ingest/slack-archive.js` 의 `detectChanges`), 고치는 것은 여기다.

> ⚠️ **원문 교체가 허용되는 유일한 경우는 "슬랙 원문 자체가 바뀐 것을 따라가는 것"이다.**
> 6.5단계의 "원문은 절대 건드리지 않는다"는 그대로다 — 사람이 판단해서 내용을 고치는 것은
> 여전히 슬랙 스레드에 `[정정]` 댓글이고, 아카이브 원문은 손대지 않는다.
> 이 둘을 섞으면 아카이브가 "슬랙 그대로"가 아니게 되어 무엇이 근거인지 알 수 없어진다.

### 절차

**① `git pull` 먼저.** 감지 결과는 VM 이 만들어 push 한다. 안 받고 시작하면 없는 파일을 보거나
낡은 목록을 본다.

**② 목록을 보여준다 — `apply_edits.py` 가 번호를 매겨 준다.**

```bash
python .claude/skills/slack-sync/scripts/apply_edits.py
```

```
슬랙에서 고쳐지거나 지워진 것 3건 — 아직 아카이브에 반영 안 됨

#  종류  대상    채널            언제 것                      지금 md 에 있는 내용
1  수정  메시지  #사업장나       2026-08-04 13:08 · 홍길동    중도금대출 2,000억으로 확정했습니다.
2  삭제  메시지  #사업장머       2026-08-03 09:12 · 박민수    보증한도 100억 유지
3  삭제  답글    #사업장사   2026-08-05 12:06 · 홍길동    넵 수정하겠습니다
```

「반영할 것이 없습니다」면 없는 것이다 (감지가 0건이면 자동 반영이 `.pending-edits.json` 을
지운다). **만기가 안 지난 보류는 목록에서 빠지고** 아래에 따로 보인다.

**③ 여기서 멈춘다.** 답을 듣기 전에는 md 를 한 글자도 고치지 않는다.
`--apply` 를 안 붙이면 스크립트도 목록만 찍고 끝난다.

**④ 승인받은 번호만 반영한다.**

```bash
python .claude/skills/slack-sync/scripts/apply_edits.py --only 1,2 --dry-run   # 먼저 본다
python .claude/skills/slack-sync/scripts/apply_edits.py --only 1,2 --apply     # 반영
```

항목의 `before`·`after` 를 그대로 써서 `insert_messages.py` 의 알맞은 모드
(`--replace-body`·`--delete-message`·`--replace-reply`·`--delete-reply`)를 부른다.
**`--expect-file` 에 `before` 를 반드시 넘긴다** — 지금 md 와 대조해 안 맞으면 그 건은
아무것도 안 고치고 멈춘다. 같은 분·같은 사람 헤더가 아카이브에 118건(57곳·파일 20개, 2026-09-22 실측) 있어 헤더만으로는
어느 블록인지 못 고르기 때문이다. **에러가 나면 억지로 우회하지 말고 그대로 보고한다.**

> **`⚠ 손으로` 표시가 붙은 건은 골라도 거부한다.** 본문이 헤더 줄에 있는 「한 줄로 줄여 적은
> 메시지」라 `--replace-body` 가 헤더는 그대로 두고 아래에 본문을 새로 넣는다. Edit 으로
> 「헤더 줄 + 본문 줄」의 정상 형태로 풀어 쓰면 다음 대조에서 저절로 빠진다.

**④-2 이번에 안 할 것은 만기를 붙여 미룬다.**

```bash
python .claude/skills/slack-sync/scripts/apply_edits.py --only 3 --later 14 --reason "판정 불가"
python .claude/skills/slack-sync/scripts/apply_edits.py --clear 1     # 보류 취소
```

만기가 지나면 **저절로 목록으로 돌아오고** 09:00 위생 점검이 다시 알린다. `--reason` 은
필수다 — 왜 미뤘는지가 없으면 다음 사람이 되돌릴 수 없다. 만기 없는 보류는 삭제와 같다
(위키 `[[적어둔-일은-돌아오지-않는다]]`). 보류는 `.sync-state.json` 의 `deferred` 에 적힌다
(`.pending-edits.json` 은 자동 반영이 회차마다 통째로 다시 써서 거기 적으면 지워진다).

**⑤ 헤더 건수는 자동으로 맞는다.** `apply_edits.py` 가 반영 뒤 `sync_index.py` 를 부른다.
손으로 고쳤을 때만 아래를 직접 돌린다.

```bash
python ... --file <채널md> --update-header --count <새 건수>
```

건수를 손으로 세지 말 것. `sync_index.py --all` 이 **전 채널을 다시 세어** 헤더와 `index.md`
표를 함께 맞춘다 (7·8단계 참조).

> **고칠 자리를 못 찾으면 이 명령은 멈춘다**(종료코드 1, 2026-08-10 수정). 예전에는 못 찾아도
> `변경 없음` + 종료코드 0 이라 부르는 쪽이 성공으로 읽고 넘어갔고, 봇 프롬프트에 실리는
> `실제 메시지 N건` 이 **아무 표시 없이 낡았다.** 값이 이미 맞으면 `SKIP 헤더 이미 같음` 이
> 뜨고 파일은 안 건드린다.

**⑥ 봇이 보는 모양이 안 깨졌는지 확인한다.** 검사는 스크립트로 돌린다:

```bash
python .claude/skills/slack-sync/scripts/verify_archive.py --all
```

스레드 머리줄 건수 ≠ 실제 답글 수 · 수집 실패 표식 잔존 · 헤더 건수 · 기간 · 한 줄 압축
메시지 · 스레드 안 인용 빠짐 · `index.md` 를 한 번에 본다. 매일 09:00 위생 점검도 같은
스크립트를 돌려 결함이 있을 때만 DM 을 보낸다. 이어서 5단계의 `splitMessages` 검사도 돌린다.
지운 내용이 실제로 검색에서 빠졌는지도 본다:

```bash
node --input-type=module -e "
import {searchArchive} from './src/archive.js';
import {FULL_ACCESS} from './src/config.js';
const {hits} = searchArchive({query: '지운 메시지의 특징적인 문구', access: FULL_ACCESS});
console.log(hits.length, '건');"
```

> ⚠️ **인자 모양을 지킬 것.** `searchArchive` 는 **객체 하나**를 받고 **`{hits, note}` 객체**를 돌려준다.
> 예전에 여기 적혀 있던 `searchArchive('문구', {}).length` 는 문자열을 넘기고 배열처럼 `.length` 를
> 읽어서, 실제로 있는 문구를 넣어도 **에러 없이 늘 `undefined`** 가 찍혔다. 0 과 구별이 안 되니
> "지워진 게 맞다"로 읽히는데, 확인한 적이 없는 것이다.
> `access` 도 반드시 넘긴다 — 빼면 fail-closed 로 비공개 채널이 통째로 빠져 역시 0 처럼 보인다.
> **0 이 나왔다면 없는 문구로 한 번 더 돌려 0 이 나오는지 대조한다.** 두 값이 같으면 검사가
> 아니라 고장이다.

**⑦ 커밋·push 를 각각 승인받는다.** 반영분이 push 돼야 봇이 고쳐진 문장을 본다.
반영에 **성공한** 건은 `apply_edits.py` 가 `.pending-edits.json` 에서 그 자리에서 뺀다
(남은 것이 없으면 파일을 지운다). 그래서 **커밋에 이 파일의 변경·삭제가 함께 들어간다** —
빼먹으면 다음 07:00 까지 09:00 점검과 상황판이 이미 반영한 건을 「미반영 N건」으로 알린다.
**작업 트리를 커밋하지 않고 두면 다음 자동 반영이 통째로 멈춘다.**

### 알아둘 것

- **`manual: true` 인 항목은 스크립트로 고치지 않는다.** 한 줄로 줄여 적은 메시지
  (`**2026-07-30 07:30 · 최지훈** — 7/29 일일업무일지 …`, 38건)는 본문이 헤더 줄에 있어
  `--replace-body` 가 엉뚱하게 동작한다(헤더 줄은 그대로 둔 채 아래에 본문을 새로 넣는다).
  Edit 으로 그 줄을 **헤더 줄 + 본문 줄**의 정상 형태로 풀어 쓴다. 그러면 다음 대조에서 저절로 빠진다
- **`중복`(kind: ambiguous) 항목도 스크립트로 안 고친다** (2026-09-22 갈래 ③). 같은 1분에
  글이 여럿이라 기계가 어느 블록인지 못 고르는 건이다 — 그 분의 md 블록을 슬랙 원문과
  직접 대보고 고치면 다음 대조에서 저절로 빠진다. 이 항목이 있는 동안 감지가 그 분을
  기준 시각과 무관하게 매 회차 다시 대조하므로, 예전의 기준-동결 래치와 「매일 다시
  알립니다」 반복 문구는 이 갈래에서 없어졌다
- **날짜가 없는 옛 답글**(`> **└ WHK** —`, 167건)은 대조 대상이 아니다. 초기 수기 추출분이라
  어느 답글인지 특정할 수 없다. 새로 쌓이는 답글은 전부 날짜가 붙으므로 시간이 지나면 줄어든다
- 감지 범위는 **최근 30일**(`config.json` 의 `limits.threadLookbackDays` — 이름이 비슷한
  `qaThreadLookbackDays`(7일)는 봇 Q&A 전용이라 **여기와 무관하다**). 그보다 오래된 것을
  고치면 안 잡힌다
- **대조는 작성자 이름을 안 본다. 「몇 시 몇 분에 있던 메시지」로만 맞춘다.** 슬랙 표시 이름은
  언제든 바뀌는데 md 에는 기록 당시 이름이 박혀 있어서, 이름을 대조에 쓰면 이름 한 번 바꾼
  사람의 30일치가 전부 "지워졌다"로 잡힌다.
  대신 **같은 1분 안에 메시지가 둘 이상이면 그것들은 대조에서 빠진다.** 헤더가 분 단위까지만
  적혀 있어 서로 구별할 방법이 없기 때문이다 (2026-09-16 실측: 아카이브 1,842건 중 188건,
  10.2%. 겹치는 자리는 89곳이고 그중 45곳이 서로 다른 사람끼리다. **잰 날짜를 같이 적는다** —
  아카이브가 커지면 바뀌는 값이라, 날짜가 없으면 낡은 줄 모르고 계속 인용된다).
  빠진다는 것은 "지워졌다·고쳐졌다"고 말하지 않고
  손을 뗀다는 뜻이라, 틀린 지시가 나가는 대신 못 잡고 지나간다
- **한 채널에서 10건이 넘게 잡히면 목록 대신 경고만 나온다**(`limits.editScanMaxFindings`).
  하나씩 지워진 것이 아니라 슬랙 보존 기간이 짧아졌거나 아카이브 포맷이 어긋난 경우다.
  그런 경고가 오면 반영하지 말고 원인부터 찾는다

## 주의

- **한 번에 45개 채널을 다 읽지 않는다.** 증분이므로 대부분 빈 응답이다. 그래도 채널 수가 많으니 `slack_read_channel` 호출은 **8~10개씩 병렬**로 묶어 보낸다.
- 응답이 너무 커서 잘리면(`exceeds maximum allowed tokens`) 그 채널만 `limit`을 낮춰 다시 읽는다.
- 며칠 밀렸다가 실행하면 메시지가 많을 수 있다. 100건을 넘으면 커서로 이어 읽되, 사용자에게 "N일치가 밀려 있었습니다"라고 알린다.
- **덮어쓰기 금지.** 기존 md는 Edit으로 삽입만 한다. Write로 통째 재생성하지 않는다.

## 관련

- 전체 재추출이 필요하면 이 스킬이 아니라 사용자에게 별도 요청을 받는다.
- 아카이브를 지식으로 넘기려면 `wiki-ingest`.
- 첨부파일 실물과 그 내용이 필요하면 `doc-archive` 스킬. 봇 토큰으로 내려받아 md로 변환하며, Slack 관리자 export는 필요 없다.
