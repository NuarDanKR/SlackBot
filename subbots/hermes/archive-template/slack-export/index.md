# Slack 대화 아카이브

> **워크스페이스**: `<워크스페이스>.slack.com`
> **추출일**: <YYYY-MM-DD> · **대상 기간**: <YYYY-MM-DD> ~ <YYYY-MM-DD>
> **채널**: 총 0개 (공개 0 + 비공개 0)
> **범위**: **대화 내용만**. 첨부파일 실물은 내려받지 않고, 메시지 안에 `📎 첨부: 파일명`으로만 남깁니다.

---

## 읽는 법

- 각 채널은 `channels/{채널명}.md` 한 파일
- 메시지는 **최신 → 과거** 순 (Slack 표시 순서와 동일)
- `📎 첨부:` = 그 메시지에 올라온 파일 (실물 없음, 파일명만)
- `> 💬 **스레드 (N)**` = 스레드 답글 본문
- `💬 스레드 N건` = 답글 본문 없이 표시만 남긴 스레드 (하단 "3. 스레드" 참조)
- **`[정정]` 으로 시작하는 답글 = 그 메시지의 내용을 고치는 것.** 원문보다 우선한다. 원문은 슬랙 그대로 두고 고치지 않으므로, 같은 블록 안에 틀린 값과 고친 값이 함께 있다. 인용할 때는 정정된 값을 쓰고 정정 날짜를 밝힌다
- **`(봇 발신 — 본문 미수록)` = 봇이 올린 글의 자리표시.** 봇 글은 Hermes 든 `주간 체크인` 같은 알림 봇이든 아카이브에 넣지 않으므로 본문이 없고, 거기 달린 사람 답글만 담겨 있다(옆의 `[원문]` 은 사람이 열어 볼 링크 — 어느 봇이었는지도 그 링크로 연다). 근거로 쓸 수 있는 것은 그 답글 문장뿐이다. 헤더 작성자는 봇 이름이 아니라 늘 `봇` 이다 — 슬랙 표시 이름이 바뀌어도 같은 블록을 계속 찾을 수 있게 (WHK 결정 2026-08-12: 그전에는 Hermes 만 뺐고 다른 봇 글은 본문째 들어 있었다)
- **`**실제 메시지**: N건` = 슬랙에 사람이 올린 메시지 수.** 위의 봇 자리표시 블록은 **세지 않는다** — 봇 글 자리를 세면 그만큼 부풀려 말하게 된다. 스레드 답글도 세지 않는다(메시지가 아니라 답글이다). 세는 코드는 코드 저장소의 src/ingest/slack-archive.js 한 곳이고, 손으로 셀 때도 이 정의를 따른다 (2026-08-10: 사람이 봇이 보는 **블록 수**를 세어 `#<채널>` 를 54 → 55 로 잘못 고쳤다. 정의가 적혀 있지 않아 갈렸다)
- **참여 기록**은 각 파일 하단에 한 문단으로 요약 (원본의 "님이 채널에 참여함" 로그를 압축)
