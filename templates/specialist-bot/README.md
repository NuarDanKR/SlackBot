# TYBot 전문 봇 시작 템플릿

이 디렉터리는 새 **독립 Git 저장소**를 만들 때 복사하는 시작점이다. 마스터 TYBot
저장소 안에서 이 디렉터리를 직접 개발하거나 별도 `.git`을 만들지 않는다.

현재 지원 범위는 `prompt-contract`다. 전문 봇은 TYBot이 권한 필터를 끝낸 근거에 적용할
프롬프트와 판정 규칙을 제공한다. Slack, DB, 원문 아카이브를 직접 조회하거나 출처를
붙이지 않는다. HTTP 서비스형 전문 봇은 아직 마스터 어댑터와 격리 배포기가 준비되지
않았으므로 이 템플릿의 범위가 아니다.

## 시작하기

1. 이 디렉터리의 내용을 회사 Git의 새 비공개 저장소로 복사한다.
2. `tybot-specialist.toml`의 `key`, 이름, 분야, 버전을 수정한다.
3. `contract/prompts/system.md`에 전문 분야의 규칙을 작성한다.
4. `contract/tests/cases.json`에 실제 업무 내용이 아닌 계약 테스트 사례를 추가한다.
5. `python scripts/validate_contract.py`를 실행한다.
6. 변경을 커밋하고 불변 릴리스 태그를 만든다.
7. TYBot 콘솔의 `전문 봇 관리`에서 공개 GitHub 저장소 URL과 릴리스 태그를
   입력해 계약을 가져온다. `latest`를 쓰려면 태그뿐 아니라 GitHub Release도 게시한다.
   태그를 직접 입력하는 경우에는 불변 태그만 있으면 된다.
8. TYBot 관리자가 계약 결과와 적용 범위를 확인해 승인한다.

Git을 사용할 수 없는 전달 경로에서는 `tybot-specialist.toml`과 `contract/`만 ZIP으로
묶어 콘솔의 `계약 ZIP`에서 올릴 수 있다. ZIP에는 소스 코드, `node_modules`, 시크릿,
추가 문서를 넣지 않는다. ZIP 전체와 계약 파일별 해시는 승인 기록에 남는다.

콘솔은 저장소 코드를 체크아웃하거나 실행하지 않는다. 태그로 고정된 매니페스트와
`contract/`의 선언된 일반 파일만 임시 bare clone에서 읽고, 크기·경로·계약 테스트와
SHA-256 해시를 검증한다. 승인 요청 시 같은 태그를 다시 읽어 미리보기와 일치하는지도
검사한다.

## 절대 경계

- 입력은 TYBot이 전달한 질문과 권한 필터 완료 근거뿐이다.
- 출력은 답변 문장뿐이다. `출처:` 또는 Slack·파일 링크를 반환하지 않는다.
- 원문, 질문, 응답을 전문 봇 저장소나 자체 데이터베이스에 저장하지 않는다.
- 토큰, API 키, 운영 URL을 저장소에 넣지 않는다.
- 실패, 시간 초과와 낮은 신뢰도에서는 TYBot 마스터가 직접 답한다.
