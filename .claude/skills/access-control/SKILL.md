# 접근 제어 — 멀티 워크스페이스

중앙 아카이브를 모든 봇이 공유하므로, 본부/팀별 분리의 의미가 **권한 필터**로만 유지된다. 여기가 뚫리면 팀 봇이 타 조직 기밀을 노출한다.

## 원칙
1. **막는 쪽이 기본값** — 문서/채널에 `[공개]`가 없으면 비공개.
2. **답변 생성 전에 권한 필터** — 요청자의 워크스페이스/채널 멤버십으로 검색 범위를 먼저 좁힌다. 사후 필터 금지(모델이 이미 본 뒤엔 늦다).
3. **크로스 워크스페이스는 화이트리스트만** — 팀 봇은 자기 워크스페이스만 기본 조회. 경영진 통합조회는 별도의 상위 워크스페이스/역할에만 명시적으로 허용.
4. **권한 없음은 존재도 숨긴다** — "열람 권한이 없습니다"만, 채널명·문서명도 노출하지 않음.
5. **공개 전환은 단일 통로** — Slack 원문 스레드에 `[공개]` 댓글. 그 외 경로로 visibility 변경 금지.

## ACL 모델(예)
- 아카이브 파일 프론트매터: `visibility`, `acl: [허용 코드...]`.
- 요청 컨텍스트: `requester_workspace`, `requester_channels`, `role`.
- 판정: `visibility==public` 또는 (`requester` ∈ `acl`) 일 때만 검색 대상.

## 감사
- 모든 조회의 (요청자, 접근한 파일, 판정)을 로깅.
- 정기적으로 "권한 없이 접근 시도" 리포트 검토.

## 흔한 사고
- 새 채널/워크스페이스에 ACL 미설정 → **비공개로 폴백**(새는 쪽 아님).
- 설정 누락 시 열리는 방향의 코드는 리뷰에서 반려.
