## 0. API 키 전달 — 채팅으로 붙여넣지 말 것
- 키는 **네 로컬 `.env`** 에만. 대화창/이슈/커밋에 붙이면 유출로 간주하고 즉시 폐기·재발급.
- 이 저장소는 3중으로 막아둠: `.gitignore`(`.env`), `.claude/settings.json`의 `Read(./.env)` deny, `.claude/hooks/guard.py`의 토큰 패턴 차단.
- 값 확인은 마스킹 스크립트로만: `python scripts/check_env.py` (앞 6자·뒤 4자만 출력 → 그 출력은 공유해도 안전).

```bash
cp .env.example .env      # 자리표시자 복사
# .env 를 편집기로 열어 값 채우기 (SLACK_BOT_TOKEN / SLACK_APP_TOKEN / ANTHROPIC_API_KEY)
```

## 1. Slack 앱 생성
1. https://api.slack.com/apps → **Create New App → From an app manifest**
2. 파일럿 워크스페이스 선택 → [`slack-app-manifest.yaml`](slack-app-manifest.yaml) 내용 붙여넣기
3. **Basic Information → App-Level Tokens → Generate**: 스코프 `connections:write` → `xapp-...` = `SLACK_APP_TOKEN`
4. **Install to Workspace** → `xoxb-...` = `SLACK_BOT_TOKEN`
5. 테스트 채널에서 `/invite @tybot` — **초대 안 하면 그 채널은 수집·조회 대상에서 빠진다**

## 2. 실행
```bash
python -m venv .venv && .venv/Scripts/activate      # Windows
pip install -e ".[dev]"
python scripts/check_env.py                          # 전부 ✓ 인지 확인
python -m tybot.slack.pilot
```
> 봇 프로세스는 **한 곳에서만** 기동. 두 곳에서 켜면 중복 답변 + LLM 비용 2배.

## 3. 사용법
| 입력 | 동작 |
|---|---|
| (아무 채널 대화) | **실시간 자동 수집** — 봇이 초대된 채널 메시지를 즉시 원문 append |
| `@tybot 전체수집` | 봇이 볼 수 있는 모든 채널 백필. 공개 채널은 자가참여, 비공개는 초대 필요 목록 반환 |
| `@tybot 수집` | 그 채널 최근 15건 + **스레드 답글**(최대 5개 스레드) 백필 |
| `@tybot 상태` | 채널별 원문 줄 수 / 형식 위반 / 실시간 수집 ON·OFF |
| `@tybot 현재 너의 상태 어때?` | **LLM 분류**가 봇 상태 질문으로 판단 → 연결·수집 현황 (LLM 답변 생성 없음) |
| `@tybot 현재까지 상황 요약해줘` | 기간 스캔 → 채널별 정리 + 출처 |
| `@tybot 이번주/30일/2주 진행상황` | 기간 표현 인식 (기본 7일, 최대 365일) |
| `@tybot 김해외동 기성금 얼마야?` | 핵심어(`김해외동`,`기성금`)만 뽑아 원문 검색 → 답변 + 출처 |
| `@tybot 채널을 잘게 쪼개는 게 나아?` | **판단·권고 요청** → 관련 원문이 있으면 근거로, 없으면 `일반적인 판단` 라벨을 붙여 답변 |
| (검색 0건일 때) | **추측하지 않는다.** 문서 목록 + 다음 행동 안내만 |
| `@tybot --model=claude-opus-4-8 질문` | 모델 지정 |
| 봇에게 DM | 동일 (채널 멤버십 기준 권한 적용) |

### 의도 분류는 LLM 이 한다
정규식으로 자연어를 가르면 표현이 바뀔 때마다 샌다("상태" vs "너의 상태" vs "잘 돌아가?").
질문이 오면 먼저 **저가 모델(Haiku)로 분류**한다 — 질문당 약 $0.0003.

| 분류 | 처리 |
|---|---|
| `status` / `help` | 봇 런타임 정보로 즉답 (아카이브·LLM 답변 생성 없음) |
| `summary` | 기간 스캔 후 채널별 정리 |
| `search` | 추출된 **핵심어**로 원문 검색 (요청 표현 `알려줘` 등은 검색어에서 제외) |
| `advice` | 판단·권고. 관련 원문이 있으면 근거로 인용, 없으면 일반 판단임을 명시 |
| `smalltalk` / `out_of_scope` | 짧게 안내. LLM 답변 생성 없음 |

- 분류기는 **답을 만들지 않는다.** 라우팅과 검색어 추출만 한다.

#### 사실과 판단의 경계 (advice 경로)
"출처 없으면 답하지 않는다"는 **사실 조회**의 규칙이다. "어느 방향이 나을까"는 사실 조회가 아니라
판단 요청이라, 같은 규칙을 적용하면 아무 답도 못 한다. 그래서 경로를 나눈다.

| | 사실 (search/summary) | 판단 (advice) |
|---|---|---|
| 근거 | 아카이브 원문**만** | 원문 우선 + 일반 지식 허용 |
| 사내 수치·조직·결정사항 | 원문 그대로만 | **원문 없으면 단정 금지** (프롬프트로 강제) |
| 출력 표시 | 출처 목록 | `💬 판단 요청으로 답합니다` + 원문 없으면 `일반적인 판단입니다` 라벨 |
| 라벨 부착 주체 | — | **코드**가 붙인다 (LLM 이 빼먹을 수 있는 것을 원칙에 맡기지 않음) |

권한 필터는 판단 경로에도 동일하게 적용된다 — 열람 권한 없는 채널 원문은 판단 근거에도 안 들어간다.
- 분류 실패·API 장애 시 **정규식 폴백**으로 자동 전환된다(봇이 멈추지 않음). 로그의 `intent kind=… src=regex` 로 확인.
- `수집`/`전체수집` 은 분류를 거치지 않는 **명시 명령**이다 — LLM 판단으로 수집이 트리거되면 안 되기 때문.

### 수집 범위 — 알아야 할 3가지
1. **실시간이 본선.** Slack이 2025-05 이후 생성된 비-마켓플레이스 앱의 `conversations.history` 를
   **분당 1요청 / 회당 15건**으로 제한한다. 과거 대화 대량 백필은 사실상 불가.
   대신 `message.channels`/`message.groups` 이벤트로 앞으로의 대화를 전부 잡는다.
2. **비공개 채널은 초대 필수.** 봇은 초대되지 않은 비공개 채널을 목록조차 볼 수 없다(Slack 설계).
   `전체수집` 이 "초대 필요" 목록을 뽑아주니 그 채널들에서 `/invite @tybot`.
### 수집 경로 세 가지 — 언제 무엇이 쓰이나
| 경로 | 담당 범위 | 한계 |
|---|---|---|
| **실시간**(기본) | 봇이 초대된 뒤의 모든 대화·첨부 | 초대 이전 과거는 못 본다 |
| **정기 배치**(`tybot-collect.timer`) | 봇 재시작·단절 구간 메우기 | 채널당 매시 15건, 스레드 답글 제외 |
| **수동 `수집`** | ① 새로 초대한 채널의 최근 대화<br>② **스레드 답글**(다른 두 경로가 놓치는 부분)<br>③ 권한·쓰기 동작 확인 | 요청당 15건, 스레드 5개 |

수동 `수집` 이 여전히 필요한 이유는 ②다. `conversations.history` 는 **스레드 답글을 주지 않는다.**
실시간 수집은 답글을 잡지만, 봇이 없던 기간의 답글은 `conversations.replies` 로만 가져올 수 있고
그걸 호출하는 건 수동 `수집` 뿐이다.

3. **답변 범위는 질문자 권한.** 질문자가 멤버인 채널만 근거로 쓴다. 전 채널 통합조회가 필요하면
   `.env` 의 `EXEC_USERS` 에 Slack user id 를 넣는다 — **채널 멤버십 필터를 우회하므로 최소 인원만.**
   (user id 확인: Slack 프로필 → 더보기 → 멤버 ID 복사)

## 4. 파일럿 합격 기준
- [ ] 아카이브에 있는 사실 → 정확히 답하고 `출처:` 가 붙는다
- [ ] 아카이브에 **없는** 사실 → 지어내지 않고 "근거 못 찾음 + 문서 목록"을 준다
- [ ] 초대되지 않은 채널 내용 → 채널명조차 노출되지 않는다
- [ ] 봇 답변이 아카이브 원문에 되먹임되지 않는다 (`## 원문` 에 봇 발언 없음)
- [ ] 주민번호/등기부등본 포함 메시지는 저장되지 않는다

## 5. 파일럿에서 의도적으로 안 한 것
| 항목 | 이유/다음 단계 |
|---|---|
| GitHub 중앙 아카이브 + 15분 pull | 로컬 `archive/` 로 먼저 검증 → 통과 후 비공개 저장소 연결 |
| 첨부(파일) 수집·변환 | `files:read` 스코프만 확보. 변환 파이프라인은 다음 단계 |
| 스레드 답글 수집 | 최상위 메시지만. `message.channels` 는 스레드 답글도 오지만 부모 연결은 미구현 |
| 정기 스케줄(일일요약 17:30, 밀림 알림) | 지금은 `@tybot 요약` 수동 트리거 |
| 멀티 워크스페이스 / `team_id → xoxb` 매핑 | 파일럿은 단일 토큰 |
| 검색 방식 | 키워드 매칭. 임베딩/BM25 는 원문량 늘어난 뒤 |
| 단일 인스턴스 락 | 지금은 운영 규칙으로 대체 |
