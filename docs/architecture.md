# TYBot 아키텍처 설계

_버전 0.1 · 2026-08-19 · Slack AI TFT_

## 1. 배경과 목표
- 기존 **Hermes**(단일 워크스페이스 `tec-wmo6240`)를 **본부/팀별 멀티 워크스페이스 + 중앙 MD 아카이브 + 멀티 LLM**으로 확장.
- 목표: "채팅 도구"가 아니라 **업무 Context 자산화 → AI 분석 → Direct 보고** 체계.
- 계승할 검증된 설계: Socket Mode 아웃바운드, 원문 보존, 출처 강제, 4겹 환각방지, 무료등급 GCP 서버.

## 2. 전체 구조
```
 워크스페이스 A(본부)  워크스페이스 B(팀)   워크스페이스 C(현장)
        │봇                │봇                 │봇
        └────────┬─────────┴─────────┬─────────┘
                 ▼                    ▼
        [수집 파이프라인]      [질의응답 라우팅]
                 │                    │
                 ▼                    ▼
        ┌─────────────────────────────────────┐
        │  중앙 서버 (DMZ, GCP e2-micro 급)     │
        │  - 중앙 MD 아카이브 (GitHub 비공개)    │
        │  - LLM 게이트웨이 (모델 라우팅/비용)   │
        │  - 접근제어(ACL) / 감사 로그          │
        └───────────────┬─────────────────────┘
                        │ (읽기전용, 화이트리스트)

             내부망 레거시: EP / OracleDB
             (일정·회의실·결재알림)
```

## 3. 핵심 컴포넌트
### 3.1 워크스페이스 봇 (Slack 연동)
- Socket Mode. 이벤트는 `app_mention`, `message.im` 만 수신.
- 새 채널 → `/invite @tybot` 가 첫 액션(초대 누락 시 요약/실시간 조회 제외).
- 첨부 다운로드 권한, 채널 자가참여 권한 필수(없으면 조용히 고장).

### 3.2 수집 파이프라인 (자산화)
- 대화 자동 취합 07:00 / 17:00, 밀림 알림 09:00 / 16:00, 일일요약 17:30, 주간정리 금 16:00.
- **원문만** 아카이브에 저장(요약은 별도 섹션, 봇 수정 금지).
- 저장 경로: `archive/channels/<workspace>/<channel>.md` (스키마: `.claude/skills/md-archive-schema`).
- 게시 전 형식 검사, 실패 시 그날 취합 롤백. 문서 변환(pdf/한글/워드)은 사람이 승인 후.
- 엑셀·이미지·도면은 현재 미변환 → 색인 「변환하지 못한 것」에 기록.

### 3.3 LLM 게이트웨이 (우선 구현)
- 모든 LLM 호출의 단일 진입점. `src/tybot/gateway/`.
- 기능: 프로바이더 추상화, **모델 선택**, **민감도별 라우팅**(기밀은 지정 벤더만), **비용 가드**, 사용 모델·토큰·비용·근거 로깅.
- 사용자 지정: Slack에서 `@tybot --model=claude-opus-4-8 질문...` 또는 기본 라우팅.

### 3.4 접근 제어 (ACL)
- 파일 프론트매터 `visibility` / `acl`. **답변 생성 이전에** 요청자 워크스페이스/채널 멤버십으로 검색 범위 축소.
- 크로스 워크스페이스는 화이트리스트(경영진 통합조회 상위 워크스페이스만).
- 미설정 → 비공개 폴백. 권한 없음은 채널명도 숨김.

### 3.5 레거시 커넥터
- 읽기 전용 DB 계정. 결재는 알림만. DMZ→내부망 단방향·화이트리스트.

## 4. 데이터 흐름 (질의응답)
1. 사용자가 채널/DM에서 봇 호출
2. 봇 → 요청자 권한 컨텍스트 구성 → ACL로 검색 범위 축소
3. 아카이브 원문 검색(색인은 위치 힌트일 뿐, 반드시 원문 열람)
4. LLM 게이트웨이로 요약/분석 요청(모델 선택·비용 체크)
5. 출처 부착해 응답. 검색 0건이면 해당 사업장 문서 제목 목록 반환
6. 질문·답변·근거를 감사 로그에 기록

## 5. 환각 방지 4겹
`.claude/skills/hallucination-guard` 참조. 근거 오염 금지 / 답 전 원문 열람 / "없다" 남용 금지 / 사람이 잡을 수 있게 출처·로깅.

## 6. 보안 경계
- 인바운드 포트 없음(Socket Mode). 관리자 접속은 클라우드 내부 경로(IAP)만.
- 시크릿은 서버 설정 파일/시크릿 매니저만. 저장소는 읽기 흐름과 분리.
- 봇 토큰·앱 토큰·LLM 키는 저장소에 올라가지 않음.

## 7. 비용
- 서버 사실상 $0(무료등급). 지출은 LLM 사용료. 요청당/일별 상한 + 캐싱 + 단순질의 다운시프트.

## 8. 미해결/결정 필요

- [ ] 크로스 워크스페이스 통합조회를 상위 워크스페이스로 할지, 별도 조회 UI로 할지
