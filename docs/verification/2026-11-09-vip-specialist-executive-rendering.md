# VIP 전문봇 답변의 경영진 후처리 — 독립 계약 검증

대상: `ca1cbde` *feat: format VIP specialist answers for executives*
범위: 독립 계약시험 `tests/test_vip_specialist_rendering.py` 추가 + 이 문서.
**제품 코드는 수정하지 않았다.** `tests/test_vip_profile.py`(Codex)도 건드리지 않았다.

## 0. 무엇이 없었고 무엇이 생겼나

직전 검증에서 보고한 구멍이다 — 전문봇이 성공하면 엔진은 `text = special.text` 로
**그대로 받아 쓰고 모델을 부르지 않았다.** `EXECUTIVE_APPENDIX` 는 `AnswerPrompts`
를 통해서만 전달되고 그 프롬프트는 마스터가 문장을 *만들 때*만 쓰이므로, VIP 에서
전문봇 답만 평문으로 나갔다. 같은 질문에 마스터 답은 경영진 형식, 전문봇 답은
아닌 상태였다.

`ca1cbde` 가 한 단계를 더했다.

- `AnswerPrompts.specialist`(기본값 `None`) 신설
- `vip_profile` 만 그 자리를 채운다 — `SPECIALIST_EXECUTIVE_PROMPT` +
  `EXECUTIVE_APPENDIX`, 리비전 `vip-executive-v1` → **`v2`**
- `AnswerEngine._render_specialist_answer()` 가 전문봇 문장을 한 번 다시 쓴다
- 호출부 **네 곳**: `summarize()` · `advise()` · `answer()`(빈 seed) ·
  `answer()`(근거 있음)
- `advise()` 의 hermes 임시 판단은 `and not specialist_rendered` 로 **겹치지 않게** 했다

## 1. 검증한 계약 10가지

전부 **실제 엔진을 지나가며** 본다(`ArchiveStore` 실파일 + 기록형 프로바이더).
단위시험이 `_render_specialist_answer` 를 홀로 보는 것과 다른 층이다 — 호출부가
하나라도 빠지면 그 경로만 평문으로 나가고 단위시험은 그것을 못 본다.

| 2 | `summarize()` 전문봇 성공 경로 | 통과 |

| 6 | 렌더링 **전** ACL 위반 차단 · LLM 호출 0회 | 통과 |

### 설계상 중요한 세 지점

**(가) 출처는 렌더링을 통과하지 않는다.** `citations` 는 렌더링 **전에**
`_specialist_citations` 가 확정하고, 렌더링 함수는 텍스트와 질문만 받는다.
시험은 두 방향으로 친다 — 렌더링한 답과 안 한 답의 `citations` ·
`EvidenceRef` · `attachment_refs` · `hit_count` 가 **글자까지 같은지**(문장만 다름),
그리고 **출처 문자열이 모델에 간 메시지 어디에도 없는지**. 모델이 출처를 못 보면
출처를 고칠 수도 없다 — 가장 싼 방어다.

**(나) 실패는 답을 버리지 않는다.** timeout·상한 초과·빈 출력 셋 다
`(원문, 전문봇 모델, 전문봇 비용)` 으로 되돌아간다. 모델 이름까지 되돌리는 것이
중요하다 — 실패한 호출의 모델이 남으면 감사기록이 「누가 답했나」 를 틀리게 말한다.
복귀 경로에서도 좌표가 그대로인지 따로 본다.

**(다) ACL 은 렌더링보다 앞이다.** 순서가 뒤집히면 보이면 안 되는 내용이 경영진
형식으로 **한 번 더 쓰여 모델 제공자에게 나간다.** 답을 안 보내도 그 전송은 이미
일어난 뒤다. 시험은 `provider.calls == []` 로 「전송 자체가 없었음」 을 단언한다.

### hermes 중복에 대해

렌더링과 임시 판단을 둘 다 붙이면 같은 답에 판단이 두 번 들어가고 호출도 두 번
든다. 더 나쁜 것은 **두 판단이 다를 수 있다**는 점이다 — 어느 쪽이 봇의 입장인지
읽는 사람이 알 수 없다. 반대로 TYBot 에서는 임시 판단이 **그대로 남아야** 한다
(렌더링이 없으므로). 두 방향을 각각 시험으로 박았다.

## 5. 2026-11-09 후속 보호 로직

위 4-1의 위험은 더 이상 전적으로 프롬프트에만 의존하지 않는다.
`AnswerEngine._render_specialist_answer()` 는 렌더링 전후의 숫자·날짜·금액·비율·수량
토큰을 다중집합으로 비교한다. 값의 변경·추가·삭제·중복이 하나라도 있으면 렌더링을
폐기하고 근거가 있는 전문봇 원문으로 복귀한다. 목록 번호는 사실값이 아니므로 비교에서
제외한다.

렌더링 결과에 `출처:` 또는 `source:` 가 생겨도 폐기한다. 전문봇 원문에 같은 표기가
들어 있으면 fallback 에서 해당 줄을 제거한다. 실제 출처는 계속 엔진이 보존한
`citations`·`EvidenceRef` 만 사용한다.

이 검사는 수치 사실과 출처 위조를 결정적으로 막는다. 기관명·사람 이름 같은 비수치
고유명사의 의미 동일성은 아직 프롬프트 계약과 원문 좌표 검증에 의존한다. 보호 로직을
포함한 대상 pytest 와 전체 pytest 는 안정된 작업 트리에서 다시 실행해야 한다.

## 4. 남은 것 — 설계 판단이 필요한 두 가지

### 4-1. 수치·출처는 강제하며 비수치 고유명사는 아직 강제하지 않는다 (중간)

숫자·날짜·금액·비율·수량은 렌더링 전후 다중집합 비교로 강제하고 모델이 만든 출처
표기도 거절한다. 조직·기관·사람 이름 같은 비수치 고유명사는 아직 프롬프트 계약과
원문 좌표 검증에 의존한다.

출처는 안전하다 — 좌표는 렌더링을 통과하지 않으니 **출처를 눌러 확인할 수 있다.**
확인하면 어긋난 것이 드러난다. 다만 그 확인은 사람이 해야 한다.

저장소에는 이미 비슷한 자리에 방어가 있다 — `canvas_harness` 는 표 단위 변환을
**결정적 코드**로 하고 확신이 없으면 원문을 둔다(설계 §5), 그 주석은 「프롬프트로
형식을 맞췄다고 치지 않는다 — 실제로 같은 표 안에서 `억` 과 `백만원` 이 섞여
나왔다」 고 적고 있다. 같은 경험이 여기에도 적용될 수 있다. 최소한 **원문에 없던
숫자가 생겼는지**는 기계적으로 셀 수 있다.

### 4-2. 전달 형식에 따라 표 표기가 달라진다 (낮음, 기존 문제)

VIP 답변이 Canvas 로 나가면 렌더링된 텍스트가 `canvas_harness.apply` 를 한 번 더
지나 표 단위가 통일된다(`pilot.py`). 메시지로 나가면 지나지 않는다. 같은 답이
전달 경로에 따라 다르게 보이는 것은 이번 변경 전부터 있던 성질이고, 이번에
렌더링이 끼면서 **문장 다시 쓰기 → 표 단위 변환** 두 단계를 거치게 됐다.
`harness_version` · `converted_cell_count` 가 기록되므로 추적은 된다.

## 6. 보호 로직 독립 검증 (§5 에 대한 검증)

`_specialist_render_is_safe` 와 `_specialist_safe_fallback` 을 직접 쳤다.

### 막는 쪽 — 전부 통과

값 변경·없던 숫자 추가·숫자 삭제·중복·단위 바꿔치기 다섯 종이 모두 폐기되고
`(원문, 전문봇 모델, 전문봇 비용)` 으로 복귀한다. 출처 날조는 `출처:` · `Source:` ·
`출처 :` 세 표기 모두 폐기된다. 전문봇 **자신이** 쓴 출처 줄도 복귀 경로에서
지워져, 시스템 출처와 두 줄이 되는 일이 없다.

### 과잉 차단 — 발견 당시 **결함 셋** (2026-11-09 수정됨)

가드가 거의 항상 발동한다. 토큰화가 세 군데 어긋난다.

**(가) 단위 정규식이 다음 낱말의 첫 글자를 먹는다.**

```
5 건축본부 → {'5건'}      5 일정 → {'5일'}      5 개발 → {'5개'}
5 회의     → {'5회'}      5 명단 → {'5명'}      5 차수 → {'5차'}
5 배정     → {'5배'}      5 원화 → {'5원'}      5 년도 → {'5년'}
5 월요일   → {'5월'}      5 기준 → {'5'}   ← 단위로 시작하지 않을 때만 정상
```

단위 목록이 `건·명·개·회·차·배·원·년·월·일` 을 포함하고 앞에 `\s*` 가 붙어 있어,
숫자 뒤 공백 하나를 건너 다음 낱말의 첫 글자를 단위로 흡수한다. 한국어 업무
문장에서 숫자 뒤에 오는 낱말은 대개 이 글자들로 시작한다. `[\d,]*` 때문에
쉼표도 먹는다 — `2026-11-05, 건축본부` → `-05,건`.

**(나) ISO 날짜가 세 토큰으로 찢긴다.** `2026-11-05` → `2026` · `-11` · `-05`
(하이픈을 음수 부호로 읽는다).

**(다) 목록 번호 제거가 1~9 만 본다.** `[1-9][.)]` 라서 `10.` 부터는 번호가
사실값으로 세어진다. 10항목 이상 목록이면 비교가 깨진다.

### 합치면 — 기능이 조용히 꺼진다

```
원문:    "집행률은 72%입니다. 2026-11-05 건축본부 보고 기준."
재구성:  "**결론:** 2026-11-05 기준 집행률 72%."     ← 숫자 하나도 안 바뀜
판정:    safe = False → 폐기, 평문으로 복귀
```

원문 토큰 `{'72%','2026','-11','-05건','15억원'}` 과 재구성 토큰
`{'72%','2026','-11','-05','15억원'}` 이 **`-05건` ↔ `-05`** 로 어긋난다.
숫자 뒤 낱말을 바꾸는 것이 곧 재구성이므로, **충실한 재구성일수록 거부된다.**

더 나쁜 것은 진단이다. 로그에는 `specialist answer rendering changed protected
facts` 한 줄만 남아 **운영자는 모델이 숫자를 바꿨다고 읽는다.** 실제 원인은
토큰화이고, 둘은 정반대 조치를 부른다.

영향 범위는 VIP 전문봇 답변 전부다. 지금 상태에서 경영진 형식은 「숫자 뒤
낱말까지 그대로 둔 재구성」 일 때만 살아남는데, 그런 재구성은 거의 재구성이
아니다.

### 적용한 수정

1. 단위 앞의 `\s*` 를 제거하고(= 숫자에 **붙은** 단위만 인정), 단위 뒤에
   `(?![가-힣])` 를 두어 낱말 중간을 먹지 않게 한다
2. ISO 날짜(`\d{4}-\d{2}-\d{2}`)를 **먼저** 한 토큰으로 잡는다
3. 목록 번호를 `\d+[.)]` 로 넓힌다

`tests/test_vip_specialist_rendering.py` 의 네 시험은 이제 일반 회귀시험이다. 수정 후
대상 시험과 전체 스위트 결과는 별도로 다시 기록한다.

### 아직 남는 것

기관명·사람 이름 같은 **비수치 고유명사**는 여전히 프롬프트 계약에만 의존한다.
「건축본부」 를 「투자사업팀」 으로 바꾼 렌더링은 수치가 그대로라 통과한다.
출처 좌표가 보존되므로 사람이 확인하면 드러나지만, 확인은 사람 몫이다.
