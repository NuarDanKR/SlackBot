# HWP 변환을 rhwp 앱에 넘긴다 — 원칙 1 의 좁은 예외

작성 2026-11-09 · 오너 결정 같은 날.

## 무엇이 바뀌나

HWP 는 채널의 rhwp 앱이 PDF 로 바꿔 올린다. TYBot 은 원칙 1 에 따라 봇·앱 메시지를
모든 수집 경로에서 버려 왔으므로 그 PDF 도 버려졌다. 그래서 **지정된 변환 앱이 올린
PDF 파일만** 원문 첨부로 받고, 앱이 지정돼 있는 동안 TYBot 은 HWP 를 직접 변환하지
않는다. 같은 문서가 두 벌의 근거가 되지 않게 하기 위해서다.

원칙 1 이 막으려는 것은 봇이 **자기 출력**을 되먹여 편향되는 것이다. rhwp PDF 는
사람이 올린 원본 문서를 렌더링한 사본이지 봇이 쓴 문장이 아니다.

## 좁게 받는다

| 조건 | 이유 |
|---|---|
| **앱 ID** 로만 가린다 (`A` + 대문자·숫자) | 봇 이름은 누구나 비슷하게 만들 수 있다. 형식이 틀린 값은 버린다 — 「아무 앱이나」 로 넓어지지 않는다 |
| **PDF 파일만** | 같은 앱이 다른 형식을 올려도 받지 않는다 |
| **글은 버린다** | 「변환했습니다」 같은 안내문은 봇 출력이다 |
| 받은 PDF 는 **사람 메시지와 같은 경로** | PII 검사·ACL·중복 방지가 그대로 걸린다. 다만 `human_upload_confirmed` 는 붙지 않는다 |
| 목록이 비면 **아무것도 바뀌지 않는다** | 예외는 켜야 생긴다. 기본은 예전처럼 TYBot 이 HWP 를 변환한다 |

적용 경로: 실시간 수집(`archiving_bot`) · 정기 수집(`collect`) · 소급(`backfill`).
세 곳이 같은 함수(`converter_bots.converted_document_message`)를 쓴다 — 한쪽만 받으면
같은 PDF 가 들어온 길에 따라 아카이브에 있다가 없다가 한다.

## 위임된 HWP 원본

원본은 그대로 보관한다. 원문 줄에는 `[첨부:변환앱위임]` 으로 남고, 진단·콘솔에서는
「변환 앱 위임 (rhwp PDF 사용)」 으로 보인다. **실패가 아니므로 실패 집계와 조치
목록에서 뺀다** — 「미지원」 으로 두면 사람이 고칠 것이 없는 파일을 찾아 헤맨다.

질문에 HWP 를 붙이면 변환하지 않고 rhwp PDF 를 붙여 다시 물어 달라고 안내한다
(`file_hwp_use_converted_pdf`).

## 켜는 법 (콘솔)

봇 관리 > 환경변수 설정 > **HWP 변환 앱 (Slack 앱 ID)** 에 rhwp 의 앱 ID 를 적고 저장.
수집기는 재시작되지 않아도 1분 안에 콘솔 설정 파일에서 새 값을 읽는다.

실패 집계 제외 · 다운로드 실패는 평소 실패 · 질문 HWP 안내 · 콘솔 입력 검증.

## 안 한 것

- 이미 아카이브에 「처리실패」·「미지원」 으로 남은 과거 HWP 는 그대로다. rhwp PDF 가
  채널에 있으면 소급 수집으로 들어온다
- `.env.example` 에 키를 적지 않았다 — 콘솔이 관리하는 값이다
