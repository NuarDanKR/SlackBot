# TYIT XLSX 답변 누락: 조회 예산과 긴 첨부 열람

2026-10-21 TYIT `C0BQYAC28F3`의 네 XLSX는 원본 보관, 변환, 정본 게시가
완료되어 있었다. 공유 Hermes의 `read_document` 4회 결과는 총 320자였고,
TYBot 로그는 `budget=time`, `elapsed_ms=53562`를 기록했다. 당시 예산 45초는
도구 실행 시간뿐 아니라 모델 응답 대기 시간도 세어, 본문을 읽기 전에 차단했다.

## 변경

- 도구 시간 예산은 실제 TYBot 도구 실행에 쓴 누적 시간만 센다. 모델 대기 시간은
  제외한다. 기본 90초, 콘솔에서 15~120초로 조정한다. 적용에는 TYBot 재시작이
  필요하다. `tool_ms`와 전체 `elapsed_ms`는 로그에서 따로 본다.
- 전체 전문봇 요청 deadline, 도구 호출 횟수, 반환 글자 수 상한은 유지한다.
  시간을 늘리는 것 자체가 토큰을 쓰지는 않지만 추가 모델 호출·도구 결과를 읽는
  과정에서 토큰 비용이 늘 수 있다.
- 같은 채널에 같은 이름으로 재업로드된 첨부는 최신 정본을 기본으로 열고,
  이전본은 `file_id`로 지정한다. 긴 XLSX는 시트별로 선택하고 응답의 `offset`으로
  이어 읽는다. 후보·시트 목록만 받은 것은 본문을 읽은 것으로 세지 않는다.
- 진행 메시지는 3초 후 게시되고, 30초 경과 시 긴 처리 안내로 갱신된다.

### 2026-10-27 이어 읽기 경계 보강

`read_document`의 XLSX 구간 응답에서 머리말과 다음 offset 안내가 차지할 글자 수를
실제 길이로 예약한다. 응답 길이를 나중에 자르면서 offset만 앞서 가는 경우를 막았다.
머리말 때문에 본문 공간이 없으면 도구 상태를 `error`로 돌리고 근거 좌표를 남기지
않는다. 작은 반환 한도와 긴 머리말을 사용한 회귀시험을 통과했다. 운영 네 파일의
답변·근거 대조는 아래 서버 확인 절차로 별도 검증해야 한다.

## 서버 확인

1. 배포 후 콘솔 `환경변수 설정`에서 자료 조회 시간이 90초로 보이는지 확인한다.
   설정을 바꾸면 재시작 요청과 `TYBOT_SPECIALIST_TOOL_SECONDS` 오버레이를 확인한다.
2. 동일 채널에서 최근 네 XLSX의 주제별 요약을 다시 요청한다. 답변에 네 파일이
   모두 확인됐는지, 긴 파일은 시트·구간별로 읽었는지 본문과 근거 보기로 대조한다.
3. 해당 시각의 `tybot.service`에서 `도구 예산 거절 name=read_document`가 없는지,
   `hermes-rpc-shared.service`의 `[rpc] 완료`에서 `read_document` 반환 글자 수가
   거절 안내 80자에 머물지 않는지 확인한다. 일부 시트만 읽었다면 전체 요약이라고
   단정하지 않는다.

실제 운영 XLSX 본문·질문 답변은 이 문서나 테스트에 복사하지 않는다.
