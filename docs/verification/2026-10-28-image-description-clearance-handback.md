## 설계에서 설명이 필요한 자리

### 거절은 **두 축을 함께** 닫는다

좌표가 어긋났거나 승인이 만료됐으면 `access_verified=False` 와
`pii_blocked=True` 를 같이 적는다. 승인 자체를 믿을 수 없는데 그 승인이 말한
「개인정보 없음」 만 살려 둘 이유가 없다.

**예외가 하나 있다.** 권한은 확인됐는데 사람이 아직 안 본 경우
(`pii_not_cleared`)는 `access_verified=True` 로 남긴다. 「권한을 모른다」 와
「검토를 기다린다」 는 사람이 할 일이 완전히 다르다 — 앞은 고치는 것이고 뒤는
사람을 부르는 것이다. 한 덩어리로 닫으면 운영 화면에서 그 구분이 사라진다.

### `text_screened` 를 읽지 않는다

읽고 무시해도 결과는 같다. 그런데 **읽는 코드가 있으면 다음 사람이 거기에
조건을 하나 더 붙인다** — 「검사도 돌았고 태그도 없으니 열어 주자」 가 한 줄이면
된다. 그래서 아예 안 읽고, 시험이 소스에 그 이름이 없는 것까지 건다
(모듈 설명 본문은 빼고 훑는다. 왜 안 읽는지 길게 적어 둔 자리라 그대로 훑으면
설명이 곧 위반으로 잡힌다).

### 승인은 사람이 아니라 **사진 하나**에 묶인다

일곱 칸 결속의 뜻이다. 묶지 않으면 「한 번 승인」 이 「그 사람이 승인한 모든
것」 으로 번진다 — 모델이 바뀌어도, 정책이 완화돼도, 같은 채널의 다른 사진에도
같은 도장이 찍힌다.

`policy_revision` 까지 묶은 이유가 그것이다. 정책이 느슨해진 판에서는 **그때
사람이 본 것과 다른 조건**으로 나가게 된다.

### ACL 은 넓어진 쪽도 거절이다

승인 당시와 지금이 다르면 넓어졌는지 좁아졌는지 **여기서 알 수 없다.** 넓어진
쪽을 맞혀 통과시키면 권한 없는 사람이 설명으로 내용을 안다(원칙 3). 집합으로
비교하므로 순서는 상관없다.

문자열이 `acl` 로 들어오면 빈 집합으로 떨어뜨린다. 파이썬이 문자열을 순회하면
**글자 하나하나가 멤버**가 되어, 어떤 ACL 과도 같지 않은 집합이 조용히
만들어진다. 조용한 거절이 틀린 통과보다는 낫지만 읽는 사람이 이유를 모른다.

### `pii_cleared` 가 `bool` 이어야 한다

`1` 이나 `"yes"` 는 참처럼 보이지만 **사람이 승인했다는 뜻이 아니다.** JSON 을
거쳐 들어온 값이 그렇게 생기기 쉽다. `type(x) is bool` 로 받는다.

### 앞뒤 공백이 붙은 좌표는 거절

` C123` 과 `C123` 이 다르게 묶이면 승인 하나가 두 사진을 가리킬 수 있다.
`_text` 로 양쪽을 다듬어 비교하되, **승인 쪽은 애초에 다듬어지지 않은 값을
거절**한다 — 원장에 들어갈 때 이미 정규화돼야 한다.

## 미검증 · 남은 것

- **호출부가 없다.** 이 판정을 부르고 `as_checks()` 를 러너에 넘기는 잡이 아직
  없다. 선별기 → 로더 → **이 판정** → 예약 → dispatch 가 한 줄로 이어져야
  파이프라인이 끝에서 끝까지 돈다
- **`SafetyAssessment` 를 저장하는 자리가 없다.** 지금은 호출자가 만들어 넘기는
  DTO 다. 사람이 콘솔에서 승인하고 그것이 원장에 남아야 실제로 쓸 수 있다
  (운영 기능은 콘솔에 둔다 — CLAUDE.md). 표가 생기면 철회·만료도 거기서 온다
- **빈 `acl` 을 거절하는 선택의 대가를 재지 않았다.** 규칙 3을 그대로 따랐는데,
  정말로 `[공개]` 이고 ACL 이 빈 문서가 아카이브에 있다면 그 사진은 영원히
  후보로만 남는다. 실제 분포를 세어 보기 전에는 모른다
- `human_upload_confirmed`(봇 생성 여부)는 **이 모듈이 보지 않는다.** 로더가
  정본으로 확인하고 러너가 `bot_generated=False` 로 적는다. 두 곳에서 보면
  갈라지고, 갈라진 쪽은 아무도 안 본다
