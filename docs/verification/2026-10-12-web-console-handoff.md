## 0. 소유권 경계 — 먼저 읽어 주세요

`05d60f6` 이후 콘솔 **화면**(`console-web/`)은 별도 프로젝트에서 관리합니다.
이 저장소는 화면을 직접 고치지 않고, 변경이 필요하면 이 문서를 갱신해 전달합니다.

다만 경계가 **화면과 API 사이**에 있다는 점이 중요합니다.

| 영역 | 경로 | 소유 |
|---|---|---|
| 콘솔 화면 (React) | `console-web/src/` | **콘솔 담당자** |
| 콘솔 API (FastAPI) | `src/tybot/console/` | **TYBot 팀(우리)** |
| DB 스키마 | `deploy/sql/` | TYBot 팀 |
| 봇·수집·아카이브 런타임 | `src/tybot/` 나머지 | TYBot 팀 |

**그래서 아래 항목마다 「누가 고치는가」를 명시했습니다.** 화면만 고쳐서는 안 되는
항목이 섞여 있고, 그걸 구분하지 않으면 콘솔 쪽에서 고칠 수 없는 일을 떠안게 됩니다.

배포 분리는 이미 반영돼 있습니다 — `deploy/install.sh` 는 `console-web` 이 없으면
빌드를 건너뛰고, 화면 계약 시험은 `tests/console_web_path.py` 가 소스 위치를 찾습니다
(`CONSOLE_WEB_DIR` 환경변수 → `SlackBot/console-web` → `SlackBot/../console-web`).
`REQUIRE_CONSOLE_WEB=1` 이면 소스를 못 찾았을 때 skip 이 아니라 실패합니다.

## P0. 워크스페이스 등록이 토큰을 요구해 실패한다

> **최우선.** 지금 **새 워크스페이스를 하나도 만들 수 없습니다.**

### 증상

`운영 > 워크스페이스 관리 > 새 워크스페이스 등록` 에서 키·표시 이름을 넣고
등록하면 저장이 거부됩니다.

```
저장 실패   워크스페이스 설정을 저장하지 못했습니다
            새 워크스페이스에는 봇 토큰과 앱 토큰이 필요합니다.
```

### 원인 — 화면이 아니라 **API** 입니다

이 건은 **콘솔 담당자가 고칠 수 없습니다.** 조사 결과를 그대로 적습니다.

화면은 이미 올바릅니다. `console-web/src/pages/Workspaces.tsx:211` 에 주석이 있고,
`:326` 은 사용자에게 "봇 토큰은 이 화면에서 받지 않습니다" 라고 안내하며,
`:236` 의 제출 payload 에 `botToken`·`appToken` 이 **없습니다.**

거부하는 쪽은 API 입니다.

| 자리 | 내용 |
|---|---|
| `src/tybot/console/app.py:170-171` | `WorkspaceBody.botToken` / `appToken` 이 `None` 으로 들어옴 |
| `src/tybot/console/app.py:2043-2044` | 그대로 `save_workspace()` 로 전달 |
| `src/tybot/console/workspace_store.py:186` | `if not exists and not encrypted: raise` ← **여기서 막힘** |

봇 토큰은 이제 `봇 관리 > 워크스페이스 연결` 에서 봇별로(Master·Archiver·Hermes)
등록합니다. 워크스페이스 행은 **조직 metadata** 만 들고 있어야 합니다. 토큰을
워크스페이스에 매는 것은 봇이 하나뿐이던 시절의 구조이고, 지금은 한 워크스페이스에
봇이 여럿이라 애초에 한 쌍으로 표현할 수 없습니다.

### 우리가 할 일 (TYBot 팀)

- `workspace_store.save_workspace()` 에서 **신규 생성 시 토큰 필수 조건을 제거**합니다.
- 기존 워크스페이스의 토큰 교체 경로(`bot_token`/`app_token` 을 **같이** 줄 때만 허용)는
  당분간 그대로 둡니다. 과거 배포본과의 호환이 끊기면 복구 수단이 사라집니다.
- 토큰 없이 만든 워크스페이스에 봇을 붙이기 전까지는 **수집·답변이 시작되지 않는다**는
  점을 API 응답에 상태로 내려 줍니다(아래 계약 참조).
- 회귀시험: 토큰 없이 신규 생성이 되고, 토큰만 한쪽 주면 여전히 거부되는지.

### 콘솔이 할 일 (콘솔 담당자)

1. **워크스페이스 목록 표에서 토큰 마스크 열을 뺍니다.**
   `console-web/src/pages/Workspaces.tsx:371` 이 `botTokenMask`·`appTokenMask` 를
   그리고 있습니다. 토큰이 워크스페이스에 없는데 열이 남아 있으면 "비어 있다 =
   설정이 빠졌다" 로 읽힙니다. 토큰 상태는 `봇 관리` 화면이 정본입니다.
2. **등록 직후 안내를 바꿉니다.** 지금은 저장만 되고 끝납니다. 등록 성공 뒤
   "아직 봇이 연결되지 않았습니다 — 봇 관리 > 워크스페이스 연결에서 붙이세요"
   를 다음 행동으로 보여 주세요.
3. 목록 행에 **연결된 봇 수**(0이면 눈에 띄게)를 둡니다. 아래 계약을 씁니다.

### API 계약 (수정 후)

```http
PUT /api/workspaces/{key}
Content-Type: application/json

{ "label": "프로젝트금융", "role": "member", "state": "enabled",
  "limitUsd": 10, "readable": ["tyit"] }
```

- `botToken`·`appToken` 은 **보내지 않습니다.** 필드는 하위 호환으로 남지만
  신규 생성에 필요하지 않습니다.
- 응답과 `GET /api/workspaces` 의 각 행에 아래를 더합니다.

| 필드 | 뜻 |
|---|---|
| `connectedBots` | 이 워크스페이스에 연결된 봇 수(0 가능) |
| `botStatus` | `none` / `partial` / `ready` — 화면이 배지로 쓰는 값 |

`botTokenMask`·`appTokenMask` 는 **응답에서 제거**합니다. 화면에서 먼저 지워 주시면
우리가 API 에서 빼겠습니다 — 순서를 반대로 하면 화면이 깨집니다.

## P1. 봇 배포와 콘솔 배포를 끝까지 가른다

> 담당: **TYBot 팀(`deploy/`)** · 콘솔 담당자는 `CONSOLE_DIST` 소유권만 확인해 주세요.

화면 빌드는 `05d60f6` 으로 갈라졌습니다(`install.sh:327` — `console-web/package.json`
이 없으면 빌드를 건너뜁니다). 그런데 **배포 스크립트의 나머지가 아직 분리 전 전제로
돌고 있습니다.** 세 군데입니다.

### (1) 봇 배포가 매번 콘솔을 내린다

`deploy/update.sh:118-120`

```bash
if [[ "$WITH_CONSOLE" == "1" ]] && systemctl is-enabled --quiet tybot-console 2>/dev/null; then
  systemctl restart tybot-console || log '콘솔 재시작 실패 — journalctl -u tybot-console 확인'
fi
```

봇 배포는 `tybot-update.timer` 로 주기 실행됩니다. 그때마다 콘솔이 끊깁니다 —
로그인 세션이 끊기고, **진행 중이던 콘솔 작업**(배포 승인, 소급 실행, 요약 검토
DM 발송)이 중간에 죽습니다. 문서·시험만 고친 배포에서도 똑같이 내려갑니다.

**다만 「콘솔은 절대 재시작하지 않는다」 는 틀립니다.**
`tybot-console.service` 가 돌리는 것은 `uvicorn tybot.console.app:app` 이고,
그 코드는 **이 저장소의 `src/tybot/console/`** 입니다. 게다가 콘솔 백엔드는
`..archive.store`, `..archive.archiving_state`, `..gateway.router`, `..feedback`
등 공유 모듈 15개 남짓을 import 합니다. 봇 코드가 바뀌면 콘솔이 돌리는 코드도
바뀝니다. 안 내리면 **옛 백엔드가 계속 떠 있습니다.**

갈라야 할 것은 「재시작하느냐」가 아니라 **「무엇이 바뀌었을 때 재시작하느냐」** 입니다.

**고칠 방향** — `update.sh` 는 이미 직전 배포 커밋을 들고 있습니다(`$DEPLOYED`,
`$APP/.deployed-commit`). 그 값으로 변경 범위를 보고 결정합니다.

```bash
# src/ 아래가 하나도 안 바뀌었으면 콘솔이 돌리는 코드도 안 바뀌었다.
# 문서·배포 스크립트·시험만 고친 배포에서 세션을 끊을 이유가 없다.
console_needs_restart() {
  [[ -z "$DEPLOYED" ]] && return 0                  # 모르면 재시작한다
  git -C "$SRC" cat-file -e "$DEPLOYED^{commit}" 2>/dev/null || return 0
  git -C "$SRC" diff --name-only "$DEPLOYED" HEAD -- src/ | grep -q .
}
```

- **모르면 재시작합니다.** 직전 커밋을 못 찾거나 비어 있으면 판단하지 않습니다 —
  안 내려서 옛 코드가 도는 쪽이 세션 끊김보다 나쁩니다.
- `TYBOT_FORCE=1` 이면 조건 없이 재시작합니다.
- 건너뛸 때는 **로그에 남깁니다.** 조용히 건너뛰면 "콘솔이 새 코드로 안 바뀌었다"를
  아무도 못 알아챕니다.

> **더 가르고 싶다면** 콘솔 백엔드(`src/tybot/console/`)도 별도 저장소·별도 서비스로
> 옮겨야 합니다. 지금 구조에서는 공유 모듈 때문에 완전히 끊을 수 없습니다.
> 그건 오너 결정 사항이라 여기서는 제안만 남깁니다.

### (2) `CONSOLE_DIST` 를 봇 배포가 소유하고 있다

`deploy/install.sh:414-417`

```bash
if [[ "${WITH_CONSOLE:-0}" == "1" ]] && ! grep -qE "^CONSOLE_DIST=.+" "$CONF_DIR/tybot.env"; then
  echo "CONSOLE_DIST=$APP_DIR/console-web/dist" >> "$CONF_DIR/tybot.env"
fi
```

값이 **비어 있을 때만** 쓰므로 콘솔 저장소가 설정한 값을 덮지는 않습니다.
문제는 **새 서버**입니다. 봇 배포가 `$APP_DIR/console-web/dist` 를 적어 넣는데,
이 저장소는 그 경로를 더 이상 빌드하지 않습니다. 그러면 콘솔이 떠도 화면이 없습니다.

그리고 이게 **조용합니다.** `src/tybot/console/app.py:2950` 의 `mount_frontend()` 는
기동 시 한 번만 봅니다.

```python
if not (root / "index.html").exists():
    logger.warning("CONSOLE_DIST 에 index.html 이 없습니다: %s", root)
    return          # ← 마운트를 통째로 건너뛴다
```

- 기동 때 `index.html` 이 없으면 **마운트 자체를 안 합니다.** 그 뒤에 콘솔 저장소가
  dist 를 배포해도 **재시작 전까지 안 보입니다.** 화면은 404 이고 단서는 로그의
  WARNING 한 줄뿐입니다.
- 반대로 기동 때 있었으면 `StaticFiles` 가 요청마다 디스크를 읽으므로,
  **같은 경로에 새 dist 를 덮는 것은 재시작이 필요 없습니다.**

**고칠 방향**
- `install.sh` 는 `CONSOLE_DIST` 를 **쓰지 않습니다.** 값의 주인은 콘솔 저장소의
  `deploy-console.sh` 입니다.
- 값이 비어 있으면 "화면은 console-web 저장소에서 배포합니다 — `CONSOLE_DIST` 를
  설정하세요" 를 **안내로만** 출력합니다(이미 `install.sh:328-329` 가 비슷한 문구를
  냅니다. 그 문구만 남기고 쓰기를 뺍니다).
- `mount_frontend()` 가 건너뛴 사실을 **콘솔 health 응답에 노출**합니다. WARNING 로그
  한 줄은 아무도 안 봅니다.

**콘솔 담당자에게 요청**: `deploy-console.sh` 가 dist 를 배포한 뒤
`CONSOLE_DIST` 가 그 경로를 가리키는지 확인하고, **처음 설정하는 경우에는**
`systemctl restart tybot-console` 을 한 번 해 주세요(마운트가 기동 시 결정되므로).
이후 같은 경로에 덮는 배포는 재시작이 필요 없습니다.

### (3) `WITH_CONSOLE` 자동 감지가 결정을 대신한다

`deploy/update.sh:15-21`

```bash
if [[ -f /etc/systemd/system/tybot-console.service ]]; then
  WITH_CONSOLE=1
```

유닛 파일이 **있기만 하면** 콘솔 의존성(`requirements-console.txt`)·sudoers·libexec 을
매 배포마다 다시 깝니다. 한 번 깔았던 서버는 영원히 그렇습니다.

`tybot-console.service` 는 우리 Python 을 돌리므로 **이 저장소가 계속 소유하는 것이
맞습니다.** 다만 자동 감지는 "예전에 깔았다" 를 "지금도 쓴다" 로 읽습니다.
`/etc/tybot/tybot.env` 에 명시적인 값을 두고, 자동 감지는 그 값이 없을 때의
폴백으로만 쓰는 편이 낫습니다.

### 완료 조건

- [ ] `src/` 가 안 바뀐 배포에서 `tybot-console` 이 재시작되지 않고, **그 사실이
      로그에 남는다**
- [ ] 직전 커밋을 모르거나 `TYBOT_FORCE=1` 이면 재시작한다
- [ ] `install.sh` 가 `CONSOLE_DIST` 를 쓰지 않고 안내만 한다
- [ ] `CONSOLE_DIST` 가 없거나 `index.html` 이 없어 마운트를 건너뛴 상태가
      health 응답에 보인다
- [ ] 위 둘을 섞은 회귀시험 — 문서만 바꾼 배포, 콘솔 백엔드만 바꾼 배포,
      둘 다 바꾼 배포

## P2. 콘솔 TLS — 평문 HTTP 로 운영 중 (B-35)

> 담당: **TYBot 팀(서버)** · 콘솔 화면 변경 없음. 알고 계셔야 해서 적습니다.

2026-09-01 에 콘솔을 사내망 전체에 열었고(`--host 0.0.0.0`), **지금도 평문입니다.**

- 로그인 비밀번호가 요청 본문에 평문으로 흐릅니다
- 세션 쿠키가 매 요청 평문으로 흐릅니다. 주워 담으면 로그인 없이 그 사람 행세가 됩니다
  (`HttpOnly`·`SameSite=strict` 는 브라우저 안을 막는 장치이지 도청을 막지 못합니다)
- 이 화면은 **아카이브 원문 열람**·환경설정·배포 승인을 쥐고 있습니다

사내망은 '아무나 못 들어오는 곳'이지 '아무도 못 보는 곳'이 아닙니다.

**콘솔 쪽 주의 한 가지**: nginx 를 443 앞단에 두고 `CONSOLE_COOKIE_SECURE=1` 을 켤
예정입니다. **TLS 를 붙인 뒤에 켭니다** — 먼저 켜면 쿠키가 전송되지 않아 로그인이
안 됩니다. 그때 화면에서 절대 경로 `http://` 를 하드코딩한 곳이 있으면 섞인 콘텐츠로
막히니, 상대 경로를 쓰고 있는지 확인 부탁드립니다.

## P3. 보존 기간과 명시적 영구 보관 관리 (B-71)

> 담당: **콘솔 화면** · API 는 우리가 제공합니다(일부 신규).

### 배경

`archive_retention_policy` 에 90일이 들어 있었지만 **그 값을 읽어 지우는 코드가
없었습니다.** 정책값은 화면과 운영 전환 차단 조건만 봤습니다. 그래서 체크리스트는
통과하는데 아무것도 만료되지 않았고, 사람은 체크된 것을 보증으로 읽었습니다.

집행 코드는 이제 있습니다(`src/tybot/retention.py`). 화면이 할 일은 **기간을 정하고
집행 상태를 보여 주는 것**입니다.

### 정책 세 가지

| 이름 | 실제 자료 |
|---|---|
| `bot_conversation_audit` | 봇↔사람 대화 감사 기록 (QA 로그 파일) |
| `bot_dm_message` | 봇과 사람의 1:1 DM 원문 |
| `bot_dm_attachment` | 그 DM 의 첨부 원본 |

### 화면 계약

1. 세 기간을 **각각** 조회·변경합니다. 기본 운영값은 90일입니다.
2. 변경 전에 **영향 범위와 만료 예정 건수**를 보여 줍니다. 기간을 줄이면 그 순간
   지워질 양이 늘어납니다 — 숫자를 보기 전에 저장 버튼을 누르게 하지 마세요.
3. `NULL` 은 계속 **미결정**입니다. 「영구 보관」이 아닙니다.
   영구 보관은 **별도의 명시적 상태**로 두고 목적·근거·승인자·사유·시각을 기록합니다.
   미설정이나 숫자 `0` 으로 우회하지 못하게 합니다(`0` 은 API 가 거부합니다).
4. 승인되지 않은 영구 보관은 적용하지 않습니다.
5. 기간 변경·철회·집행 상태와 **마지막 실행 결과**를 감사 기록으로 확인할 수 있게 합니다.
6. 법령상 파기·삭제 요청을 막지 않습니다.

### 집행 상태 표시 — 이게 핵심입니다

**값이 있다는 사실은 집행이 아닙니다.** 2026-10-02 까지 정확히 그랬습니다.
`GET /api/workspaces/{key}/archiving` 의 `blockers` 에 아래가 올라옵니다.

```

보존 기간이 집행되지 않고 있습니다: 마지막 집행이 30일 전입니다
보존 기간이 집행되지 않고 있습니다: 마지막 집행이 보지 않은 정책이 있습니다: …
```

## 공통 규칙 — 모든 화면에 적용

### 1. 원문을 표시하지 않습니다

콘솔은 **상태·건수·좌표·오류 코드**만 보여 줍니다. 대화 원문, 첨부 본문, DM 내용은
화면에 올리지 않습니다. 봇과의 DM 은 **그 사람 본인이 DM 에서 물을 때만** 근거가
됩니다 — exec·root·콘솔도 예외가 아닙니다.

### 2. 시크릿은 마스크만

Slack 토큰·DSN·API 키·원문 경로는 API 응답과 로그 **양쪽에서** 가립니다.
저장 후 화면에는 **설정 여부와 마지막 검증 시각**만 보입니다.

### 3. 모르면 "모른다"고 씁니다

상태를 못 읽었을 때 「정상」이나 「0건」으로 보여 주지 마세요. 못 본 것과 없는 것은
사람이 할 일이 다릅니다. 이 프로젝트에서 반복해 터진 고장이 전부 이 모양입니다 —
오류는 안 나고 0 이 나옵니다.

### 4. 파괴적이거나 비용이 드는 동작은 범위를 명시하게

예: 소급은 채널을 고르게 하고, 실행 전에 **분량을 먼저 셉니다.**
보존 집행은 기본이 **읽기 전용 미리보기**이고, 적용에는 실행자 이름이 필요합니다.

### 5. 화면 계약 시험

`tests/test_console_bot_ui_contract.py` 등이 `console-web` 소스를 읽어 계약을
고정합니다. 화면 문구·필드를 바꾸면 이 시험이 깨질 수 있습니다.
`CONSOLE_WEB_DIR` 를 맞춰 두고 `REQUIRE_CONSOLE_WEB=1` 로 돌려 보시면
"소스 없음" 으로 조용히 skip 되는 일을 막을 수 있습니다.

## 부록 A. 이 문서와 **함께** 받아야 할 것

이 인계서는 「무엇을 고칠지」를 적었습니다. 「고친 것이 맞는지」는 혼자 확인할 수
없습니다 — 화면 계약을 강제하는 시험이 **TYBot 저장소**에 있고, 그 시험이 **콘솔
저장소의 소스를 읽기** 때문입니다.

### A-1. 화면 계약 시험 — 모르면 우리 배포가 깨집니다

화면 문구·필드·경로를 바꾸면 아래 시험이 깨집니다. 콘솔 저장소에는 없고
TYBot 저장소 `tests/` 에 있습니다.

| 파일 | 시험 수 | 무엇을 강제하나 |
|---|---:|---|
| `tests/test_console_bot_ui_contract.py` | 52 | 봇 관리 화면의 토큰 입력·문구·권한·탭 경로 |
| `tests/test_pf_isolation.py` | 35 | PF 콘솔과 TY 콘솔이 섞이지 않는다 |
| `tests/test_deploy_scripts.py` | 48 | 배포 스크립트 계약(P1 과 직접 연결) |
| `tests/test_manifest_sync.py` | 9 | 화면이 보여 주는 Slack 매니페스트와 실제 파일 일치 |

강제하는 것 중 **보안에 걸리는 것들**입니다. 이건 취향이 아니라 계약입니다.

- 토큰 입력은 `password` 타입이고 저장 후 **지워진다**
- 평문 토큰 필드를 **어떤 경로로도 렌더링하지 않는다**
- 내부 호출 화면에는 토큰 입력이 **없다**
- 메뉴를 옮겨도 **권한이 넓어지지 않는다**
- 옛 URL 은 알려진 경로로 **착지한다**(쿼리는 건드리지 않고)

**돌리는 법** — 콘솔 저장소를 체크아웃한 경로를 알려 주면 됩니다.

```bash
# TYBot 저장소에서
CONSOLE_WEB_DIR=/path/to/console-web REQUIRE_CONSOLE_WEB=1   python -m pytest tests/test_console_bot_ui_contract.py tests/test_pf_isolation.py                    tests/test_manifest_sync.py -q
```

`REQUIRE_CONSOLE_WEB=1` 을 **꼭 붙여 주세요.** 없으면 소스를 못 찾았을 때
실패가 아니라 **skip** 입니다. 배포 게이트가 「소스 없음」 으로 계약 시험을 통째로
건너뛰고 통과하면, 화면과 API 가 어긋난 채로 배포됩니다.

경로를 안 주면 `SlackBot/console-web` → `SlackBot/../console-web` 순으로 찾습니다.
**두 저장소를 나란히 두면** 환경변수 없이도 돕니다.

### A-2. API 계약 — 내보낸 파일이 없습니다

OpenAPI 스펙을 파일로 내보내 두지 않았습니다. 지금은 **도는 콘솔**에서 받아야 합니다.

```
GET http://<콘솔>/openapi.json      # FastAPI 자동 생성
GET http://<콘솔>/docs              # 사람이 보는 화면
```

**요청 주시면 `docs/` 에 `openapi.json` 을 커밋해 버전마다 올리겠습니다.**
그게 없으면 콘솔을 띄울 수 없는 환경에서 화면을 못 만듭니다. 이 문서의 P0·P3 은
