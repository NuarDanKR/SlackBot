# VIPBot 공통 TYBot 구성 분기 전환

> **폐기된 절체 기록(2026-11-12).** 공유 `tybot.service` 분기가 운영 정본이며
> 독립 `tybot-vipbot.service`와 실행 코드는 삭제됐다. 아래 절차를 다시 실행하지 않는다.

상태: 구현 중. `VIPBOT_SHARED_RUNTIME_ENABLED=0` 유지. 현재 운영 중인
`tybot-vipbot.service`를 아직 중지하거나 교체하지 않는다.

## 오너 결정

VIPBot은 별도 답변 제품이 아니다. 동일한 `WorkspaceBot`과 `AnswerEngine` 경로를
사용하고 다음 구성만 다르다.

1. VIP 모델·프롬프트·일일 비용 상한
2. `bot_access(bot='vipbot')` 사용자 허용 판정
3. `bot_source_channel(bot='vipbot')` 근거 좌표
4. 채널 호출의 상세 답변은 요청자 DM으로만 전달. 채널에는 DM 전송 성공 뒤 고정
   안내만 남기며, DM 실패 시 채널로 폴백하지 않음

Canvas, 질문 첨부, 후속 질문, 검색, 출처, 전문봇, QA 전달은 TYBot과 같은 메서드를
사용한다. VIP 앱은 중앙 원문 writer가 아니므로 실시간 수집·백필·채널 은퇴 판정·
상태 파일 기록은 기존 TYBot 인스턴스만 소유한다.

## 이번 구현

- `WorkspaceBot`에 요청 컨텍스트·질문 정규화 구성 지점을 추가했다.
- VIP 권한은 계획·첨부 다운로드·LLM 호출 전에 확정한다.
- VIP 답변 인스턴스도 `WorkspaceBot`으로 만든다. 별도 delivery 코드를 호출하지 않는다.
- VIP 모델은 공통 gateway `Router`와 공통 `AnswerEngine`으로 구성한다.
- VIP QA 좌표는 TYBot QA와 다른 디렉터리에 둔다. 서로 다른 ACL로 선택한 후속 질문
  좌표가 섞이지 않게 하기 위함이다.
- VIP 분기는 원문 수집 의도, 채널 수명주기, heartbeat와 워크스페이스 런타임 상태를
  쓰지 않는다. 이 상태의 소유자는 기존 TYBot 하나뿐이다.
- 관리형 근거의 실시간 조회는 등록된 `(workspace, channel_id)`가 채널 ID를 정확히
  한 워크스페이스로 결정할 때만 연다. 빈 목록과 중복 좌표는 조회하지 않는다.
- TYBot과 VIPBot의 Slack bot/app 토큰 중 하나라도 같으면 두 번째 Socket Mode 세션을
  만들지 않고 기동을 거절한다.
- 기능 플래그 기본값은 꺼짐이다.

## 전환 전 필수 게이트

- 전체 pytest와 ruff 통과
- VIP 매니페스트에 Canvas·DM·질문 첨부·mention 답변에 필요한 scope/event 반영
- 허용, 거절, 근거 0건, 교차 워크스페이스, Canvas, 첨부, 후속 질문 실 Slack 시험
- 같은 질문을 TYBot과 VIPBot에 보내 전달 형식과 출처 형식이 같은지 대조
- 전문봇 성공 답변에도 VIP 경영진 답변 계약을 적용할 방법 확정. 현재 전문봇 성공은
  `AnswerEngine`에서 조기 반환하므로 VIP 프롬프트를 다시 거치지 않는다.
- VIP가 원문·채널 상태·heartbeat를 쓰지 않는지 확인
- 새 공통 분기를 먼저 기동한 상태에서 기존 별도 서비스와 동시 응답하지 않도록
  한 번의 절체 절차 확정

위 게이트 전에는 `VIPBOT_SHARED_RUNTIME_ENABLED=1`을 운영 설정에 넣지 않는다.

## 워크스페이스 선택 계약

- 워크스페이스를 지정하지 않은 VIP 질문은 콘솔의 `bot_source_channel`에 등록된
  모든 `(workspace, channel_id)`를 후보로 검색한다.
- 질문에 설정된 워크스페이스 키나 표시 이름을 명시하면 해당 워크스페이스의 등록
  좌표를 검색·요약·전문봇·후속 질문에서 먼저 평가한다. 접근 범위는 줄이지 않는다.
- 명시한 워크스페이스에 등록 좌표가 없거나 근거가 부족해도 나머지 등록 좌표는
  계속 후보로 남는다. 단, 콘솔에 등록되지 않은 채널을 새로 여는 일은 없다.
- 워크스페이스 이름 지도는 활성 TYBot 연결만이 아니라 콘솔 DB의 비활성 제외 전체
  워크스페이스 메타데이터에서 만든다. 조회 권한 자체는 이름 지도가 아니라
  `bot_source_channel` 좌표 집합이 결정한다.
- 이미 복원한 후속 질문 근거도 현재 등록 범위로 다시 검사한 뒤, 새 질문이 명시한
  워크스페이스의 근거를 먼저 배치한다. 이번 질문의 임시 첨부도 계속 유지한다.
