# B-51 구현 기록 — 보관·삭제된 채널을 근거에서 뺀다

> 작성: 2026-09-16 (Claude)
> 보고: 오너 — "삭제된 채널에서의 문서도 출처로 가져오고 그걸 요약 내용에 집어넣고 있어."
> 상태: 구현 완료 · **운영 검증 대기**

## 1. 무엇이 문제였나

Slack 채널을 보관(archive)하거나 지워도 **우리 아카이브에는 원문이 그대로 남는다.**
그게 설계대로다 — 원문은 지우지 않는다(원칙 1).

그런데 답변·요약 경로가 그 원문을 **지금도 살아 있는 자료처럼** 썼다. 우리 쪽
코드 어디에도 「이 채널이 아직 있는가」 를 보는 자리가 없었다.

사람 입장에서는 없앤 채널의 이야기가 오늘 답에 섞여 나오고, 출처를 눌러도 채널이
없어 확인할 수 없다. **「자료가 틀렸다」 보다 나쁘다** — 확인할 방법이 없는 자료가
답에 들어간다.

## 2. 무엇을 했나

### 새 모듈 `src/tybot/channel_lifecycle.py`

보관·삭제된 채널을 `STATE_DIR/retired-channels.json` 에 기록한다. 담는 것은
좌표뿐이다 — `workspace`·`channel_id`·`channel`·`reason`·`at`. **원문도 메시지도
여기 오지 않는다.**

### 기록은 두 곳에서 온다

| 경로 | 언제 | 왜 필요한가 |
|---|---|---|
| Slack 이벤트 | 보관·삭제·해제 즉시 | 대조만 쓰면 다음 대조까지 계속 답에 나온다 |
| 기동 시 대조(`retired_sweep`) | 봇 시작 | 이벤트만 쓰면 **봇이 꺼져 있던 사이**를 영영 놓친다 |

이벤트 6개를 `docs/pilot/slack-app-manifest.yaml` 에 더했다 —
`channel_archive`·`channel_unarchive`·`channel_deleted` 와 비공개용 `group_*`.

### 근거에서 빼는 자리는 둘

사용자가 본 증상이 둘이었다 — **출처로 나오고, 요약에 들어간다.**

| 자리 | 무엇을 막나 |
|---|---|
| `ArchiveStore.visible_docs()` | 답변·검색·후속 질문 복원 — 모든 조회가 여기를 지난다 |
| `summary_review.channel_source()` | 요약 후보 생성 |

`ArchiveStore.docs()` 는 **거르지 않는다.** 콘솔 진단·수집 현황은 전부 세어야 한다 —
「몇 건 모았나」 에서 보관 채널이 사라지면 수집이 줄어든 것처럼 보인다.

### 콘솔 설정

환경설정에 `보관·삭제된 채널도 근거로 사용`(`INCLUDE_RETIRED_CHANNELS`).
**기본은 꺼짐.** 화면에는 지금 기록된 채널 수와 목록(이름·사유·시각)을 함께
보여 준다 — 설정만 보여 주면 「켜면 뭐가 달라지는지」 를 알 수 없다.

켜면 경고가 함께 뜬다: *"사람이 출처를 눌러도 채널이 없어 확인하지 못할 수 있습니다."*

### 켜도 조용히 섞지 않는다

포함으로 켠 경우 출처 뒤에 표시가 붙는다.

```text
[전산팀]공지 (보관 채널), 📄2026-09-01.md(2026-09-01)
[자금팀]주간 (삭제 채널), 📄2026-08-20.md(2026-08-20)
```

## 3. 기본값의 방향 — 왜 이쪽인가

| 판정 | 기본값 | 이유 |
|---|---|---|
| 보관·삭제 채널을 근거로 쓸까 | **아니오** | 확인할 수 없는 자료는 답에 안 넣는다(원칙 3) |
| 기록을 못 읽으면 | **아무것도 빼지 않는다** | 막는 쪽이면 디스크 오류 하나로 멀쩡한 자료가 통째로 사라지고, 봇은 "자료가 없다" 고 답한다 — 사람은 수집 실패로 읽는다 |
| 비공개 채널이 목록에서 사라지면 | **삭제로 적지 않는다** | 지워진 것과 **봇이 나간 것**을 구별할 수 없다. 나간 것을 삭제로 적으면 다시 초대해도 자료가 빠진 채로 남는다 |
| 같은 이름의 새 채널 | **그대로 근거** | 신원은 ID 다. 이름은 바뀌고 재사용된다 |

**두 번째 줄이 다른 기본값과 방향이 반대라는 점을 짚어 둔다.** 권한 판정은 막는
쪽이 기본값이지만(원칙 3), 이것은 권한이 아니라 **선도** 문제다. 여기서 막는 쪽으로
기울면 고장이 「자료 없음」 으로 보이고, 그건 조용한 실패다.

## 6. 배포에 필요한 것

**Slack 앱을 다시 설치해야 새 이벤트가 온다.** 매니페스트에 6개를 더했고,
재설치 전까지는 대조(기동 시 1회)만 동작한다.

DB 변경 없음. 스키마도 새 환경변수 필수 항목도 없다 —
`INCLUDE_RETIRED_CHANNELS` 는 없으면 꺼짐이다.

`STATE_DIR/retired-channels.json` 이 새로 생긴다. 없어도 동작한다(빈 기록).

## 7. 운영에서 확인할 것

- [ ] 채널을 보관하면 그 채널 자료가 답변·요약에서 빠지는지
- [ ] 보관 해제하면 다시 들어오는지
- [ ] 봇을 껐다 켜면 그 사이 보관된 채널을 대조가 잡는지
- [ ] 콘솔에서 켰을 때 출처에 `(보관 채널)` 이 붙는지
- [ ] 이미 지워진 채널이 대조 한 번으로 정리되는지
      (기동 로그 `보관 채널 대조 archived=… deleted=…`)

## 8. 하지 않은 것

- **원문을 지우지 않는다.** 뺀 것은 근거로 쓰는 것뿐이다(원칙 1)
- 콘솔에서 채널별로 켜고 끄는 화면을 만들지 않았다 — 지금은 워크스페이스 공통
  스위치 하나다. 채널별이 필요해지면 그때 기록에 필드를 더한다
- 보관 채널 자료의 **보존기간**을 정하지 않았다. 지우는 판단은 사람 몫이다
- `ArchiveStore.docs()` 는 거르지 않는다 — 진단·수집 현황은 전부 세어야 한다
