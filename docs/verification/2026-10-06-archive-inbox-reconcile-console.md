# 검토 결정 대조 — 콘솔에 붙여야 할 것 (인계)

> 작성: 2026-10-06
> 대상: 관리 콘솔(`console-web`, `src/tybot/console`) 담당
> 구현 범위: 이 문서를 쓴 작업은 **콘솔을 건드리지 않았다.** 아래가 남은 몫이다.
> 설계: [`../design/summary-approval-ports.md`](../design/summary-approval-ports.md) §3.A·§3.B ·
> [`../design/hermes-write-entrypoints.md`](../design/hermes-write-entrypoints.md) §6.5

## 0. 왜 콘솔이 필요한가

CLAUDE.md 「운영 기능은 콘솔에 둔다」(2026-09-18 오너 결정). 지금 이 기능은 **환경변수
하나와 로그 한 줄**로만 보인다. 그 상태의 문제는 편의가 아니다 —

- `SUMMARY_DECISION_DIR` 이 비어 있으면 내보내기가 **조용히 꺼진다.** 꺼져도 운영은
  돌아가고(아무것도 생략되지 않을 뿐) 오류도 안 난다. 그래서 **켜졌다고 믿는 상태로
  몇 주가 지날 수 있다**
- 좌표를 못 내 빠지는 건수는 지금 Hermes 쪽 화면과 TYBot 로그에만 찍힌다. 서버
  로그를 읽을 수 있는 사람은 한 명이고, 그 사람이 없으면 기능이 없는 것과 같다
  (「대기 31건·처리 0건」 과 같은 축)

## 1. 화면 하나 — 「검토 결정 대조」

읽기 전용으로 시작해도 된다. **쓰는 버튼보다 보이는 숫자가 먼저다.**

| 보여 줄 것 | 어디서 | 왜 |
|---|---|---|
| 뿌리 경로와 **켜짐/꺼짐** | `summary_review_reconcile.export_root()` | 꺼진 것을 꺼졌다고 말해야 한다. 「검증 안 됨」 을 문장으로 들고 있는 release gate 와 같은 모양 |
| 워크스페이스별 파일 목록 | `<root>/<ws>/*.json` | 출처가 몇 개인지, 상대편 파일이 **있는지** |
| 각 파일의 `source` · 결정 건수 · 마지막 수정 시각 | 파일 자체 | 파일이 오래 안 바뀌면 그쪽 인터페이스가 멈춘 것이다 |
| **못 읽는 파일** | `load_decisions()` 가 `None` | 하나라도 못 읽으면 **그 워크스페이스의 생략이 전부 멈춘다.** 이게 가장 중요한 한 줄이다 |
| 최근 회차의 사유별 건수 | `GenerateStats.settled_elsewhere` + `filter_candidates()` 의 `reasons` | 「후보 0건」 과 「전부 저쪽에서 끝났다」 는 사람이 할 일이 다르다 |

### 1.1 「못 읽음」 은 경고가 아니라 **빨간 줄**이다

`counterpart_decisions()` 는 파일 하나를 못 읽으면 `None` 을 돌려주고, 그러면 그
워크스페이스에서 **아무것도 생략되지 않는다.** 안전한 방향이지만 **조용하다** — 화면에
안 띄우면 사람은 「요즘 중복이 늘었네」 로만 겪고 원인을 못 찾는다.

문장으로 적을 것: *「<파일> 을 읽지 못해 이 워크스페이스의 중복 생략이 멈췄습니다.
같은 건이 두 번 올 수 있습니다.」*

## 2. 사유 코드를 사람 말로

로그·통계에 그대로 나가는 코드다. 화면에서는 아래 문장으로 바꿔 보여 주면 된다.
**코드와 문장을 한 자리에 두고 양쪽 이름을 바꾸지 말 것** — 두 벌이 되면 갈린다.

| 코드 | 화면 문장 |
|---|---|
| `skip` | 상대편에서 이미 끝났습니다 |
| `records_unreadable` | 상대편 기록을 읽지 못했습니다 — 생략이 멈췄습니다 |
| `no_match` | 그 원문 좌표에 대한 결정이 없습니다 |
| `not_final` | 상대편이 **보류**했습니다. 아직 끝난 것이 아닙니다 |
| `source_mismatch` | 좌표는 같지만 워크스페이스·채널이 다릅니다 |
| `evidence_changed` | 결정 이후 **원문이 바뀌었습니다** |
| `no_coordinate` | 원문 좌표가 없어 대조할 수 없습니다 |
| `conflict` | 같은 좌표에 **승인과 거절이 함께** 있습니다 — 사람이 봐야 합니다 |

`conflict` 는 따로 모아 보여 줄 가치가 있다. 두 인터페이스가 같은 원문에 다른 답을
냈다는 뜻이고, 그건 「한 채널의 승인 주체는 하나」(설계 §6) 가 깨진 신호다.

## 3. 범위를 명시하게 만들 것

파괴적이거나 비용이 드는 동작은 콘솔에서 범위를 고르게 한다(CLAUDE.md). 이 기능에서
해당하는 것은 둘이다.

| 동작 | 콘솔에서 요구할 것 |
|---|---|
| 내보내기 **지금 다시** | 워크스페이스를 고르게 한다. 전체 스냅샷을 다시 쓰므로 그 파일의 writer 가 하나뿐임을 전제한다 — 다른 쪽이 쓰는 중이면 `ConcurrentExportRefused` 가 올라오고, 그 사유를 그대로 보여 주면 된다 |
| 뿌리 경로 변경 | **운영 중에 바꾸면 상대편 파일을 못 찾는다.** 바꾸기 전 현재 경로의 파일 수를 세어 보이고, 새 경로에 같은 것이 있는지 확인하게 한다 |

## 4. 하지 말 것

- **결정을 콘솔에서 직접 고치는 문을 만들지 않는다.** 결정은 승인 인터페이스에서만
  난다. 콘솔에서 고치면 그 결정에 좌표도 결정자도 없다
- **`skip` 건수를 「처리 완료」 로 세지 않는다.** 생략은 우리가 안 물은 것이고,
  사람이 끝낸 것은 상대편 기록에 있다. 두 숫자를 합치면 어느 쪽이 일했는지 사라진다
- **「못 읽음」 을 0건으로 보여 주지 않는다.** 없는 것과 못 읽은 것은 다르다
