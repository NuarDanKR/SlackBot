# Hermes 요약 검토 흐름 구현 점검

> 점검일: 2026-09-07  
> 기준 커밋: `a88732a`  
> 범위: TYBot의 채널별 자동 요약과 Hermes 검토 흐름. 이 문서는 구현을 변경하지 않고 현재 상태와 보완 조건만 기록한다.

## 확정할 운영 정책

마스터 TYBot과 Hermes의 책임을 다음처럼 나눈다.

| 단계 | 책임 |
|---|---|
| 원문 수집·ACL 판정 | TYBot |
| 채널별 요약 후보 생성 | Hermes |
| 후보와 근거 원문 보관 | TYBot의 검토 DB |
| 정해진 시각의 검토자 DM | TYBot |
| 승인·반려·정정 | 채널에 지정된 사람 |
| 승인 결과 반영·감사 | TYBot |

요약은 두 종류를 구분한다.

1. **대화형 요약**: 사용자가 Slack에서 지금 요청한 답변이다. Hermes가 생성해 바로
   보여줄 수 있지만 아카이브와 승인 요약에는 저장하지 않는다. 출처는 TYBot이 붙인다.
2. **채널 승인 요약**: 채널별 설정 시각에 자동 생성하는 파생 문서다. 검토자가 승인하기
   전에는 게시하거나 검색 근거로 쓰지 않는다.

승인 요약도 원문이 아니다. `raw/`를 수정하지 않고 별도 파생 저장소에 두며, TYBot의
사실 답변은 계속 원문만 근거로 삼는다. 승인 여부는 사람이 읽을 수 있는 품질과 책임을
보장하지만 요약을 원문으로 바꾸지는 않는다.

## 현재 구현 판정

| 기능 | 판정 | 확인 근거 |
|---|---|---|
| 채널별 검토자 저장 | 구현됨 | `channel_reviewer`, `reviewers.set_reviewers()` |
| 채널별 발송 시각 저장 | 구현됨 | `channel_reviewer.send_at` |
| `/채널 검토자` 조회·변경 | 구현됨 | `slack/pilot.py::_handle_reviewer_command()` |
| 채널 개설자를 기본 검토자로 자동 등록 | 미구현 | `set_reviewers()` 호출은 명령 처리 경로에만 있음 |
| Hermes 요약 후보 생성 | 미구현 | 후보 생성 모듈·호출 경로 없음 |
| 모델 인용과 원문 기계 대조 | 미구현 | Hermes `verifyEvidence()` 대응 코드 없음 |
| 설정 시각 실행기 | 미구현 | 전용 service/timer 및 due-query 없음 |
| 후보·근거·상태 DB | 미구현 | `channel_reviewer` 외 후보 테이블 없음 |
| 검토자 DM과 Block Kit 액션 | 미구현 | 발송 및 승인·반려 action handler 없음 |
| 정정 후 재생성·재승인 | 미구현 | 정정 수명주기 없음 |
| 승인 요약 별도 저장·열람 | 미구현 | 콘솔 capability `approvedSummaries=false` |
| 콘솔 검토 현황 | 미구현 | 콘솔 capability `summaryReview=false` |
| 검토자 누락 경보 | 일부 코드만 있음 | `channels_without_reviewer()`가 콘솔/헬스에 연결되지 않음 |
| 재귀 차단 관문 | 미구현 | 승인 요약과 원문을 분리하는 저장 경로·검사 없음 |

현재 반영된 것은 **B-37 1단계인 설정 저장**이다. 스키마 주석에는 “1분마다 도는
타이머”가 적혀 있지만 실제 타이머와 실행기는 없다. 따라서 오후 5시를 저장해도 현재
코드만으로 오후 5시에 DM이 발송되지는 않는다.

`a88732a`에서 대화형 기간 요약을 전문 봇으로 보내는 경로와 권한 회귀 테스트가
추가됐다. 이것은 위의 **대화형 요약** 경로이며, 채널 승인 요약 흐름을 구현한 것은
아니다.

이 점검은 저장소 구현을 대상으로 했다. 콘솔의 실제 피드백 본문은 서버의 QA/feedback
JSONL에만 있어, 개별 사용자 신고의 원인 분류는 포함하지 않았다.

## Hermes 원본에서 가져와야 할 방어 장치

Hermes 소스는 다음 문제를 이미 다룬다.

- 상단 요약을 자동 수정하지 않고 후보만 만든다.
- 모델이 제시한 인용을 원문에서 찾아보며, 찾지 못한 후보는 검토자에게 보내지 않는다.
- 대조 실패를 “변경 없음”으로 처리하지 않고 실패 목록으로 남긴다.
- 요약이 `max_tokens`에서 잘리면 완성본처럼 보내지 않는다.
- 미처리 후보를 다음 실행이 지우지 않고, 요약이 바뀌면 과거 판정을 무효화한다.
- 봇 출력과 운영 상태를 원문 아카이브에서 분리한다.

다만 그대로 가져와도 보장이 완전하지는 않다.

- `verifyEvidence()`는 여러 인용 중 **하나의 일부 문자열**만 찾아도 후보를 통과시킨다.
  후보에 수치가 여러 개면 모든 핵심 주장과 수치를 각각 대조해야 한다.
- 일반 Q&A와 일일·주간 요약의 모든 문장을 기계적으로 대조하지는 않는다.
- 문서 변환에서 빠진 내용과 OCR 오류는 요약기가 복구할 수 없다.
- 현재 TYBot의 40,000자 앞부분 자르기를 그대로 쓰면 뒤쪽 근거가 빠질 수 있다.

따라서 가져올 단위는 짧은 프롬프트만이 아니라 **후보 상태 모델, 근거 정규화·대조,
잘림 감지, 검토 대기열과 회귀 검사**까지여야 한다.

## 필요한 수명주기

```text
원문 watermark 확정
  -> Hermes 후보 생성
  -> 모든 핵심 주장·수치의 원문 대조
  -> pending 후보와 근거 스냅샷 저장
  -> 채널 시각에 검토자 DM (중복 발송 방지)
  -> 승인: 별도 승인 요약 저장
     반려: 반영하지 않고 사유 기록
     정정: 원문과 정정 지시로 새 후보 생성 -> 다시 승인
     나중에: 만기 시 재알림
```

사람이 쓴 정정 문장을 곧바로 원문이나 승인 요약에 복사하면 안 된다. 정정은 Hermes가
원문을 다시 읽게 하는 지시이며, 새 후보도 동일한 근거 대조와 재승인을 거쳐야 한다.

## 구현 완료 조건

- 같은 채널·기간·후보 버전에 대해 DM이 한 번만 발송된다.
- 서버 재시작과 타이머 재실행에도 중복 후보·중복 DM이 생기지 않는다.
- 발송 시각은 KST로 명시하며 일광절약시간이나 DB 세션 시간대에 의존하지 않는다.
- 여러 검토자가 있을 때 승인 충돌 규칙이 결정되어 있다. 권장은 첫 확정이 상태를 잠그고,
  이후 응답은 이미 처리됐다고 표시하는 방식이다.
- 후보 생성에 사용한 원문 watermark와 해시를 저장해 승인 시점의 원문을 재현할 수 있다.
- 반려·정정·만기 후보가 다음 실행에서 조용히 사라지지 않는다.
- 검토자 없음, 생성 실패, 대조 탈락, DM 실패, 장기 미처리가 콘솔에 각각 구분된다.
- 승인 요약은 `raw/` 및 QA 검색 인덱스에 들어가지 않는다.
- 요약·피드백·DM 본문이 다시 수집되어 다음 요약의 근거가 되지 않는다.
- 실제 Slack Block Kit 액션과 systemd timer를 포함한 통합 테스트가 있다.

## 결론

정책 방향은 적절하다. TYBot이 ACL과 원문을 소유하고 Hermes는 권한 필터가 끝난 채널
원문으로 후보만 만들며, 사람 승인 전에는 파생 요약을 확정하지 않는 구조가 맞다.

하지만 현재 구현 완료 범위는 검토자·시각 설정까지다. 후보 생성부터 승인 반영까지는
아직 설계 상태이며, 콘솔도 이를 의도적으로 숨기고 있다. 이 상태를 “자동 요약 검토가
반영됨”으로 운영하면 설정은 저장되지만 아무 DM도 오지 않는 조용한 실패가 발생한다.
