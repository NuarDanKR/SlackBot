## 계약

```python
guard_index_write(result: ImageDescription) -> ImageIndexDecision
```

입력을 **고치지 않는다.** 판정은 별도 DTO 로 돌려주고, 원본 결과는 원장이 그대로
들고 있는다 — 거기서 설명을 지우면 「왜 색인이 비었나」 를 나중에 못 답한다.

모델을 부르지 않는다. 외부 의존은 `image_description`(코어 어휘)과
`pii_screen.screen_line` 둘뿐이다.

### 세 가지 결말

| 판정 | 저장 | 언제 |
|---|---|---|
| `allow` | 설명 + 태그 | 깨끗하거나 화질 코드만 |
| `withhold_description` | 태그·코드만 | 민감 uncertainty, 모르는 코드, 빈 설명 |
| `block` | 없음 | failed · 알 수 없는 status · 형태 검사 적중 |

`storable` 로 앞의 둘을 한 번에 가른다.

### DTO

`verdict` · 좌표 4종 · `prompt_revision` · `index_status` · `description` ·
`tags` · `uncertainty` · `codes`. `allow` 가 아니면 `description` 은 빈 문자열이다.

## 「차단」 과 「설명 제외」 를 가른 기준 — 판단이 필요했던 곳

지시의 3번(이메일·전화·차량번호·숫자)은 **차단**, 4번(민감 uncertainty)은
**설명 본문을 색인하지 않는다** 로 말이 다르다. 그대로 따랐고, 까닭도 그 쪽이
맞다고 본다.

| | 모델이 | 태그를 믿을 수 있나 |
|---|---|---|
| 3번 | 규칙을 **어겼다** | 없다 → 통째로 막는다 |
| 4번 | 규칙을 **지켜서** 알려 줬다 | 있다 → 설명만 뺀다 |

4번에 가운데 단계가 따로 있어야 하는 이유도 같다. 사람이 찍힌 사진은 색인에서
지우면 안 되고(그 사진이 있다는 사실은 PII 검토에 필요하다) 설명을 남겨도 안
된다. 둘 중 하나만 두면 **사진이 사라지거나 설명이 돌아다닌다.**

형태 검사는 민감 uncertainty보다 **먼저** 돈다. `plate_visible` 이 붙은 채로
설명에 번호판이 적혀 있으면 설명만 빼는 것으로 끝내지 않고 막는다.

## 규칙별 구현

| 지시 | 구현 |
|---|---|
| 1. failed 저장 불가 | `status` 확인. 알 수 없는 status 도 막는다 |
| 2. 주민번호 | `pii_screen.screen_line` **재사용**. 여기에 정규식을 또 두면 두 규칙이 갈라진다 |
| 3. 이메일·전화·차량번호·숫자 | 각각 패턴 + 마지막에 유니코드 숫자 전부 |
| 4. 민감 5종 | `SENSITIVE_UNCERTAINTY` → `withhold_description` |
| 5. 화질 5종 | `QUALITY_UNCERTAINTY` → 설명이 안전하면 `uncertain` 으로 저장 |
| 6. 태그 | 코어 허용 목록으로 다시 거른다 — **코어를 믿지 않는다** |
| 7. 비민감 코드만 | 코드 11종 전부 ASCII 식별자. 탐지 문자열은 안 돌려준다 |
| 8. 입력 불변 | 별도 DTO. 시험이 `repr` 과 동등성으로 확인한다 |

### 숫자를 통째로 막는다

설명에 숫자가 들어갈 이유가 없다 — 공정률·수량·치수·번호 전사가 **전부** 금지다.
「굴착기 2대」 가 허용되면 어디까지가 세는 것이고 어디부터 추정인지 **코드가 가를
수 없다.** 전각 숫자(`３`)도 `\d` 로 잡힌다.

이메일·전화·번호판 패턴을 따로 둔 이유는 **사유 코드가 달라야** 운영에서
「모델이 무엇을 적었나」 를 가릴 수 있어서다. 숫자 없는 이메일(`a@b.com`)은
숫자 검사로는 안 걸린다.

### 어휘 분류를 import 시점에 검사한다

코어의 `UNCERTAINTY_CODES` 가 민감/화질 두 집합의 합과 다르면 **import 가
실패한다.** 코어에 코드가 늘었는데 여기서 분류를 빠뜨리면 새 민감 코드가 설명과
함께 조용히 색인되기 때문이다. `assert` 가 아니라 `raise` 다 — `-O` 에서 사라지면
안 된다.

## 미검증 · 남은 구멍

- **글자로 쓴 숫자는 안 걸린다.** 「굴착기 두 대」 · 「공정률 절반」 은 통과한다.
  숫자 검사는 **자릿수 모양**만 본다. 막으려면 프롬프트 쪽이거나 사람 검토다
- **이름은 안 걸린다.** 한국어 이름을 형태로 가려내면 일반 명사가 대량으로
  걸린다. 사람 식별은 `person_visible` 코드와 프롬프트에 의지한다 — 모델이 코드도
  안 달고 이름도 적으면 **이 게이트는 못 막는다**
- 이 게이트는 **설명만** 본다. 태그는 허용 목록이라 안전하지만, 목록 자체가
  무엇이 찍혔는지를 말한다는 점은 그대로다(로그에는 개수만 남긴다)
- 저장 경로에 **실제로 연결되지 않았다.** `vision_store`·`vision_worker` 는
  Codex 담당이라 손대지 않았다 — 호출부를 붙이기 전까지 이 게이트는 돌지 않는다
- `pii_screen.screen_line` 은 줄 단위 검사기다. 설명은 한두 문장이라 맞지만,
  문서 전체 판정(`screen_document`)과는 **다른 규칙**이라는 점을 적어 둔다
