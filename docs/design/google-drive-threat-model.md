# Google Drive 근거 — 위협 모델 (B-97)

- 상태: 초안 (2026-11-18, Claude) · 설계 [google-drive-evidence.md](google-drive-evidence.md) 와 같이 읽는다
- 범위: Slack 링크 감지 → Drive API 조회·받기 → 기존 변환·마스킹·정본·색인 → TYBot/VIPBot 답변·출처
- 방법: 자산 → 신뢰 경계 → 위협(STRIDE 축) → 통제 → 남는 위험. 통제마다 **시험으로 확인할 불변식**을 붙인다

## 1. 자산

| 자산 | 왜 중요한가 |
|---|---|
| A1 Slack bot/app 토큰 | 워크스페이스 전체 대화·파일 열람. 유출 = 최대 사고 |
| A2 Google Drive 자격(서비스 계정 키·refresh token) | 승인 루트 전부 + **서비스 계정에 잘못 공유된 모든 것** 열람 |
| A3 Drive 문서 본문·파일명 | 업무 기밀·PII |
| A4 결속 표(`gdrive_root`) | 「누가 어떤 폴더를 보나」 를 정한다. 변조 = 권한 우회 |
| A5 아카이브 정본·색인 | 답변 근거. 오염되면 원칙 1 붕괴 |
| A6 감사·상태 기록 | 철회가 반영됐는지 증명 |

## 2. 신뢰 경계

```
[Slack 사용자 입력·원격 파일 앱]  ← 신뢰 안 함 (URL·external_url·제목 전부 공격자 제어 가능)
        │ B1
[Archiver (Slack 토큰 O, Google 자격 X)]
        │ B2  좌표만 (DB sighting)
[Drive 워커 (Google 자격 O, Slack 토큰 X)]  ── B3 ──▶ Google APIs (외부)
        │ B4  staging 바이트
[변환 워커 tybot-convert (자격 둘 다 X)]
        │ B5
[정본·색인] ──▶ [TYBot / VIPBot 답변 (자격 X, 결속 채널 ACL)]  ── B6 ──▶ Slack 사용자
[콘솔 (자격 암호화만, 승인·해제)]  ── B7 ──▶ DB
```

**핵심 분리:** Slack 토큰과 Google 자격이 **한 프로세스에 같이 있지 않다.** 어느 한쪽이 털려도
다른 쪽으로 번지지 않는다.

## 3. 위협과 통제

| ID | 위협 | 경계 | 영향 | 통제 | 확인 불변식(시험) |
|---|---|---|---|---|---|
| **T1** | 원격 파일 `url_private` 이 외부 호스트(Google 또는 **임의 앱이 정한 공격자 서버**)를 가리키는데 수집기가 `Bearer` Slack 토큰을 붙여 요청 | B1 | A1 유출 → 워크스페이스 전체 | **0단계**: `mode=external`/`is_external`/`filetype=remote` 거부, https + 호스트 `files.slack.com` **정확 일치**, 리다이렉트로 호스트가 바뀌면 헤더 제거 또는 실패 | 원격 파일·유사 호스트·http·리다이렉트 4종에서 `Authorization` 전송 0회 |
| T2 | Slack 메시지에 가짜 Drive URL(공격자 ID)을 넣어 승인 밖 파일을 끌어오게 함 | B1→B2 | A3 오염·확산 | URL 은 **후보**일 뿐. API 응답의 `driveId`/`parents` 로 승인 루트 소속을 확인해야 받음 | 루트 밖 ID 로 본문 요청 0회, 상태 `out_of_scope` |
| T3 | 누군가 서비스 계정 주소로 **승인되지 않은** 폴더를 공유(실수·악의) | B3 | 승인 안 된 자료가 근거로 들어옴 | 서비스 계정 접근 가능 여부가 아니라 **DB 승인 루트**가 범위를 정한다. 승인 밖은 받지 않음 | 서비스 계정이 읽을 수 있어도 루트 없으면 0바이트 |
| T4 | 폴더 A(채널 X 결속) 파일 링크를 채널 Y 에 올려 Y 멤버가 내용을 봇에게 물음 | B6 | 권한 확산(원칙 3) | 정본은 **결속 채널에만**. 링크 채널로 넓히지 않음 | 채널 Y 컨텍스트 질문에서 그 정본 0건 |
| T5 | Drive 권한(소수)이 Slack 채널(다수)보다 좁은데 결속됨 | B7 | 봇을 통한 우회 열람 | 승인은 **사람 결정**(사유·경고 확인 필수, 감사 기록). D2 로 오너가 수용 범위 결정 | 승인 행에 사유·승인자 없으면 INSERT 실패 |
| T6 | `resourcekey`·공유 링크 쿼리를 저장·재노출 | B1, B6 | 링크만 알면 열리는 파일의 키 유출 | 쿼리 제거 후 ID 만 저장, 출처는 `webViewLink` 정규화본 | DB·정본·로그에 `resourcekey=` 0건 |
| T7 | 소유자가 삭제·권한 회수·다운로드 금지했는데 봇이 계속 답 | B3→B6 | 철회 무시, 신뢰 상실 | 변경 로그 15분 + 일일 전수 대조, reader 철회 표식이 경계, 색인 삭제 | 철회 표식 있는 정본은 `visible_docs` 결과 0건 |
| T8 | 다운로드 제한(`copyRequiresWriterPermission`, `downloadRestrictions`) 파일을 편집자 권한 서비스 계정으로 받아버림 | B3 | 소유자 의도 위반 | `canDownload=false` 또는 제한 하나라도 있으면 받지 않음(D7) | 제한 플래그 조합별 본문 요청 0회 |

## 4. 남는 위험 (수용 또는 오너 결정)

| ID | 위험 | 왜 남나 | 대응 |
|---|---|---|---|
| R1 | 철회 후 최대 동기화 주기(기본 15분)+색인 지연 동안 답변에 나올 수 있음 | 답변 시점 실시간 조회를 하지 않기로 함 | D5 에서 주기 결정. reader 표식 반영은 동기화 즉시 |
| R2 | 사람이 봇 답변을 Drive 문서에 붙여넣으면 봇 출력이 원문처럼 들어옴 | 사람 행위는 구별 불가 | 기존 Slack 첨부와 같은 위험. 검토 흐름(B-37)로 발견 |
| R3 | Drive 권한 < 채널 멤버 범위인 결속 | D2-(a) 채택 시 | 승인 경고·사유·감사. 정기 재확인(분기) |
| R4 | 서비스 계정 키 장기 유효 | 키 만료가 없음(G10) | 90일 회전, WIF 전환 검토(D1) |
| R5 | `drive.readonly` 는 restricted 스코프 | 서비스 계정이 공유받은 범위에만 실효. 외부 배포 앱이 아님 | 내부 프로젝트 전용. 보안 심사 필요 여부는 **인프라·보안 확인 필요** |
| R6 | URL 모양 공식 규격 없음 → 새 URL 형식 놓침 | G12 | 놓친 것은 「링크 줄」 로 남고 본문만 없음(안전한 쪽 실패). 감지율 콘솔 표시 |

## 5. 운영 전 점검표 (8단계 착수 조건)

- [ ] 0단계 배포·서버 확인 — 원격 파일 메시지에서 외부 요청에 `Authorization` 없음(프록시·로그로 확인)
- [ ] Google Cloud 프로젝트·서비스 계정 생성은 **사람이** 콘솔에서. 키는 서버에서 바로 암호화 업로드, 로컬 사본 삭제
- [ ] 서비스 계정에 Drive 쓰기 권한(편집자)이 아닌 **뷰어**로 공유됐는지
- [ ] `tybot-drive` OS 계정·키 파일 권한 0400 확인, 다른 계정으로 읽기 실패 확인(「막힌 것」 으로 확인, BACKLOG 인계 교훈 3)
- [ ] DB 역할로 `ciphertext` SELECT 실패 확인
- [ ] 시범 루트 1개로 철회 시나리오 3종(삭제·공유 해제·다운로드 제한) 실측, 반영 시간 기록
