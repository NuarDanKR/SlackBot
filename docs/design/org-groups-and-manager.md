# 조직장·직무 — 그룹웨어에 실제로 있는 것과, Slack 그룹으로 만들 수 있는 것

_2026-09-10 · GWUSER 조사 계정으로 직접 조회한 값이다. 추정이 아니다._

---

## 1. 결론 먼저

| 물음 | 답 |
|---|---|
| 조직장 정보는 어디 있나 | `SYS_OBJECT_GROUP.MANAGERCODE`. **242개 부서 중 119개만 채워져 있다** |
| `JOBDUTY` 가 조직장인가 | 아니다. **직무**(안전관리·건축공사·회계/세무관리…)다 |
| 직위(부장·차장)는 있나 | **없다.** `JOBPOSITIONNAME` 컬럼은 있지만 1449행 전부 NULL |
| JOBDUTY 로 Slack 그룹화가 되나 | 기술적으로 된다. 그러나 전체 자동 생성은 권하지 않는다(4절) |

조사 중에 **별건의 오류**를 찾았다 — 우리가 쓰는 소속 조직 컬럼이 틀렸다(3절).

## 2. 조직장 — `MANAGERCODE`

```sql
-- TY 사용중 부서 기준
부서 총                 242
MANAGERCODE 채워짐      119   (사람 95명 — 겸임 있음)
MANAGERCODE 비어 있음   123
USERCODE 로 정상 연결   119 / 119   ← 데이터 품질은 문제없다
```

절반이 비어 있다. 그룹웨어에 안 채워져 있다는 뜻이고 **우리가 추정으로 메우지 않는다.**
"이 조직의 장은 누구" 를 틀리게 답하는 것보다 모른다고 답하는 편이 낫다(원칙 2와 같은 축).

받는 쪽은 `org_unit.manager_emp_no` 로 실어 두되 **`employee` 를 참조하지 않는다.**
조직 스냅샷과 인사 스냅샷의 시점이 어긋나면 외래키가 반영 전체를 되돌린다.

그룹웨어에서 조직장이 비워지면 우리도 비운다. 예전 값을 남기면 이미 그 자리에 없는
사람을 조직장으로 답한다.

## 3. 별건 — 우리가 쓰는 소속 조직이 틀렸다

`V_TYSLACK_EMP` 는 `u.DEPARTMENTMANAGECODE` 를 `org_code` 로 내보낸다. 이 컬럼은
**소속이 아니라 관리 부서**다. 그 결과:

| | 현재 (DEPARTMENTMANAGECODE) | 실제 (BASEGROUP.DEPTCODE, JOBTYPE='Origin') |
|---|---|---|
| 재직자 | 1120 | 1122 |
| 배정된 조직 수 | **33** | **132** |
| 최다 조직 | 토목현장관리팀 374명 | 건축현장관리팀 30명 |

현장 사람들이 자기 현장이 아니라 본사 관리팀으로 뭉쳐 있다. `김해외동주공재건축 24명`
처럼 붙어야 할 것이 `토목현장관리팀 374명` 이 되어 있다.

**영향 범위가 넓다** — `my_org_chain`(`/채널` 자동 채움), 조직 단위 집계, 조직 기반
권한이 모두 33개 덩어리로 뭉친다. 그래서 이 문서에 적어 두고 **별도 결정 사항으로
남긴다.** 고치는 SQL 은 아래와 같다(겸직 `AddJob` 은 제외하고 본직만 쓴다).

```sql
-- V_TYSLACK_EMP 의 org_code 를 이것으로 바꾼다
(SELECT b.DEPTCODE
   FROM COVI_SMART4J.SYS_OBJECT_USER_BASEGROUP b
  WHERE b.USERCODE = u.USERCODE
    AND b.JOBTYPE = 'Origin')            AS org_code
```

주의: 본직 기준으로 바꾸면 **13명**의 소속이 우리 선택 대상 조직(TY·사용중) 밖을
가리킨다. `employee.org_code` 는 `org_unit(code)` 외래키이므로, 그 13명을 어떻게
할지(소속 NULL 로 둘지, 해당 조직을 복제에 유지할지) 먼저 정해야 반영이 통과한다.

## 4. JOBDUTY 로 Slack 그룹 만들기 — 검토

### 4.1 Slack 쪽 제약 (문서 확인)

| 항목 | 사실 |
|---|---|
| 스코프 | `usergroups:write`. **봇 토큰으로 가능**(사용자 토큰 불필요) |
| 플랜 | Standard(=현 **Pro**) 이상 유료 플랜 필수. **우리는 전 워크스페이스 Pro — 통과** |
| 사전 조건 | 관리자가 *워크스페이스 설정 > 권한 > 사용자 그룹* 에서 생성을 허용해야 한다 |
| handle | **채널·사용자·그룹과 전역 유일.** 어기면 `bad_handle`/`forbidden_handle` |
| 개수·인원 상한 | 문서에 없다. 기본 채널만 그룹당 100개로 명시돼 있다 |
| 기본 생성 권한 | **소유자·관리자만.** 멤버에게 열려면 관리자가 따로 허용한다 |

현재 우리 매니페스트에 `usergroups:write` 는 **없다.** 넣으면 전 워크스페이스 재승인이
필요하다.

### 4.2 JOBDUTY 값의 모양

재직·인사연동 대상 기준 **89개** (전체로는 111개).

```
안전관리(현장)   368      관리/자재(현장)   58     C/S            14
건축공사(현장)   363      CAD기사           45     IT기획         11
토목공사(현장)   275      주택/개발수주영업 25     내부회계관리    8
관리보           243      민자사업영업/관리 27     …
```

그룹으로 만들 때 걸리는 것 셋:

1. **`/` 와 괄호가 들어간다.** `관리/자재(현장)`·`C/S`·`주택/개발사업관리` 는 handle
   로 쓸 수 없다. 정규화 규칙이 필요하고, 정규화하면 `관리-자재-현장` 처럼 원래 값과
   달라져 **사람이 찾을 이름과 어긋난다.**
2. **워크스페이스를 넘나든다.** 사용자 그룹은 워크스페이스 단위다. `안전관리(현장)`
   368명 전원이 한 워크스페이스에 있지 않으므로, 워크스페이스마다 **그 안에 실제로
   있는 사람만** 넣어야 한다. 없는 사람을 넣을 방법도 없다.
3. **89개는 많다.** 워크스페이스 4개면 최대 356개 그룹을 우리가 계속 맞춰야 한다.
   인사 스냅샷마다 `usergroups.users.update` 를 그만큼 호출한다.

### 4.3 권고 — 전체 자동 생성은 하지 않는다

만들 값어치가 있는 것과 없는 것이 섞여 있다. `내부회계관리 8명` 을 위해 그룹을 만들고
평생 동기화할 이유가 없고, `안전관리(현장) 368명` 은 그 워크스페이스에 몇 명이 있는지가
먼저다.

그래서 **요청 기반**으로 한다.

| 만들 것 | 근거 |
|---|---|
| `@조직장` | 119명. 하나의 그룹으로 의미가 분명하다. 공지 대상이 곧 이 집합이다 |
| 사람이 요청한 직무 몇 개 | 안전·품질처럼 실제로 한꺼번에 부를 일이 있는 것만 |

만들지 않을 것: 89개 전체 자동 생성, 그리고 132개 조직 단위 그룹 자동 생성.

동기화는 **덮어쓰지 않고 비교만 해서 알린다** 를 먼저 한다. 사람이 Slack 에서 손으로
넣은 멤버를 우리가 조용히 지우면, 그건 우리가 만든 사고다. 그룹 소유를 우리가 갖는 것이
확정된 뒤에 자동 반영으로 넘어간다.

### 4.3.1 문서로 확인되지 않은 것 — 첫 그룹을 만들 때 실측한다

Slack 문서에 **없는** 항목이다. 모르는 것을 추정으로 적어 두면 나중에 그게 근거로
쓰인다.

- handle 에 허용되는 문자 — `bad_handle` 오류로만 알 수 있다. 한글 handle 가능 여부 포함
- 워크스페이스당 그룹 개수 상한
- 그룹당 인원 상한

그래서 `@조직장` 하나를 먼저 만들어 이 셋을 확인하고, 그 결과를 이 절에 적은 뒤
다음으로 넘어간다.

## 5. 조사에 쓴 도구

```bash
# 조사 전용 계정(GW_PROBE_*)으로 원본 스키마를 본다. SELECT 만 실행한다.
python scripts/oracle_probe.py --probe --schema COVI_SMART4J --table SYS_OBJECT_USER
python scripts/oracle_probe.py --probe --schema COVI_SMART4J --values SYS_OBJECT_USER.JOBDUTY
```

`--probe` 는 `GW_PROBE_USER`/`GW_PROBE_PASSWORD` 를 쓴다. 그 계정은 `UPDATE ANY TABLE`·
`DROP ANY TABLE` 을 갖고 있어서 `ORACLE_USER` 자리에 넣으면 "봇은 뷰 2개만 읽는다" 는
설계가 무의미해진다. 그래서 변수를 분리하고 호출할 때 명시하게 했다.

**조사가 끝나면 `.env` 에서 `GW_PROBE_*` 를 지운다.**
