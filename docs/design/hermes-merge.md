# Hermes 아카이브 병합 설계

_2026-08-27 · Hermes(`tec-wmo6240`)는 TYBot 의 **합병 대상**이다. MD 아카이브를 중앙으로 옮긴다._

## 이 문서가 다루는 것
Hermes 의 MD 아카이브와 첨부를 중앙 아카이브로 **한 번** 옮기는 작업. 되돌리기가
가장 어려운 작업이므로, 무엇을 검사하고 무엇을 거절하는지 먼저 못 박는다.

> 병합 이후 Hermes 를 요약 프로바이더로 호출하는 안(B-28)은 **과도기 수단**이 된다.
> 데이터가 우리 쪽에 있으면 남은 문제는 "왜 Hermes 요약이 더 좋은가" 뿐이고,
> 그건 프롬프트·구조를 가져오는 문제다. 상시 의존을 만들 이유가 사라진다.

---

## 절대 통과시키지 말 것 (병합 게이트)

### G1. 봇이 생성한 문장은 원문으로 들어오지 않는다
**가장 위험한 항목.** Hermes 가 자기 요약·답변을 아카이브에 남겼다면, 그것을 가져오는
순간 원칙 1(요약 재귀 금지)이 **데이터에 굳는다.** 우리 봇은 "원문만 근거" 라는 전제로
출처를 붙이므로, 그 원문이 실은 봇 요약이면 틀린 내용이 출처를 달고 사실이 된다.

병합 후에는 구별할 방법이 없다. 판별 재료:
- 발화자가 Hermes 봇 계정·앱인 라인
- `bot_id` / `app_id` 흔적, "요약", "출처:" 같은 봇 출력 서식
- Hermes 쪽에 별도 요약 파일·섹션이 있는지

**판별이 불확실한 라인은 가져오지 않는다.** 원문 손실보다 오염이 비싸다.

### G2. 권한은 막는 쪽이 기본값
- 임포트되는 모든 문서는 `visibility: private` 로 들어온다. `[공개]` 를 **부여하지 않는다**.
- `acl` 은 원래 채널 기준으로 채운다. 원래 채널 멤버십을 알 수 없으면 비공개로 두고
  **사람이 결정**하게 남긴다(문서에 표시 + 리포트에 목록).
- 크로스 워크스페이스 노출(`share_with`)은 임포터가 절대 자동 설정하지 않는다(원칙 4).

편의로 공개를 붙이는 순간, 데이터 이관 한 번으로 원칙 3 이 무력화된다.

### G3. PII 스캔은 병합 **전에**
Hermes 아카이브는 우리 제외 규칙(원칙 5) 없이 쌓였다. 등기부등본·계약자 명단·
주민번호가 이미 있을 수 있다. 병합 후 스캔은 늦다 — 그 시점에 이미 검색 대상이다.

기존 수집 경로가 쓰는 거절 규칙을 임포트에도 **같은 코드로** 적용한다.
거절된 항목은 원문을 리포트에 싣지 않고 위치와 사유만 남긴다.

### G4. 원문 불변 · 출신 기록
- 원문 블록은 편집하지 않는다. 형식 변환이 필요하면 **새 라인으로** 쓰고 변환 사실을 남긴다.
- 프론트매터에 출신을 남긴다: `imported_from: hermes/tec-wmo6240`, `imported_at`,
  `source_path`. 나중에 "이 줄은 어디서 왔나" 를 답할 수 있어야 한다.
- 출처 표기에 출신이 드러나야 한다 — 사람이 두 시점을 구분할 수 있게(원칙 7).

### G5. 멱등 · 드라이런 우선
- `--dry-run` 이 기본. 리포트를 사람이 본 뒤에만 실제 쓰기.
- 두 번 돌려도 같은 결과여야 한다(`dedupe_key` 사용).
- 실패 시 부분 상태가 남지 않게, 문서 단위로 원자적으로 쓴다.
- 리포트는 `archive/` **밖에** 쓴다(검색 대상이 되면 요약 재귀의 통로가 된다).

## 확인해야 하는 것 (Hermes 담당자)

| 질문 | 왜 필요한가 |
|---|---|
| 아카이브에 **봇 답변·요약이 저장돼 있나** | G1. 있으면 판별 규칙을 먼저 만들어야 한다 |
| MD 형식·프론트매터 필드 | 스키마 매핑. 우리 필수 필드에 없는 값이 무엇인지 |
| 채널·멤버십 정보가 파일에 있나 | G2. 없으면 전부 비공개로 들어가고 사람이 결정해야 한다 |
| 첨부 원본을 보관하나, 링크만 있나 | 링크만이면 이관 후 깨진다. 본문 변환분만 남는다 |
| 개인정보 제외 규칙이 있었나 | G3 스캔 강도 |
| 전체 규모(문서 수·용량) | 처리 시간·rate limit 무관하지만 검토 인력 산정 |
| 봇 종료 시점 | 두 봇이 같은 채널에 답하면 중복 답변·비용 2배 |

**샘플 MD 파일 1건**(민감정보 마스킹)만 있으면 임포터 초안을 만들 수 있다.

## 전환(cutover)

1. Hermes 아카이브 스냅샷 → 드라이런 → 리포트 검토
2. 실제 임포트(비공개로) → `상태` 로 문서 수 확인
3. 공개 범위 결정 — 채널·문서 단위로 사람이 `scripts/share.py` 사용
4. **Hermes 봇 정지** → TYBot 을 해당 워크스페이스에 설치
   (동시 가동 금지: 같은 채널에 두 봇이 답하면 중복 답변 · LLM 비용 2배)
5. 1주일간 `qa-log` 로 답변 품질 비교 — 골든셋(B-27)을 같은 질문으로 돌린다

## 왜 Hermes 요약이 더 좋은가 — 병합과 별개로 답해야 한다
데이터를 옮겨도 요약 품질은 자동으로 따라오지 않는다. 원인을 나눠 본다:
- **프롬프트** → 가져온다. 우리 요약 지시는 현재 한 줄이다
- **모델 선택** → 라우터 설정으로 끝난다
- **구조**(채널별 2단 요약, 자체 인덱스 등) → 설계를 가져올 가치가 있다
- **데이터가 더 많았을 뿐** → 병합으로 해결된다

골든셋 30건을 양쪽에 돌리면 어느 쪽인지 갈린다(B-27).
