# 봇과의 DM — 개인 작업공간

> 결정: 2026-09-18 (오너). 백로그: B-57
> 상위 문서: [`bot-hierarchy.md`](bot-hierarchy.md) · [`db-and-acl.md`](db-and-acl.md)

## 1. 무엇을 바꾸는가

지금까지 DM 은 **질문을 받는 창구**였을 뿐이다. DM 에 올린 파일은 어디에도 저장되지
않았고, DM 에서 오간 이야기는 다음 질문의 맥락이 되지 못했다.

> "봇과의 DM 도 아카이빙하자. 그래야 봇과의 DM 을 일반적인 LLM 처럼 쓸 수 있으니까.
> 또 채널과 다르게 DM 은 맥락을 더 강력하게 작용시키자." — 오너 (2026-09-18)

그래서 DM 을 **그 사람 한 명의 작업공간**으로 만든다. 채널이 조직의 기록이라면
DM 은 개인의 기록이다. 둘은 저장 위치도, 권한도, 맥락 규칙도 다르다.

| | 채널 | 봇과의 DM |
|---|---|---|
| 무엇을 쌓나 | 사람의 대화·첨부 | 사람의 말·첨부 (**봇 답변은 안 쌓는다**) |
| 누가 보나 | 채널 멤버 | **그 사람만** (exec·root 도 예외 아님) |
| 어디서 보이나 | 그 채널 질문 + DM 통합조회 | **DM 질문에서만** |
| 맥락 | 스레드 단위 | 최근 N턴 + 시간창 (스레드 아니어도 이어진다) |
| 요약 검토 | 채널 검토자 | 없음 (검토자가 없으므로 후보를 만들지 않는다) |

## 2. 절대 원칙과의 관계

이 기능은 원칙 1·3·5 를 동시에 건드린다. 각각 어떻게 지키는지 먼저 적는다.

### 원칙 1 — 봇 발언은 원문이 아니다

**DM 에서도 봇 답변은 아카이브에 쓰지 않는다.** 사람이 쓴 말과 올린 파일만 쌓는다.

DM 대화가 「일반 LLM 처럼」 이어지는 것은 **맥락**이 하는 일이지 **근거**가 하는 일이
아니다. 이 저장소는 둘을 이미 분리해 두었다.

| | 어디에 있나 | 무엇에 쓰나 |
|---|---|---|
| 맥락 | QA 기록(`qa-*.jsonl`)의 이전 문답 + `evidence_refs` 좌표 | 지칭 해석("아까 그거"), 후속 질문 범위 |
| 근거 | 아카이브 원문 MD | 답변의 사실 |

봇 답변을 원문에 넣으면 다음 질문이 그 문장을 **사실로** 인용한다. 한 번 잘못 말한
숫자가 원문처럼 굳고 되돌릴 방법이 없다. 오너 결정(2026-09-18)도 같다 —
사람 발언·첨부만 원문, 봇 답변은 대화 기록에만.

### 원칙 3 — 막는 쪽이 기본값

DM 문서는 **기본적으로 보이지 않는다.** 세 조건을 전부 만족할 때만 열린다.

1. 같은 워크스페이스
2. `ctx.user_id == dm_user` — 그 DM 의 당사자 본인
3. **채널 질문이 아니다** — 채널에서 물으면 답을 다른 사람이 함께 본다

`exec`·`is_root` 는 예외가 아니다. 통합조회 권한은 **조직의 기록**을 보는 권한이지
남의 개인 공간을 보는 권한이 아니다. 그래서 이 판정은 `can_access()` 의 **맨 앞**에
둔다 — 뒤에 두면 `role == "exec"` 의 조기 반환에 걸려 통과한다.

`ctx.user_id` 가 비어 있으면 DM 문서는 보이지 않는다. 콘솔·배치·스크립트처럼
사용자가 특정되지 않는 경로는 그래서 자동으로 제외된다.

### 원칙 5 — PII

DM 이라고 검사를 늦추지 않는다. 채널과 **같은** `pii_screen` 을 통과한 것만 쌓는다.
오히려 DM 은 개인이 자기 파일을 올리는 자리라 걸릴 확률이 높다. 거부되면 그 사실을
그 사람에게만 알린다.

## 3. 저장 구조

```text
workspaces/<ws>/channels/<channel-id>__<name>/raw/<날짜>.md   ← 기존
workspaces/<ws>/dm/<user-id>/raw/<날짜>.md                     ← 신규
```

디렉터리를 나누는 이유는 **기본 제외**를 경로로 보장하기 위해서다. `ArchiveStore` 의
문서 열거는 DM 을 **넣지 않는 것이 기본값**이고, 답변 경로(`visible_docs`)와 색인만
명시적으로 켠다. 채널을 훑는 기존 소비자(콘솔 채널 목록, 채널 헬스, 조직 매핑,
요약 검토)는 **한 줄도 고치지 않아도** DM 을 보지 않는다.

프론트매터는 v2 그대로에 한 줄을 더한다.

```yaml
schema_version: 2
workspace: tyit
channel: "DM:U0BR..."     # 사람마다 다르다 — 한 이름으로 합쳐지면 안 된다
channel_id: D0BR...
dm_user: U0BR...          # 이 줄이 있으면 DM 문서다
visibility: private
acl: []                   # 채널 멤버십으로는 열리지 않는다
source_date: 2026-09-18
```

`channel` 을 사람마다 다르게 두는 이유는 검색 색인 때문이다. `raw_line.channel` 이
모든 DM 에서 같은 값이면 한 사람의 질의가 다른 사람 DM 줄을 후보로 끌어올린다.
최종 판정은 `visible_docs()` 가 다시 하므로 새어 나가지는 않지만, **판정 하나에만
기대는 구조를 만들지 않는다.**

출처 표기는 `[DM]나와의 대화, 📄2026-09-18.md(2026-09-18)` 로 보인다. 채널명을
그대로 보이면 `DM:U0BR...` 라는 내부 키가 사람에게 나간다.

## 4. 수집 경로

```text
DM 메시지 도착
   ├─ 봇·시스템 메시지  → 버린다 (_is_human_request)
   ├─ `정정:` 으로 시작 → 피드백 경로 (기존)
   └─ 사람 질문
        1. 수집   — 본문·첨부를 그 사람의 DM 아카이브에 쌓는다
        2. 답변   — 방금 수집한 첨부를 **이번 답변의 근거로 함께** 넣는다
```

순서가 핵심이다. 지금은 답변만 하고 수집을 하지 않아서, 질문에 파일을 붙여도
그 파일이 근거가 될 방법이 없었다(2026-09-18 문제 패킷 `98fa5853`·`4d98bb66`).

첨부는 채널과 **같은** 경로(`stage_attachments`)로 내려받고 변환한다. 새 입구를
만들지 않는다 — 중복 방지·PII 검사·변환이 전부 그 경로에 있고, 새로 짜면 그 입구만
헐거워진다.

### 이번 질문의 첨부를 근거로

수집이 끝나면 그 줄은 아카이브에 있다. 그래도 **검색에 맡기지 않는다.** 사람이 방금
올린 파일은 「찾아야 하는 자료」가 아니라 「이 질문의 입력」이다. 검색어가 파일 내용과
어긋나면 바로 옆에 둔 파일을 못 찾는다.

그래서 방금 수집한 줄을 좌표로 만들어 검색 결과 **앞에** 붙인다. 검색을 끄지는
않는다 — 첨부만 보고 답하면 "이 목록이 슬랙 어디에 있나" 같은 질문에 답할 수 없다.

## 5. 맥락 — DM 은 더 강하게

지금은 DM 에서 지칭 정규식(`방금|아까|이전…`)에 걸릴 때만 이전 문답을 싣는다.
그 규칙이 CLAUDE.md 가 금지한 자리다 — **규칙이 LLM 판정을 가로챈다**(B-47).
한국어 활용형은 반드시 새고, 새면 사람은 "어제 한 얘기를 기억 못 한다" 고 느낀다.

바꾸는 것은 하나다. **DM 이면 최근 문답을 항상 싣고, 이어서 물은 것인지는 분해기
(LLM)가 판단한다.** 범위는 최근 `THREAD_TURNS`턴 · `DM_CONTEXT_WINDOW_MINUTES` 안.

- 턴 수와 시간창을 두는 이유: 무제한이면 오래된 주제가 새 질문에 섞이고 토큰이
  대화 길이에 비례해 는다.
- 싣는 것은 **질문과 좌표**다. 봇 답변 전문이 아니다(§2, 원칙 1).
- 주제가 바뀌면 분해기가 `reference_mode=none` 을 준다. 코드가 규칙으로 흉내내지
  않는다 — 한 번 해 봤고 거의 항상 빗나갔다.

## 6. 하지 않는 것

- **DM 을 요약 검토 대상으로 만들지 않는다.** 검토자가 없다. 개인 기록을 남에게
  검토시킬 수 없고, 본인에게 매일 DM 을 또 보내는 것은 소음이다.
- **사람과 사람의 DM 은 수집하지 않는다.** 이 문서가 다루는 것은 **봇과의 DM** 뿐이다.
  `_is_human_request` 를 통과해 봇에게 온 메시지만 쌓인다.
- **DM 자료를 채널 답변에 쓰지 않는다.** §2 원칙 3 의 세 번째 조건.
- **DM 문서를 콘솔 채널 목록·채널 헬스에 올리지 않는다.** 경로 분리로 이미 보장된다.
- **봇 답변을 원문에 쓰지 않는다.** 재귀 차단 관문(`.githooks/pre-commit`)이 그대로
  적용된다.

## 7. 사람이 지울 수 있어야 한다

개인 공간이므로 본인이 지울 수 있어야 한다. 1차 구현 범위 밖이지만 설계에 남긴다 —
`DM 기록 지워줘` 로 그 사람의 DM 아카이브를 통째로 지우는 경로가 필요하다. 그때도
원문 편집은 하지 않는다. **파일 단위 삭제**이고, 지웠다는 사실을 감사 기록에 남긴다.
