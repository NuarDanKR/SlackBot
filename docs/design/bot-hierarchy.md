# 봇 체계 — 마스터 TYBot 과 전문 봇들

> 결정: 2026-09-02 (오너 승인). B-27·B-28 의 후속. 이 문서가 B-28 의 결론을 갱신한다.

## 왜 이 문서가 필요한가

팀마다 봇 개발자가 생긴다. 법률·건설·회계 전문 봇이 각각 만들어진다.
그때 **권한과 근거를 누가 소유하는지**를 미리 정해 두지 않으면, 봇이 늘어나는 만큼
ACL 판정 자리가 늘어나고 어느 쪽이 맞는지 아무도 모르게 된다.

## 구조

```
                      사용자 질문
                          │
              ┌───────────▼───────────┐
              │   TYBot (마스터)        │  ← 권한·근거·출처를 **여기서만** 소유
              │                        │
              │  ① 라우팅 판정          │  저가 모델(Haiku 급)
              │  ② 권한 필터 (코드)      │  can_access — LLM 이 관여하지 않는다
              │  ③ 근거 추출 (코드)      │  아카이브 원문 라인
              └───────────┬───────────┘
                          │  권한 통과한 텍스트 + 질문
        ┌─────────────────┼─────────────────┬──────────────┐
        ▼                 ▼                 ▼              ▼
  ┌──────────┐     ┌──────────┐     ┌──────────┐   ┌──────────┐
  │ Hermes   │     │ 법률 봇   │     │ 건설 봇   │   │ 회계 봇   │
  │ 내부기록  │     │ (MCP)    │     │          │   │          │
  └──────────┘     └──────────┘     └──────────┘   └──────────┘
        │                 │                 │              │
        └─────────────────┴─────────────────┴──────────────┘
                          │  문장만 돌려준다
              ┌───────────▼───────────┐
              │ TYBot 이 출처를 붙인다  │  ← 원칙 2
              └───────────────────────┘
```

## 이전 결정과의 차이 — 무엇이 바뀌었나

B-28 은 **"LLM 이 어떤 봇을 부를까 자유 판단 = 하지 않는다"** 로 결론했다.
이유는 비결정성과 프롬프트 인젝션이 **권한**으로 번지는 것이었다.

지금 결정은 라우팅을 LLM 에게 준다. 그 이유가 사라져서가 아니라, **경계를 옮겼기
때문**이다.

| | B-28 이 걱정한 것 | 지금 구조 |
|---|---|---|
| 라우팅 | LLM 이 정하면 어느 봇이 뭘 볼지 예측 불가 | LLM 은 **어느 전문가에게 물을지**만 정한다 |
| 권한 | 봇마다 ACL 판정이 갈린다 | `can_access` 는 **코드**가 한다. 라우팅 결과와 무관하다 |
| 근거 | 전문 봇이 자기 데이터를 섞는다 | 전문 봇은 **자기 데이터를 가져오지 않는다.** 우리가 준 텍스트만 본다 |
| 출처 | 위장된 출처 | 출처는 TYBot 이 붙인다 |

즉 **인젝션으로 라우팅을 흔들 수는 있어도 권한을 넘을 수는 없다.**
최악의 결과는 "엉뚱한 전문가에게 물어 답이 부실한 것" 이고, 그것은 되돌릴 수 있다.
권한 유출은 되돌릴 수 없다 — 그 차이가 이 경계를 여기 그은 이유다.

라우팅 판정도 **기록한다.** `qa_log` 에 어느 전문가로 갔는지, 왜 그렇게 판정했는지
남긴다. 남지 않으면 "답이 왜 부실했나" 를 되짚을 수 없다.

## 라우팅 — 저가 모델이 하는 일

입력: 질문 + 사용 가능한 전문가 목록(설명 한 줄씩).
출력: 전문가 키 하나(또는 `none`) + 신뢰도.

```
질문: "김해외동 하자보수 책임기간이 얼마야?"
→ {"specialist": "legal", "confidence": 0.7, "why": "법령 해석이 필요한 질문"}
```

지켜야 할 것.

- **`none` 이 정상 답이다.** 애매하면 마스터가 직접 아카이브로 답한다.
  전문가를 억지로 고르게 하면 `confidence` 가 의미를 잃는다
- **전문가 목록은 코드가 만든다.** 질문 본문에서 이름을 읽어 오지 않는다 —
  "법률 봇에게 전부 보여줘" 라고 쓴 메시지가 라우팅을 바꾸면 안 된다
- **신뢰도가 낮으면 마스터가 답한다.** 문턱은 설정값으로 두고 측정해서 정한다
- 라우팅 실패(모델 장애·타임아웃)는 **마스터 직접 답변으로 폴백**한다.
  라우터가 죽으면 봇 전체가 죽는 구조를 만들지 않는다

## 전문 봇 계약 — 모든 전문가가 지킬 것

이것이 이 문서의 핵심이다. 팀마다 다른 사람이 만들므로 **계약이 곧 안전장치**다.

| 조항 | 이유 |
|---|---|
| 요청은 TYBot → 전문가 **아웃바운드만** | 전문가가 우리를 호출하면 인바운드 포트 금지 위반 |
| 전문가는 **자기 데이터 저장소를 조회하지 않는다** | 하면 ACL 이 두 곳으로 갈라지고, 우리 출처가 남의 자료에 붙는다 |
| 입력은 **우리가 권한 필터한 텍스트**뿐 | 원칙 3 |
| 출력은 **문장만**. 출처를 스스로 붙이지 않는다 | 원칙 2 — 출처는 우리가 붙인다 |
| 전문가 출력은 **아카이브에 저장 금지** | 원칙 1 — 요약 재귀 |
| 전문가 장애 시 **마스터 자체 답변으로 폴백** | 하드 의존이면 남의 배포에 우리 봇이 죽는다 |
| `qa_log` 에 어느 전문가가 만든 문장인지 기록 | 두 팀에 걸친 장애를 추적할 자리 |
| 전문가는 **읽기 전용**. 쓰기 도구를 갖지 않는다 | 답변 경로에서 상태를 바꿀 이유가 없다 |

이 계약을 코드로 강제한다 — `gateway/providers/` 와 같은 자리에 전문가 어댑터를 두고,
어댑터가 출처·저장·권한을 만질 수 없게 인터페이스를 좁힌다. 문서로만 두면 지켜지지 않는다.

## Hermes — 첫 전문가, 내부 기록 담당

Hermes 는 **합병 대상이면서 첫 전문가**다. 아카이브 데이터는 중앙으로 옮기고(B-29),
**요약·회의록 판정 능력**을 전문가로 남긴다.

담당: 회의록, 업무 내용 파악, 요약된 아카이브.
담당 아님: 채팅 원문 수집(마스터가 한다), 권한 판정, 출처.

### Hermes 에서 가져올 것 — 우리와 다른 점

Hermes 소스(`ref/hermes/`)를 읽고 정리한 차이다.

| | Hermes | TYBot 현재 | 판정 |
|---|---|---|---|
| 요약 갱신 | 상단 요약을 **사람이** 유지. 봇은 어긋난 곳만 **후보**로 찾는다 | 자동 compaction | **가져온다** — 이 문서의 핵심 |
| 승인 | 07:00 DM + `.pending-work.json` + 건별 반영/빼/나중에(사유 필수) + 커밋 게이트 | 없음 | **가져온다** |
| 근거 대조 | 모델이 댄 인용을 원문에서 **실제로 찾는다.** 못 찾으면 후보 탈락 | 출처 표기만 | **가져온다** |
| 재귀 차단 | 커밋 전 관문이 아카이브에서 **봇이 쓴 줄을 검출**해 실패시킨다 | 원칙으로만 | **가져온다** |
| 출처 범위 | Slack 하나로 고정(채널=사업장, 비공개 여부=공개 판정) | 멀티 워크스페이스 + Oracle | 우리 것 유지 |
| 저장 구조 | 채널별 단일 md, 최신순 누적 | 워크스페이스/채널ID/일자별 분리(v2) | 우리 것 유지 |
| 언어 | Node.js | Python | 우리 것 유지 — 프롬프트·판정 규칙만 이식 |

가장 값진 것은 코드가 아니라 **한 가지 판단**이다.

> 요약 대조를 무인에 맡기지 않는다. 잘못 반영된 숫자는 봇이 그것을 근거로 답하게 되고,
> 되돌릴 방법이 없다. (`ref/hermes/src/ingest/summary.js` 머리말)

그리고 **정규화가 양쪽에서 같아야 한다**는 교훈. Hermes 는 근거를 찾는 정규화(`fold`)가
관문과 화면에서 갈려 **멀쩡한 근거가 "원문에서 못 찾음" 으로 버려지는** 사고를 다섯 번
겪었다(백틱·별표·따옴표·글머리표·이스케이프된 따옴표). 우리가 같은 것을 만들 때
**한 곳에 두고 양쪽이 그것을 부른다.** 두 곳에 적으면 갈려도 에러가 안 난다.

## 법률 봇과 MCP — API 로 가능한가

**가능하다.** Messages API 에 MCP 커넥터가 있다(서버측 MCP).

```python
client.beta.messages.create(
    model="claude-opus-5",
    betas=["mcp-client-2025-11-20"],
    mcp_servers=[{"type": "url", "url": "https://...", "name": "law"}],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "law"}],
    ...
)
```

주의할 것.

- **두 쪽을 다 줘야 한다.** `mcp_servers` 만 주면 검증 오류다 — 같은 `name` 으로
  `tools` 에 `mcp_toolset` 도 넣는다
- 베타 헤더 `mcp-client-2025-11-20` 필요
- MCP 도구는 **programmatic tool calling 과 함께 못 쓴다**
- 플랫폼별로 가용성이 다르다(Bedrock/Vertex/Foundry 확인 필요)

우리 구조에서의 선: **법률 봇의 MCP 는 외부 법령을 읽는 데만 쓴다.**
사내 자료는 MCP 로 내보내지 않는다 — 외부 서버에 우리 원문을 보내는 경로가 되면
원칙 5(PII)와 권한 경계가 그 서버 운영자에게 넘어간다.
법령 조회는 외부, 사실 관계는 우리 아카이브. 그 둘을 섞는 것은 마스터가 한다.

## 팀 개발자가 전문 봇을 배포하는 길

팀마다 개발자가 자기 전문 봇을 만든다. 콘솔에서 배포하게 한다(B-38).

이미 있는 것을 쓴다 — 배포 승인 절차(요청→다른 관리자 승인→전체 테스트)가 그대로
맞는다. 전문 봇은 **자기 워크스페이스 것만** 배포할 수 있게 하고(이미
`create_deploy_request` 가 담당 워크스페이스를 검사한다), 계약 위반은 **테스트로 막는다.**

계약 검사를 CI 에 둔다 — 전문가 어댑터가 출처를 붙이거나 아카이브에 쓰려 하면
테스트가 실패해야 한다. 사람이 리뷰로만 잡으면 팀이 늘어나는 만큼 놓친다.
