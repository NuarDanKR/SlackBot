# 답변 피드백·수집 품질 정책

_2026-08-27 회의 결정 반영_

## 즉시 적용

| 항목 | 정책 |
|---|---|
| Bot 메시지 | 채널·Thread 구분 없이 작성 주체가 Bot이면 원문 아카이브에서 제외 |
| 일반 임직원 DM | 수집하지 않음 |
| 사용자 ↔ TYBot DM | 질문·답변·출처·응답시간·오류를 `qa-log/`에 기록. 검색 근거로 사용 금지 |
| 답변 평가 | TYBot 답변의 👍/👎와 답변 스레드의 `@tybot 정정: ...`을 별도 JSONL에 기록 |

피드백은 `qa-log/feedback-YYYY-MM.jsonl`에 append-only로 저장한다. 답변 본문과 검색 원문은
복제하지 않고 QA 레코드 ID로 연결한다. Reaction 취소도 삭제하지 않고 `removed` 이벤트를 남긴다.

## Bot 메시지 예외 수집

Bot 답변을 명령이나 Tag로 원문 아카이브에 넣는 기능은 만들지 않는다. 사용자가 명시했더라도
Bot 출력이 다음 답변의 사실 근거가 되면 요약 재귀가 발생한다. 업무 사실로 남겨야 한다면 사람이
원문을 확인한 뒤 자신의 발언으로 `정정:` 또는 `확정:` 내용을 작성한다. 이 인간 발언은 기존
원문 보존 규칙에 따라 수집할 수 있지만 Bot 답변 자체는 계속 제외한다.

## 후속 작업

### MD 최종 검수

첨부 변환물은 검색 가능한 아카이브에 바로 등록하지 않고 검수 대기 영역에 둔다. 승인자는 중복,
구버전, 변환 오류, 불필요 자료를 확인한 후 등록한다. 원문 채널 대화의 실시간 append 정책과
첨부 변환물 승인 정책은 분리한다.

### 계층 기준

조직마다 상위 기준을 설정으로 둔다: 프로젝트금융=사업장, 건축·토목=현장,
투자사업=프로젝트, 경영·전산=업무영역 또는 시스템. 하나의 고정 계층을 전 조직에 강제하지 않는다.

### OCR·이미지

OCR 결과는 `source_quality: ocr`처럼 기계 판독임을 표시하고, 인용 답변에는 원본 확인 권고를
코드가 붙인다. 현재 구현은 OCR을 수행하지 않으므로 샘플 문서로 정확도·표·도면 처리 범위를
검증한 뒤 도입한다.

## 골든셋 후보

다음 이벤트를 우선 후보로 삼는다: 👎, 정정, `reason=no_hits`, `reason=error`, 짧은 시간 안의
재질문. 후보는 자동으로 학습·규칙에 반영하지 않고 사람이 검토해 골든셋에 추가한다.
