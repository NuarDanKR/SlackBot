# 관리 콘솔 설계

_결정 문서 · 2026-08-21 · 2026-09-02 구현 상태 갱신_

현업(비개발자)이 바이브코딩으로 워크스페이스 봇을 개선하는 구조에서, **서버 접속 · `git pull` ·
`.env` 편집을 사람 손에서 걷어내는 것**이 이 콘솔의 목적입니다.

---

## 0. 이 콘솔은 보안 경계를 하나 바꿉니다

지금 시스템의 전제는 **인바운드 포트 0개**입니다(Socket Mode 아웃바운드 전용). 웹 콘솔은 포트를
열고, 배포 승인 버튼은 본질적으로 원격 코드 실행 창구입니다. 그래서 노출 경로와 게이트를 코드보다
먼저 정했습니다.

| 항목 | 결정 |
|---|---|
| 노출 경로 | **미정.** 현재 배포 서비스는 `127.0.0.1` 에만 바인딩 |
| 스택 | React + Vite SPA + FastAPI |
| 승인 권한 | **관리자.** 개발자는 요청만 하고 관리자가 승인 |
| 로그인 | 회사 이메일·비밀번호 → HttpOnly 세션 쿠키(SameSite=strict) |
| 배포 게이트 | 자동 검사 4종 통과 + 승인 + 실패 시 자동 되돌리기 |
| DB | 기존 PostgreSQL |

현재 운영 화면은 실제 API가 있는 기능만 노출합니다. 데이터 현황·문서·사용량·헬스 체크·서비스
로그·환경변수·콘솔 사용자는 실제 서버 데이터를 사용하고, 봇 규칙은 읽기 전용입니다. 아직 쓰기
API가 없는 배포 승인·워크스페이스 관리·규칙 변경 요청은 메뉴에서 숨깁니다. 프런트 예시 데이터를
운영 수치나 경고와 섞어 표시하지 않습니다.

사내 원격접속망은 현재 없으며, 콘솔을 어느 범위에 노출할지는 아직 결정하지 않았습니다. 노출 경로와
접근 통제가 승인되기 전에는 `deploy/tybot-console.service` 의 루프백 바인딩을 유지합니다.

서버(Rocky 8)는 인터넷이 연결되어 있으므로 한글 웹폰트는 CDN 에서 불러오고, 프론트 빌드
산출물(`dist/`)만 서버로 옮깁니다.

## 1. 화면

| 메뉴 | 답하는 질문 |
|---|---|
| 데이터 현황 | 원문이 지금도 쌓이고 있나. 어느 워크스페이스가 멈췄나 |
| 수집 문서 열람 | 봇이 실제로 무엇을 저장했나. 첨부 변환은 제대로 됐나 |
| API 사용량 | 오늘 얼마 썼나. 평소보다 이상한가. 누가 쓰고 있나 |
| 봇 규칙 열람 | 서버에 배포된 답변 규칙과 업무 흐름은 무엇인가 |
| 환경변수 설정 | 수집 범위와 워크스페이스 간 조회 범위를 어떻게 바꾸나 (관리자 전용) |
| 서비스 로그 | `tybot.service`의 INFO·WARNING·ERROR 기록을 어떻게 확인하나 (개발자 이상) |
| 콘솔 사용자 관리 | 회사 이메일 계정과 게스트·개발자·관리자 권한을 어떻게 관리하나 (관리자 전용) |

메뉴 이름과 화면 제목은 **같은 말을 씁니다.** 화면 제목에 표어를 쓰면 지금 어느 메뉴에 있는지
헷갈립니다. 설명은 제목 아래 문장으로 풀어 씁니다.

## 2. 디자인 규칙

### 서체 (네이버 무료 한글 글꼴)
| 역할 | 글꼴 | 쓰는 곳 |
|---|---|---|
| 제목 | 나눔스퀘어 Neo | 화면 제목 · 구역 제목 · 카드 제목 |
| 일반 UI | 나눔스퀘어 라운드 | 본문 기본값 · 설명문 · 라벨 · 버튼 |
| 문서 미리보기 | 마루 부리 | 수집 문서·규칙 문서 미리보기 한 곳만 |
| 수치·커밋해시·경로·토큰 | IBM Plex Mono | 숫자와 ASCII 만 |

모두 네이버 공식 CDN(`hangeul.pstatic.net`)에서 불러옵니다. 서버에 인터넷이 있으므로 폰트를
저장소에 내장하지 않습니다.

두 가지를 확인하고 고쳤습니다.

1. **구 나눔스퀘어 woff2 에는 한글 글리프가 없었습니다.** jsDelivr 의 155KB 파일을 물렸더니
   제목이 조용히 나눔스퀘어 라운드로 폴백됐습니다(브라우저에서 렌더 폭을 재서 확인).
   한글이 들어 있으면 woff2 가 380KB 이상입니다. 네이버가 현재 배포하는 **Neo** 로 교체했습니다.
2. **화면 설명문에는 마루 부리를 쓰지 않습니다.** 명조꼴은 긴 글을 읽는 자리에만 맞습니다.
   두 줄짜리 설명에 쓰면 UI 가 아니라 문서처럼 보입니다. 마루 부리는 MD 미리보기에만 남겼습니다.

**한글 라벨에 Mono 를 쓰지 않습니다.** IBM Plex Mono 에는 한글 글리프가 없어 폴백되고, 자간까지
어긋나 조악해 보입니다.

### 색
CI 컬러 `#800020` 는 **강조·포인트 전용**입니다. 쓰는 자리는 네 곳뿐입니다.
브랜드 표식, 활성 메뉴 표시, 주요 실행 버튼, 사용량 최고점 막대.

상태는 CI 색이 아니라 기능색으로 표시합니다 — 파랑(진행·데이터), 초록(정상), 주황(주의),
빨강(실패). CI 색을 상태 표시에까지 쓰면 "지금 중요한 것"이 화면에서 구분되지 않습니다.

**채워진 면에는 다크 모드에서도 `#800020` 원색을 씁니다**(`--brand-solid`). 흰 글자와 대비가
9.7:1 이라 문제가 없습니다. 3px 세로선이나 배지 글자처럼 얇은 요소만 어두운 지면에서 한 단
밝은 같은 계열(`--brand`)을 씁니다.

### 문체
- 화면에 나오는 모든 문장은 **친절하고 자세하게** 씁니다. 사용자는 개발자가 아닙니다.
- 시스템 용어가 아니라 사람이 하는 일로 씁니다. "커밋 반영" 대신 "승인하고 반영".
- 실패 화면은 무엇이 잘못됐고 무엇을 하면 되는지 함께 적습니다.
- 버튼 이름과 결과 알림의 말을 맞춥니다. `승인하고 반영` → "승인했습니다. 반영을 시작합니다."

## 3. 권한과 승인을 분리합니다

역할은 세 단계이며 관리자는 여러 명일 수 있습니다. 개발자가 변경을 요청하고 관리자가 승인합니다.

| 보는 사람 | 화면 |
|---|---|
| 관리자(admin) | 전체 접근. 검사를 통과한 요청에 `승인하고 반영` · `반려` 버튼이 열립니다 |
| 개발자(developer) | 데이터·봇 관리. 변경 요청은 할 수 있지만 자기 요청을 승인할 수 없습니다 |
| 게스트(guest) | 데이터 현황·문서 목록·API 사용량만 읽을 수 있습니다 |

담당자에게는 자기 워크스페이스 범위의 데이터만 보입니다. 쓰기 API가 준비되기 전에는 역할과
무관하게 배포 승인·워크스페이스 관리 메뉴를 노출하지 않습니다.

## 4. 지켜야 할 제한

### A. 아카이브 원문 열람은 관리자 전용 + 열람 기록 (수정됨)
당초에는 "콘솔은 원문을 표시하지 않는다"로 두었습니다. 수집이 제대로 되는지 눈으로 확인해야 하는
운영상 필요가 있어 **열람 화면을 두되 세 가지를 함께 겁니다.**

1. 원문 본문(`content`)은 `role === 'admin'` 인 사용자에게만 내려보냅니다. 그 외 역할은 목록과
   수집 상태(줄 수, 첨부 추출 줄 수, 마지막 수집 시각, 형식 오류)만 봅니다.
2. 열람 자체를 감사 기록에 남깁니다(누가·어느 문서를·언제). 콘솔에서 지울 수 없습니다.
3. 화면에도 그 사실을 적습니다. 관리자도 한 번 더 확인 버튼을 눌러야 본문이 열립니다.

이유: 이 문서들은 Slack 채널 멤버십으로 보호되던 대화입니다. 콘솔에서 아무나 열 수 있으면
권한 3층이 무의미해집니다. 열람 범위를 더 좁히려면 1번 조건을 조이면 됩니다.

### B. 시크릿은 DB 평문 금지 · 복호화 조회 API 없음
봇/앱 토큰은 암호화해 저장하고(키는 systemd credential), 콘솔에는 마스킹된 문자열만 내려줍니다.
"저장된 토큰 보기" 기능은 만들지 않습니다. 잘못 넣었으면 덮어씁니다.

### C. 요청자 ≠ 승인자
담당자가 요청하고 관리자가 승인합니다. 검토 없이 운영에 들어가는 것을 막는 유일한 장치입니다.

### D. 자동 검사 통과 전에는 승인 버튼이 열리지 않습니다
배포는 `pytest` · `ruff` · 아카이브 스키마 · 시크릿 패턴 4종.
규칙 문서 편집은 문서 형식 · 시크릿 · 금지 표현(PII) · 규칙 충돌 4종.

### E. 실행 가능한 동작은 반영 / 재기동 / 되돌리기 셋뿐
명령 입력창을 두지 않습니다. `sudoers` 는 `systemctl restart tybot` 만 허용하고, 콘솔
프로세스는 별도 저권한 유저로 돌립니다. fast-forward 가 아닌 병합은 반영하지 않습니다.

### F. 반영 후 90초 확인 실패 → 직전 상태로 자동 되돌리기
승인은 10분간 유효합니다. 그 사이 새 커밋이 올라오면 다시 승인해야 합니다.

### G. 워크스페이스별 개별 비용 상한 + 급증 시 차단
지금 `DAILY_COST_LIMIT_USD` 는 전 워크스페이스 합산 하나입니다. 한 팀의 폭주가 전체 상한을
먹습니다. 워크스페이스별 상한을 두고, 기준선(최근 14일 같은 시각 중위값) 대비 급증 시 해당
워크스페이스 호출만 멈춥니다.

### H. 봇 단일 인스턴스 락을 콘솔보다 먼저 (구현됨)
콘솔이 재기동 권한을 쥐는 순간 이중 기동 위험이 실재합니다(중복 답변 + LLM 비용 2배).
`src/tybot/lock.py` 에서 두 가지를 막습니다.

| 락 | 무엇을 막나 | 잡는 곳 |
|---|---|---|
| `instance-bot` | 봇 프로세스 이중 기동 | `pilot.main()` — Slack 에 연결하기 **전에** |
| `instance-collect` | 정기 백필 회차 겹침 | `collect.main()` |
| `archive-write` | 서로 다른 프로세스의 MD 동시 append | `writer.ingest()` 안 |

봇과 백필은 서로를 막지 않습니다(락 이름이 다릅니다). 둘이 동시에 돌아도 되는 이유는 아카이브
쓰기를 따로 직렬화하기 때문입니다.

`DATABASE_URL` 이 없으면 파일 락으로 동작합니다 — 같은 서버 안의 중복 기동은 막습니다.
값을 넣으면 advisory 락으로 바뀌어 여러 서버에 걸친 경우까지 막습니다.
파일 락은 OS 가 프로세스 종료 시 회수하므로, `kill -9` 로 죽어도 다음 기동이 막히지 않습니다.

### I. 마크다운 미리보기는 직접 렌더링합니다
화면에 들어오는 텍스트는 사내 대화 원문과 현업이 편집한 규칙 파일 — 둘 다 사람이 쓴 임의의
문자열입니다. 그대로 HTML 로 넣으면 스크립트가 실행될 수 있습니다. 그래서 순서를 고정합니다:
**먼저 전부 이스케이프하고, 그다음 아는 문법만 태그로 바꿉니다.** 링크는 태그로 만들지 않습니다
(콘솔에서 외부로 나가는 클릭 경로를 만들지 않습니다). 주입 시도 8종으로 검증했습니다.

### J. 환경변수 설정은 비시크릿 허용 목록만 씁니다
`admin`만 환경변수 설정 화면과 API에 접근할 수 있습니다. Slack 토큰과 API 키는 읽기·표시·수정
대상에서 제외하며, 화면에서는 기존 워크스페이스의 라벨·루트 여부·교차 조회 허용 목록과 수집
동작 스위치만 바꿀 수 있습니다. admin 역할의 DB 계정만 저장할 수 있습니다.

저장 결과는 원본 `tybot.env`가 아니라 기본값
`/var/lib/tybot/config/console-managed.env`에 원자적으로 기록합니다. 쓰기 요청은 동일 출처와
`X-TYBot-CSRF: 1` 헤더를 모두 확인하고, 감사 로그에는 값이 아니라 변경된 키 이름만 남깁니다.
설정이 바뀌면 실행 중인 봇이 재시작 요청 파일을 소비해 정상 종료하며 systemd가 다시 기동합니다.

### K. 서비스 로그는 고정 헬퍼로만 읽습니다
개발자와 관리자는 `tybot.service`의 최근 로그를 INFO·WARNING·ERROR로 나눠 볼 수 있습니다.
콘솔 프로세스에 전체 systemd journal 읽기 권한을 주지 않습니다. root 소유 헬퍼가 서비스명,
레벨, 최대 개수를 고정하고 API가 토큰·API 키·DB URL 패턴을 다시 마스킹합니다. 임의 유닛명이나
명령 문자열은 API와 헬퍼 어느 쪽에서도 받지 않습니다.

Python 예외 로그는 첫 ERROR 줄부터 다음 구조화 로그 직전까지 한 항목으로 묶습니다. 따라서
`Traceback`, 파일·줄 번호, 최종 예외 문장을 콘솔에서도 줄바꿈 그대로 확인할 수 있습니다.

## 5. 봇 하네싱(규칙 MD) 편집

TYBot 은 두 층으로 움직입니다.

| 층 | 내용 | 고치는 사람 |
|---|---|---|
| 파이썬 코드 | 수집·검색·권한 판정 등 통제 로직 | 개발 담당 (배포 승인 경로) |
| **MD 파일** | 답변 규칙·업무 흐름·용어 사전 | **현업 (콘솔에서 직접)** |

현업이 손대는 쪽은 대부분 MD 입니다. 그래서 콘솔에서 편집하고, 저장 버튼은 반영이 아니라
**승인 요청 제출**입니다. 요청에는 변경 이유를 필수로 적게 합니다 — 승인자가 판단할 근거입니다.

승인자 화면에는 **추가되는 줄만** 원문 그대로(코드블록) 보여 줍니다. 마크다운으로 렌더하면
`5.` 로 시작하는 줄이 `1.` 로 번호가 다시 매겨져, 몇 번째 규칙이 추가되는지 오해할 수 있습니다.

같은 파일에 이미 대기 중인 편집이 있으면 경고를 띄웁니다(동시 편집 충돌 방지).

## 6. 워크스페이스 등록 — `.env` 편집을 대체합니다

현재 구현된 `환경변수 설정` 화면은 기존 워크스페이스의 비시크릿 관계 설정만 관리한다.
워크스페이스 추가·삭제와 Slack 토큰 등록은 이 화면에서 할 수 없으며, 아래 DB 레지스트리 전환은
별도 후속 작업으로 남아 있다.

지금은 워크스페이스를 늘릴 때 `tybot.env` 를 편집하고 프로세스를 다시 띄웁니다.
`load_workspaces()` 는 설정 오류를 만나면 **기동을 막습니다**. env 단일 파일에서는 옳은
정책이었지만, 여러 사람이 콘솔로 워크스페이스를 추가하는 순간 **토큰 한 줄 오타가 전
워크스페이스 봇을 못 뜨게 만듭니다.**

그래서 DB 레지스트리로 옮기면서 실패 격리도 함께 바꿉니다.

| | env 파일 (현재) | DB 레지스트리 (콘솔) |
|---|---|---|
| 워크스페이스 추가 | 서버 접속 → 파일 편집 → 재기동 | 콘솔에서 키·라벨·토큰 등록 |
| 설정 오류 | **전체 기동 차단** | **그 워크스페이스만 `error` 로 멈춤** |
| 시크릿 | 평문 파일 | 암호화 저장 · 마스킹 표시 |

키(별칭)는 아카이브 디렉터리 이름과 문서 프론트매터에 함께 쓰이므로 **수집을 시작한 뒤에는 바꿀
수 없습니다.** 콘솔에서 형식(`^[a-z][a-z0-9-]{1,23}$`)과 중복을 미리 막습니다.
